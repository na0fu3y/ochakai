[売上が落ちるときの因果](/insights/why-revenue-falls.md)をたどると、どの
枝もどこかでデータが切れて止まる。止まった場所で推測を続けると、答えの
形をした作り話になる。行き止まりはここに書き、答える代わりに「何があれば
答えられたか」を返す。

| 答えられない問い | 何が無いか | あれば答えられるデータ |
|---|---|---|
| 需要が落ちたのは、広告を絞ったからか | 広告費・キャンペーンの記録 | チャネル別・日別の出稿額と配信期間 |
| 買わずに帰った客はどれだけいたか(コンバージョン率) | ログインして買わなかった訪問。[events](/tables/events.md) にはログインした訪問が購入の分しか無い | 購入に至らなかった訪問も含む行動ログ |
| 完了しなかった明細は、いつ・なぜ止まったか | 状態の履歴。`status` は今の値だけで、しかも時間が経っても進まない | 状態が変わるたびに 1 行残る履歴テーブル |
| キャンセル・返品の理由は何か | 理由の列 | 理由コード付きのキャンセル・返品の記録 |
| 安い商品に寄ったのは、値引きのせいか、露出のせいか | 値引き・クーポン・商品ページの露出。今のデータでは実売価格が常に定価と一致する | 販促の記録と、商品ごとの表示回数 |
| 売れなかったのは在庫が無かったからか | 在庫切れの記録。明細の `inventory_item_id` は売れた在庫を指していない([inventory_item_id は売れた在庫を指さない](/insights/inventory-item-id.md)) | 日別・商品別の在庫数 |
| 粗利は、送料や返品の処理費を引くといくらか | 物流費・決済手数料・返品処理費 | 注文ごとの費用明細 |
| 先月見た数字は、何だったか | スナップショット。データは履歴ごと毎日作り直される([thelook_ecommerce](/datasets/thelook-ecommerce.md)) | 締めのたびに保存した結果と receipt |

## 使い方

- 診断の結果に「ここから先はデータが無い」を含めるのは、失敗ではなく
  結果である。どの行で止まったかを書いて返す。
- 同じ行で何度も止まるなら、それはデータを足す提案の根拠になる。
  `report_outcome` の記録がその回数を数えている。
- このデータは合成データなので、表の右の列は「このデータセットに
  あったら」という話である。自分の店のウェアハウスに同じ表を当てると、
  足りないものの候補表として使える。
