# 0153: バンドルは、静的ファイルサーバーと同じ顔で配る

Date: 2026-09-27
領域: [住所・パス・move](../spec/addressing.md)

## 背景

OKF は「静的ファイルサーバーでも配れる」ことを前提にしている。`.md` を
GET すれば文書が返り、`index.md` やディレクトリのリンクを辿れば一覧が
返る。ochakai の `/api/v1/bundle` はそうなっていなかった — concept の
住所は `Accept` を付けない GET に JSON の View を返し、ディレクトリの
住所(`metrics/`)と根は 501 か 404 を返した。SPEC §8 の例は
`[Subdirectory](subdir/)` と書く。汎用の OKF の読み手からは、ochakai は
OKF を配っていなかった。

0064 が View を既定に残したのは、凍結の時点で既存のクライアントを
黙って壊さないためだった。いま ochakai が同梱するクライアント(CLI・
Web UI)はすべて JSON を名指しており、名指していなかったのは例の
Python ジョブ一つだけである。

## 決定

- concept の住所への GET は、`Accept: application/json` を名指さない限り
  **文書**を返す(export と同じ形、ETag 付き)。View は名指したときだけ。
- ディレクトリの住所 — `/` で終わるパスと空のパス — は、その
  `index.md` と同じものを返す。`/api/v1/bundle/` がバンドルの根である。
- 書き込み(PUT)の応答は JSON の View のまま — 何をしたか(`plan`・
  note)を本文で運ぶのがそちらだからである。
- 凍結コアの破壊的変更で、0100 が置いた二つ目の理由(出力が OKF に
  適合しない)に当たる。指紋は動かない(散文だけが変わる)。

## 退けた案

- **View を既定のまま、`index.md` だけ直す。** 読み手は文書を取れず、
  半分しか直らない。
- **根に別の配信口(`/bundle/` など)を足す。** 住所が二つになり、
  0075 の「一つのアドレス空間」を崩す。
- **ディレクトリの住所を `index.md` へリダイレクトする。** 一往復増える
  だけで、相対リンクの解決は同じ結果になる。
- **`Vary: Accept` を足す。** 応答は認証の後ろにあり共有キャッシュに
  載らない。ヘッダを一つ増やす理由がまだ無い。

## 戻す条件

JSON を既定と仮定した外部のクライアントが実際に壊れ、`Accept` を足す
直し方が取れない一件が出たとき。
