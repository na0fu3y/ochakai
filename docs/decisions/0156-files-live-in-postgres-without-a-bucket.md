# 0156: バケットが無ければ、ファイルは PostgreSQL に置く

Date: 2026-09-27
領域: [OKF 互換・バンドル・保存形・往復と provenance](../spec/okf.md)

## 背景

設計記録 0013 はファイルのバイト列を GCS 一本にし、DB との二重化を
やめた。バケットの無いデプロイは markdown の concept だけを持つ。

その代金が見えたのは、OKF のリポジトリが公開するバンドル四つを取り込んだ
ときである。どれも `viz.html` か attester の `.py` を運び、OKF §10 の
Attested Computation は attester をファイルとして持つ。手元の開発機・CI・
Google Cloud の外・`OCHAKAI_GCS_BUCKET` を設定していない小さなデプロイは、
**OKF のバンドルを丸ごと往復できなかった**(C1・C3)。取り込みが止まるのは
直したが、ファイルは残らないままだった。

## 決定

- `OCHAKAI_GCS_BUCKET` が無いデプロイは、ファイルのバイト列を
  PostgreSQL の `blob_bytes` に置く。上限は今と同じ一オブジェクト 5 MiB、
  content-addressed で、消えるのは掃除(sweep)が参照の無いハッシュを
  見つけたときだけ — GCS と同じ約束である。
- バケットを名指したデプロイは今までどおり GCS に書く。**後から名指した
  デプロイは、それまで DB に置いたバイト列を DB から読み続ける**(読みは
  GCS、無ければ DB。書きは GCS。消すのは両方)。
- 環境変数も面も増えない。`stats` の `files.enabled` は、`ochakai serve` が
  動かすデプロイでは常に true になる。

## 退けた案

- **GCS 一本のまま**(取り込みを止めないだけ)。どのデプロイでも往復する、
  を手放す。
- **テキストのファイルだけ DB に置く。** 画像と PDF だけ別の規則になり、
  覚えることが一つ増える。
- **0009 が落とした `blob.bytes` の列を戻す。** `blob` はどの保存先でも
  掃除が読むハッシュの台帳で、バイト列の置き場とは別である。
- **DB から GCS へ移す手順を作る。** 読みが両方を見るので、急ぐ理由が無い。

## 戻す条件

DB に置いたファイルが、データベースの大きさやバックアップの時間で実際に
問題になった一件が出たとき(上限を下げるか、バケットを必須に戻す)。
