# 0155: export の `verified` は、立っている検証だけを書く

Date: 2026-09-27
領域: [OKF 互換・バンドル・保存形・往復と provenance](../spec/okf.md)

## 背景

ochakai は trust の段を、**いまの内容に対して立っている検証**(内容の
最後の意味のある変更以後の行)だけから決める。編集の後の古い確認は、
いまの内容を確かめていないからである(設計記録 0138、0141 §2.4)。

ところが export と文書の表現は、台帳の**全行**を `verified` に書いて
いた(0141 が「export は全行を書く」と決めていた)。OKF SPEC §5.3 は
`verified` に何があるかだけで段を決め、§5.2 は「内容は再確認なしに
変わりうる」と書くので、読み手に「その確認はもう立っていない」と
伝える綴りが無い。結果、確認の後に編集された concept は、ochakai が
unverified と言うのに、**あらゆる OKF の読み手には human-reviewed と
読まれていた**。ochakai の出口が、ochakai 自身の判定より強い主張を
していた。

## 決定

- export・`GET` の文書・`ochakai get` が書く `verified` は、立っている
  検証だけにする。OKF の読み手が §5.3 で出す段と、ochakai の段が一致する。
- 台帳は一行も消えない。誰がいつ何を確認したかの全体は `log.md`(各
  verify のリビジョン)と `?history` が持つ。
- 自分の export が戻ってきたかの判定(`IsObservation`)も同じ行を比べる
  ので、export → レビュー → import の往復は今までどおり `unchanged` に
  なる。

## 退けた案

- **全行を書き、立っていない行に印を付ける**(拡張キー)。SPEC の読み手は
  それを知らず、段は相変わらず高く出る。
- **`generated.at` を最後の確認より前に見せる。** 内容の変更時刻を偽る。
- **全行を書き続け、ずれを文書に書くだけにする。** 出口が規格の読み方で
  嘘をつく状態が残る。

## 戻す条件

OKF が、確認がいまの内容に立っているかを言う綴りを持ったとき。
