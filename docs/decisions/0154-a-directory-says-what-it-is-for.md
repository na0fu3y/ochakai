# 0154: ディレクトリは、自分が何のためにあるかを言える

Date: 2026-09-27
領域: [OKF 互換・バンドル・保存形・往復と provenance](../spec/okf.md)

## 背景

OKF でディレクトリが何のためにあるかを書ける場所は、親の `index.md` の
一行(`* [sales](sales/) - 売上を経路別に`)しか無い(SPEC §8)。ochakai は
`index.md` を中身から生成し、取り込みでは producer の `index.md` を note 付きで
捨てていた。OKF のリポジトリが公開するバンドルは、どれもサブディレクトリの
説明を `index.md` に持つ。それが取り込むたびに消え、`--strict` は公式の
バンドルを一つ残らず落としていた。ochakai のディレクトリには、代わりに
「N concepts」としか書かれない。

## 決定

- 親の `index.md` への PUT は、**各サブディレクトリの行の説明だけ**を
  保つ。一覧は中身から生成し続け、concept の行は読まない(説明は concept が
  持つ)。行に説明が無いか、ochakai の書く「N concepts」だけなら、その
  説明を消す。載っていないサブディレクトリは動かない。
- 生成する `index.md` と一覧の JSON は、説明があればそれを、無ければ件数を
  書く。応答は 200 と今の `index.md`、`Ochakai-Plan`。`dry_run` で何も
  保たない。凍結の指紋は動かない(200 の `text/markdown` は元からある)。
- 書けるのはそのディレクトリに書ける人である。ディレクトリの move は
  説明を運ぶ。
- `ochakai import` は `index.md` を送り、note を出さなくなる。`log.md` は
  今までどおり読まず、note を出す。

## 退けた案

- **producer の `index.md` をそのまま保存して配る。** 往復は完全だが、後から
  concept を足すと一覧が中身と食い違う。
- **捨てたまま、note を減らす。** 面は増えないが、説明は残らない。
- **ディレクトリの説明を書く専用の操作を足す。** 同じことを OKF が既に
  `index.md` で言っている。

## 戻す条件

見出しによるまとめ方など、`index.md` の説明以外の部分を保ちたい producer が
実際に現れたとき。
