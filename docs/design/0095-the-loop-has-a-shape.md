# ochakai 設計ドキュメント 0095: ループには形がある

Status: Accepted(2026-08-10)。[0069](0069-the-loop-and-what-measures-it.md)
を改訂する — §「人間側のフロー」に**時系列**を加える。0069 が決めたことは
一つも動かない。[0092](0092-the-page-is-modules-so-it-can-be-tested.md) §5
が「可能にするだけで決めていない」と書いたループ推移の答えでもある。
Date: 2026-08-10

## 0. この記録が決めたこと

1. **`GET /api/v1/stats` の `review` に `weekly` が増える** — 7 日ずつ 8 本、
   古い順(§2)。
2. **数えるのは検証であって、キューの深さではない。** キューの深さの履歴は
   **どこにも記録されていない**(§1)。
3. **Web UI にはレビューページの一枚だけ**、軸も目盛りも無い SVG。BI ツール
   にはしない(§3)。

## 1. キューの深さの履歴は、無い

issue はキュー深度と検証率の時系列を求めていた。**前者は取れない。**

キューの三つ(`drafts` / `failed` / `stale_after`)は、いずれも **いまの状態
から数えている**(`QueueCounts`)。先月そこに何件あったかを記録している
テーブルは無い。revision から再構成することは理屈の上では考えられるが、
出てくるのは**それらしく見えて正しくない数**であり、
[0089](0089-a-half-embedded-concept-says-so.md) §4 と同じ理由でそれは足さない。

そして 0069 は、この区別を既に書いていた:

> **キューは何が残っているかを言い、何が通ったかは決して言わない。**

つまり「ループがどう動いているか」の答えは、もともと**フロー**の側である。
検証は台帳(`knowledge_verification`)に一件ずつ時刻付きで残り、剪定されない
ので、**ベースが在るかぎり遡って数えられる**。取れるものが、たまたま正しい
ものだった。

## 2. 形の作り方

- **7 日ずつ 8 本。** 二か月で、二週間の沈黙が周りと比べて見える長さであり、
  一目で読める短さである。定数(`ReviewTrendWeeks`)であって設定ではない —
  「レビューにリズムがあるのはどれくらいの期間か」は製品の答えであり、
  デプロイごとに違えば**同じ形が違う意味を持つ**。
- **暦の週ではなく今日から遡る 7 日。** 暦の週にすると最新のバケツが必ず
  途中になり、そこの落ち込みは**キュレーターではなく暦**が作ったものになる。
- **`days` には従わない。** 呼び出し側の窓は他の数のためのもので、形の長さが
  それで変わると、二回の測定が比較できない。
- **誰も何も検証していないベースには `weekly` を出さない。** 8 本のゼロは
  「レビューが止まった」と読める。「まだ始まっていない」は別のことである。
- **一件も無い週も 0 として並ぶ。** 台帳を group by しただけだとその週は
  行ごと消え、**両隣が隣同士として描かれる**。

## 3. 面への出方

| 面 | 何が出るか |
|---|---|
| REST | `stats.review.weekly`。応答専用スキーマへの追加なので凍結の外([0082](0082-what-the-freeze-holds-still.md)) |
| CLI | `verifications_weekly` 一行、古い順の整数列。完全性の面なので、ワイヤに在る数は出す(0067 §3) |
| Web UI | レビューページに一枚。**軸も目盛りも凡例も無い** |
| MCP | **出さない。** これは運用者とキュレーターの数であって、エージェントが一回のループで要るものではない(0089 §3 と同じ線) |

**Web UI の一枚が答える問いは一つだけである** — レビューは増えているか、
保っているか、止まりかけているか。それ以上を描けば
[0067](0067-four-faces-and-what-they-decline.md) §1 が「BI ツールではない」と
言った当のものになる。バーには `<title>`、SVG には数を読み上げる
`aria-label` が付く([0094](0094-the-page-runs-under-a-policy.md) §4 と同じ
理由で、見えない読者にも同じ数が届く)。

## 4. やらないこと

- **キューの深さの時系列**(§1)。スナップショットを取る表を作れば可能に
  なるが、それは定期実行という可動部を増やすことで、0090 が減衰列を断った
  のと同じ理由で断る。
- **却下(reject)を形に混ぜること。** `review.verifications` はスカラーとして
  検証だけを数えており、形だけが二本になると**同じ節の二つの数が別のものを
  数える**ことになる。
- **期間・粒度のパラメータ**(§2)。
- **MCP に出すこと**(§3)。
