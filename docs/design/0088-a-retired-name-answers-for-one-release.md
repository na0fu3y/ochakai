# ochakai 設計ドキュメント 0088: 名前が変わっても、一リリースは答える

Status: Accepted(2026-08-09)。MCP と CLI の安定性契約を定める。
[docs/compatibility.md](../compatibility.md) の「猶予は無い」を置き換え、
[0082](0082-what-the-freeze-holds-still.md) が REST 側で緩めたぶんの
釣り合いを取る
Date: 2026-08-09

## 1. 何が起きたか

`docs/compatibility.md` はこう書いていた —— **REST は凍結、それ以外
(MCP・CLI・保存形)は minor で壊れうる、猶予期間は無い**。これは正直な
記述であり、隠していたわけではない。

問題は、それを読む人が誰かである。**エージェントの設定ファイルは
ツール名を名指しで持つ。** CI のスクリプトは `ochakai search` と書く。
minor を上げると、その呼び出しは仕事の途中で `unknown tool` になる。
そして**エージェントは CHANGELOG を読まない** —— 唯一の告知が、
壊れる側に届かない場所にある。

C5(Claude Code から使える)と C4(導入に人手が要らない)が同時に払う
代金がこれである。2026 年の MCP は、サーバを差し替えられる市場である。
「minor ごとに設定が壊れる」は、その市場では通らない。

## 2. 決定: 一リリースだけ、古い名前が答える

**あるリリースが MCP のツール名または CLI のコマンド名を改名したとき、
古い綴りはそのリリースのあいだ答え続け、次のリリースで消える。**

- **MCP** —— 古い名前で `tools/call` すると、置き換えた側のツールが
  実行される。答えの先頭に、新しい名前と「次のリリースで止まる」ことを
  書いた一行が付く。
- **CLI** —— 古い名前で起動すると、置き換えた側のコマンドが走る。同じ
  内容が stderr に一行出る。

対象は**名前だけ**である。引数・フラグ・出力の形は含まない。保存形も
含まない(マイグレーションは一方向で、戻る道は無い)。REST は元から
凍っているので、そもそも改名が起きない。

## 3. 要点: 呼べるが、載らない

**この記録の中身はここである。**

MCP のツール説明文は**エージェントのコンテキストから支払われる**
([0067](0067-four-faces-and-what-they-decline.md) §1)。だから MCP の
既定は No であり、ツール数は予算である。古い名前を `AddTool` で
もう一本生やす形の猶予は、**そのコンテキスト代を二重に払わせる** ——
しかも、これから消える名前のために。

だから窓は片側だけ開ける:

- `tools/list` は古い名前を**返さない**。まだ知らないエージェントは
  永久に知らない。`ochakai help` も `docs/cli.md` も補完スクリプトも
  同じで、どれも「いま学ぶべき名前」の一覧だからである。
- `tools/call` は古い名前を**受ける**。すでに設定に書いてしまった側は、
  一リリースぶん壊れずに済む。

実装がミドルウェアなのはこのためである。登録は `tools/list` が読むもの
であり、登録した時点で「載らない」が成り立たなくなる。クライアントが
名前を選んだ後、サーバが名前を引く前 —— 二つの事実が同時に真でいられる
場所は、そこしかない。

## 4. 窓が閉じることは、検査される

猶予期間の失敗の仕方は「破られる」ではなく、**閉じられない**である。
足したエイリアスが全部生き残り、どこにも載らない影の語彙が積み上がり、
誰も「いま何が生きているのか」を答えられなくなる。それは §3 が避けた
コンテキスト代を、別の形で払い直すことでもある。

だから各エントリは**改名したリリース番号**を持ち、テストが
`CHANGELOG.md` の最新リリースと突き合わせる。エントリのリリースが
最新より古くなった瞬間 —— つまり**次のリリースを切った瞬間** —— CI が
赤くなり、消す以外に緑にする方法が無い。落ちる場所は release 準備 PR
であり、そこはレビューを通る PR である(CONTRIBUTING.md, Releases)。

「一リリース」を人が覚えている必要は無い、というのが 0035 の作法である。

## 5. 遡らない

0088 より前に消えた名前は戻さない。`compile_sql` も、`concept` に
変わる前の五本も、消えたままである。**もう誰も呼んでいない綴りを
生き返らせるのは、それをもう一度教えることにしかならない。**
窓は、この記録が入るリリース以降の改名に対して開く。

## 6. 何と引き換えか

これは片側の緩和ではなく、**振り分けの変更**である。

[0082](0082-what-the-freeze-holds-still.md) は、凍結が止めていなかった
もの —— 応答専用スキーマへのプロパティ追加 —— を明文で外に置いた。
REST は少しだけ動けるようになった。その代わりに、動くことを前提に
していた MCP と CLI が、一リリースぶんの猶予を負う。

面の数は増えない。数えているのは `tools/list` と `clientCommands` で
あり、**利用者が実際に払うもの**だからである(0067 §1)。載らない名前は
そこに現れず、そして §4 が「載らない名前が増え続けない」を保証する。

## 7. 採らなかった案

- **古い名前もツールとして登録する。** §3。エージェントのコンテキストで
  払うことになり、MCP の既定を No にした理由をそのまま踏む。
- **窓を二リリース、あるいは 90 日にする。** 数えるものが増える。
  「一つ前のリリースまで」なら、比べる相手は CHANGELOG の最新行だけで
  済み、日付を持たなくてよい。0.x で minor が数週間ごとに出る以上、
  一リリースは時間としても十分に長い。
- **非推奨リストを文書に置く(コードには置かない)。** 文書は落ちない。
  §4 の「閉じられない」がそのまま起きる。
- **改名をやめる。** 名前が悪いまま凍るほうが高い。[0054] が五本を
  `concept` に揃えたのも [0076] が二本を降ろしたのも、面が小さいうちに
  やるべきことだった。窓は改名を安くするためにあり、減らすためではない。
- **クライアントにバージョン交渉をさせる。** MCP の `initialize` は
  プロトコルの版を交渉するものであって、サーバの語彙の版ではない。
  ochakai が独自の交渉を持ち込めば、それ自体が面である。

## 8. 面

- **MCP** —— ツールは増えない(`tools/list` は変わらない)。増えるのは、
  古い名前で呼んだときに返る一行だけである。
- **CLI** —— コマンドは増えない。usage にも `docs/cli.md` にも補完にも
  出ない。
- **REST / Web UI** —— 何も無い。REST は凍っており、Web UI が名指しで
  持っている名前は無い。
- **文書** —— `docs/compatibility.md` の冒頭が変わる。あの一段落は
  「これに対して意思決定してくれ」と書いてあるページの要約なので、
  そこが古いのは他のどこが古いより高くつく。
