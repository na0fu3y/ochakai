# ochakai 設計ドキュメント 0094: ページはポリシーの下で動く

Status: Accepted(2026-08-10)。[0092](0092-the-page-is-modules-so-it-can-be-tested.md)
§5 が「可能にするだけで決めていない」と書いた CSP と a11y の基礎を決める。
0092 と [0072](0072-the-web-ui-serves-and-edits-documents.md) は現行のまま。
Date: 2026-08-10

## 0. この記録が決めたこと

1. **Web UI は Content-Security-Policy の下で配信される。** インライン
   スクリプトが無くなったので `script-src 'self'` が書けるようになった
   (§1)。
2. **ochakai の Web UI は他人のフレームに入らない**(`frame-ancestors
   'none'`)。これは利用者が観測できる**拒否**である(§2)。
3. **`style-src` は `'unsafe-inline'` を残す。** 支払いであって、値引き
   ではない(§3)。
4. **人が読む面の最低限は、見えない読者にも届く**(§4)。

## 1. 書けるようになったから書く

0092 が 2,438 行の一枚を ES モジュールに割ったとき、**インライン
`<script>` が一つも無くなった**。CSP の価値の大半は
`script-src 'self'` — インジェクションが DOM に届いてもコードにならない
こと — であり、それはインラインスクリプトが一行でもあると書けない。

このページは **concept の本文を描く**。本文は他人が書いたテキストであり、
面のうちここだけがそれを HTML にする。エスケープは一箇所を通っていて
テストもあるが、**壁は二枚あるほうがよい**。CSP はその二枚目である。

計測して確かめた: ポリシーを厳しくして走らせると違反は**インラインの
`style` だけ**で、スクリプトの違反は一件も出ない。ブラウザ自身が
「script については既に満たしている」と言っている。

## 2. フレームに入らないのは、拒否である

`frame-ancestors 'none'` は、**ochakai の Web UI を自分のポータルや wiki の
iframe に埋める運用ができなくなる**ということである。これは設定ではなく
決定なので、ここに書く。

理由は面の役割である。Web UI は**キュレーションの面**であり
(0067 §1)、人の裁定 — verify と reject — が起きる唯一の場所である
(0069)。裁定の画面を他所のページが囲めるなら、囲んだ側は**どのボタンが
どこにあるかを知っていて、その上に何でも重ねられる**。押した人は自分が
何に署名したかを知らないまま押せてしまう。ochakai が持っている最も強い
主張は「人間が確認した」であり、それを他人のレイアウトの中で起こさせない。

埋め込みたい人には REST がある(0067 §2 — REST が契約で、他の三面は
その client)。UI を囲むのではなく、自分の UI を書くのが答えである。

`img-src` に `https:` を許すのも同じ性質の判断である。本文が外部の画像を
指すことはあり、**ヘッダを足したついでにそれを黙って消すのは、安全に
見えるように文書を壊すこと**である。`data:` と `http:` は許さない。

## 3. `style-src 'unsafe-inline'` は支払いである

ページには literal な `style` 属性が約 40 ある。全部をクラスに移せば
`style-src 'self'` にできるが、**三十個ほどのユーティリティクラスと引き
換え**になる。

払う価値があるかで決めた。CSP が居るのはスクリプトのためであり、
style 属性に**攻撃者由来の値は一つも入らない** — 唯一の動的なものは表の
`text-align` で、区切り行から導かれる四つの定数のどれかである。
だから厳しい半分を先に取り、緩い半分は名前を付けて残す。**残っている
ことが読めるので、後から締めるのは掃除であって設計ではない。**

`Referrer-Policy` は**足さない**。数える面のヘッダが 14 本目になる
([surface.md](../surface.md))のに、買えるのは「クロスサイトで origin
だけを送る」という今どきのブラウザ既定の少し先だけで、しかもこの
ページ自身のパスは `/` である(ルートは fragment に居り、fragment は
そもそも送られない)。

## 4. 見えない読者に届く最低限

四つだけ決める。増やすのではなく、**無いと使えないものを埋める**。

| | 何が起きるか |
|---|---|
| `#toast` が live region | 保存・拒否・失敗は、見える人には一瞬光る。見えない人には何も無かった |
| 移動後にフォーカスが `#view` へ | 主領域が入れ替わるのに、次の Tab は消えた場所の続きを辿っていた |
| 現在のタブに `aria-current` | 「ここに居る」を言っていたのは色だけだった |
| エラーバナーが `role="alert"` | 読み上げの順番待ちに入る種類の情報ではない |

**アイコンだけのボタンには名前を付ける。** `title` は読み上げられるとは
限らない。

最初の描画ではフォーカスを動かさない — 文書を読み込んだ直後のブラウザと
争うことになる。

## 5. やらないこと

- **`style-src` を締めること**(§3)。掃除として、いつでも。
- **`Referrer-Policy` を足すこと**(§3)。
- **a11y の網羅**。ここにあるのは「無いと使えない」四つで、監査ではない。
- **CSP を設定にすること。** 何を許すかはこのページの性質であって、
  デプロイの好みではない。フレームに入れたい人には REST がある(§2)。
