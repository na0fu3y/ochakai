# ochakai 設計ドキュメント 0123: 数は、何を数えたかを言う

Status: Accepted(2026-08-23)。[0109](0109-a-directory-has-readers-and-writers.md) §3 の
「バンドル全体を取る操作は管理者のものになる」から **`stats` を外す** —

## 1. 0109 §3 が断った理由と、そこに無かったもの

0109 §3 はこう書いた。

> **stats を部分集合で返さない。** ループを測る数
> ([0069](0069-the-loop-and-what-measures-it.md))に二つ目の意味を与える
> ことになる。

**理由は正しく、対象が広すぎた。** 部分集合の数はその日も出せたからである
— `stats` は 0041 以来 `prefix` を取り、管理者が
`ochakai stats --prefix teams/growth` と打てば、まさにその「部分集合」が
返ってくる。**二つ目の意味を作っていたのは部分集合が存在することではなく、
答えがどちらを運んでいるかを言わないこと**だった。

同じ数の並びが、あるときは全体で、あるときは一部で、**見分けが付かない**。
それが二つ目の意味である。

## 2. 決定: 答えが自分の範囲を宣言する

応答は `scope` を持つ。**数えた prefix の一覧で、バンドル全体を数えた
ときは載らない。**

- **範囲を持つ呼び出し元は、自分の数を読める。** 付与の読み取りスコープ
  ([0109](0109-a-directory-has-readers-and-writers.md))に絞られ、`prefix`
  を渡していればその交差になる。絞りは検索・一覧が既に通っている
  `narrow` と同じ一箇所である。
- **管理者が `prefix` で訊いたときも同じ宣言が付く。** この欄は**数に
  ついて**であって呼び出し元についてではない。規則が一つなら、読む人は
  「自分は管理者だからこれは全体だ」と推論しなくてよい。
- **空の一覧は「あなたには何も見えない」である。** 付与を一つも持たない、
  あるいは見えない subtree を訊いた場合で、**すべての数がゼロになるのは
  何も起きなかったからではない**と言うためにこの形が要る。空の prefix
  一覧はフィルタでは「バンドル全体」を意味するので、それでは言えない。

これは [0114](0114-a-degraded-ranking-says-so.md) が退化したランキングに
置いた形の再適用である — **狭くなったことを、狭くなった側が言う。**

## 3. 絞れない二つは、絞れないと言う

- **miss は差し止める。** 何も返さなかった検索には concept の id が無い
  ([0069](0069-the-loop-and-what-measures-it.md) §5.1)ので、絞る手がかりが
  存在しない。絞らずに見せれば、**あるチームに他の全チームが何を探したかを
  教える**ことになる。だから範囲を持つ呼び出し元には `withheld` を立て、
  数と一覧を空にする。
  **ゼロにしないのが要点である**: `recording: false` が既に「ゼロではなく
  無意味」を綴っており、これはその二つ目の理由である。二つを別の語にする
  のは、**直し方が違う**からで — 片方は設定を変える、もう片方は管理者に
  訊く。
- **dropped は全体のままである。** 失われたイベントは、失われた時点で
  それが何についてだったかが分からない。範囲を持つ呼び出し元にも見せる —
  ナレッジの中身ではなく、**上の数がどれだけ信用できるか**の脚注だからで
  ある。

## 4. 管理者に残るもの

`stats` だけが出ていく。**export・`move`・`reembed`・アクセスポリシー自身は
0109 §3 のままである** — それぞれの理由がまだ効いている:

- **export** は「入ったものは出てくる」というバンドル唯一の不変条件
  ([0075](0075-the-bundle-is-the-address-space.md) §1、C1)に乗っており、
  欠けたアーカイブもバックアップと呼ばれる。**宣言では直らない**: 復元の
  runbook は宣言を読まない。
- **`move`** は内向き参照を書き換えるので、絞れば飛ばしたリンクが切れる。
- **`reembed`** はベース全体に対して Vertex AI の呼び出しを支払う。

**`stats` が違うのは、答えが読まれるためだけに在るからである。** export と
move は他の何かを変える。読まれるだけのものは、自分が何であるかを言えば
足りる。

## 5. ついでに直したもの — 記録がコードを追い越していた

`domain.Stats.Queues` の注釈は「prefix で絞られない」と書いていたが、
store は既に絞っていた(`statsReview` が `QueueCounts` に prefixes を
渡している)。散文だけが古く、**その散文を根拠に「絞れないもの」を数え直す
読者がいれば間違える**。0109 §3 を読み直すこの記録が、その一行に当たった。

## 6. 面

| 面 | 現れ方 |
|---|---|
| REST | 応答に `scope` と `misses.withheld` が増える。**応答専用スキーマへの追加**で、凍結の外である([0082](0082-what-the-freeze-holds-still.md) §2)。操作もパラメータもヘッダも増えない |
| CLI | `scope` 行(全体のときは出ない)と `misses withheld`。**フラグは増えない** — `--prefix` は既にある |
| MCP | **載せない。** `stats` は元から MCP に無い |
| Web UI | 範囲を宣言された答えは、その範囲を名指す。miss のタイルは `–` になり、ラベルが「非公開」と言う |

`REST` / `PARAM` / `HEADER` / `MCP` / `CLI` / `FLAG` / `ENV` の数はどれも
動かない。

## 7. 採らなかった案

- **範囲を持つ呼び出し元に miss を絞って見せること。** 絞る手がかりが
  無い(§3)。「その prefix を含むクエリだけ」は別のものを数えることに
  なり、名前が同じで意味が違う数を増やす。
- **範囲を持つ呼び出し元に `stats` を 403 のままにすること。** 0119 §5 が
  名指した宿題であり、ディレクトリの形で組織を受け入れるなら、その組織が
  自分のループを測れないのは C7 を満たしていない。
- **`scope` を常に載せること**(全体のときは全 prefix、あるいは `["" ]`)。
  全体を数えた答えは今日の答えであり、**そこに欄が増えると、既存の読み手が
  「何か狭まったのか」と読む**。無いことが「全体」の綴りである。
- **`withheld` を `recording: false` に畳むこと。** §3 のとおり直し方が
  違い、畳めば運用者が `OCHAKAI_RECORD_MISSES` を疑いに行く。
- **export も同時に割ること。** §4 のとおり理由が別で、割るなら「欠けた
  export をバックアップと呼ばせない」ための別の答えが要る。**一つずつ
  割るのが 0109 §3 の言う「後からできる」の形である。**
