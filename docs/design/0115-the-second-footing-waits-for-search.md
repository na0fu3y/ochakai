# ochakai 設計ドキュメント 0115: 二つ目の足場は、検索を待つ

Status: Accepted(2026-08-21)。[0003](0003-gcp-only.md) の「それ以外の実行
環境をサポートしない」を改訂する — 決定は一行も緩めず、**それを撤回して
よい条件**を一つ与える。[0086](0086-a-second-way-to-say-who-is-calling.md)
が認証について開いた道の、その先をどう扱うかである。secret-zero も、
埋め込みが Vertex AI であることも、ここでは動かさない
Date: 2026-08-21

## 0. この記録が決めたこと

0086 は 0003 を認証について改訂し、そこで止まった。止まったことは自分で
書いている — 「secret-zero も、認可を持たないことも、**埋め込みが Vertex AI
であることも動かさない**」。**止まった先に何があるかは、どの記録も書いて
いない。**

書いていないと何が起きるかは分かっている。0003 は「サポートしない」と
だけ言っており、読む人はそれが**永久の決定なのか、まだ来ていない日を
待っているのか区別できない**。区別できない決定は、提案を測る道具として
働かない — Google Cloud の外に触れる提案はすべてプラットフォーム違反に
見え、0086 自身がそう読まれれば提案の段階で落ちていた。

だからこの記録が足すのは決定ではなく**条件**である。0003 の「サポート
しない」は今日も真で、条件に当たらないうちは外で動かす提案は no のまま
である。前例は [0065](0065-identity-and-provenance.md) §1 で、自分で置いた
改訂条件を [0109](0109-a-directory-has-readers-and-writers.md) が満たした。
**条件を先に書いておくと、後から誰かがそれを満たせる。**

## 1. 0086 の後、Google Cloud に縛られているもの

三つある。

1. **データベースの資格情報。** Cloud SQL IAM の外では、パスワードなり
   別のクラウドの IAM なりが運用者の仕事に戻る。
2. **埋め込み。** Vertex AI か、無いか
   ([0080](0080-search-and-how-a-deployment-embeds.md) §1)。無ければ
   検索は字句だけになる。
3. **ファイルのバイト列。** `OCHAKAI_GCS_BUCKET` が無ければ非 markdown の
   書き込みは 501 で、起動時のログもそう言う
   ([0075](0075-the-bundle-is-the-address-space.md))。

**三つは同じ重さではない。** それを決めるのは好みではなく、
[docs/surface.md](../surface.md) の八つの条件である。

## 2. 返せるものと、返せないもの

(1) と (3) は**運用者に返せる。** 何が失われるかを起動時と文書で言えば、
そこから先は運用者の選択になる。ochakai は自分が何であるかを言う製品で
あり([0066](0066-four-postures-one-word.md)、[0087](0087-a-sandbox-says-it-is-one.md))、
資格情報を自分で持つことも、添付の無いベースで足りることも、選べる形を
している。どちらも八つの条件のどれかを偽にはしない。

(2) は返せない。**C8 — 日本語話者にとって類似サービスと比較したときの
最適な選択肢の一つであること — が乗っているのが検索だからである。**
0080 §1 が埋め込みを既定に上げた理由がそれで、「この製品でいちばん効く
機能が、いちばん奥に置いてあった」。外ではその機能が奥にあるのではなく、
**無い**。

しかも壊れて見えない。[0114](0114-a-degraded-ranking-says-so.md) §2 が
その形を既に言語化している — **埋め込みを持たないデプロイは「退化」して
いない**。字句が答えの全部であり、毎回そうなのだから、そう名乗るフラグ
すら立たない。壊れてはおらず、**別の製品である。**

[positioning](../positioning.md) はこれを負けとして既に書いている:
「Google Cloud の外で動かす — どれか一つでも真なら、FDE 型を買う理由は
まだそこにある」。

## 3. 条件は、埋め込みが外でも既定になること

**支える価値の無い足場を「支える」と宣言するのは、嘘を一つ増やすことで
ある。** C4(No FDE)は「デプロイは自分でできて」だが、自分でできた先に
あるのが C8 を満たさない ochakai なら、支えたことにならない。だから
0003 を撤回してよい条件は一つで、それは検索である。

条件が雰囲気にならないよう、測れる形にする。**三つとも真であること。**

- **a. 設定を足さずに有効になる。** 0080 §1.1 が Google Cloud 上でやった
  こと — メタデータサーバに自分がどこで動いているかを訊き、その答えで
  有効にする — に相当するものが、外にもあること。`OCHAKAI_EMBEDDINGS`
  一語という綴りは動かさない(0080 §2 が畳んだものを開き直さない)。
- **b. secret を増やさない。** 外部 API キーで呼ぶ埋め込みは条件を満た
  さない。C2 の性質を壊すものは、その性質を外に持ち出す手段にはならない。
- **c. データ所在地を運用者が選べる。** 0080 §1.2 が譲らなかったもので、
  東京に立てたデプロイの本文が誰も選んでいない国へ出ていってはならない。

三つを同時に満たす機構が**いま無い**ことが、この条件が今日は満たされない
という意味である。**この記録は機構を選ばない** — 選ぶのは、候補が現れた
ときの評価である。

## 4. 条件が満たされたら

そのとき残るのは §1 の (1) と (3) で、どちらも §2 のとおり返せる。だから
**そこで初めて 0003 を改訂するかを問える。**

**この記録はその改訂ではない。** 条件が満たされた日に、新しい番号が 0003
を改訂する。順序は逆にできない — 先に足場を足すと、支える価値を測る前に
面が増える。

## 5. 採らなかった案

- **外部 API キーの埋め込みプロバイダ。** 0003 §2 が
  `OCHAKAI_EMBEDDING_PROVIDER` を退役させた理由は分岐が増えることだったが、
  いま断る理由はそれより強い。鍵は secret であり、C2 の性質そのものを壊す。
- **二つ目のストレージエンジンを先に足すこと。** 単一ファイルのデータ
  ベースは資格情報を消すので §1 の (1) には効くが、(2) には何もしない。
  条件が満たされる前に足すと、支える価値の無い足場のために store が二重化
  し、以後すべての移行が二度書きになる。**効く順序が逆である。**
- **「マルチクラウド対応」という言葉。**
  [0081](0081-what-ochakai-is-and-what-it-refuses-to-hold.md) §2 が数えて
  いるのは**動かすのに何が要るか**であって、どこで動くかの主張ではない。
  足場が二つになる日が来ても、依存は PostgreSQL 一つのままである。
- **条件を書かずに黙っていること。** 黙っていても 0003 は守られるが、
  守られていることと、なぜ守られているかを読み手が知っていることは別で
  ある。§0 のとおり、区別できない決定は物差しとして働かない。
