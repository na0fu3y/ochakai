# ochakai 設計ドキュメント 0084: ヒットは、なぜ一致したかを言う

Status: Accepted(2026-08-09)。[0067 §4](0067-four-faces-and-what-they-decline.md)
の「ヒットは概念そのものを運ばない」を保ったまま、一致した箇所だけを
運ぶ。[0082](0082-what-the-freeze-holds-still.md) が凍結の外と定めた
応答専用スキーマへの追加である
Date: 2026-08-09

## 1. 何が起きたか

検索のヒットは**どの concept が一致したか**を言い、**なぜ一致したか**を
言わなかった。行にあるのは title と description で、どちらも
「この concept は全体として何か」であって、「この問いに何が答えたか」
ではない。

代金は往復である。10 件のヒットからどれを開くか決める呼び出し元は、
本文を取りに行くしかない。エージェントにとってそれは固定のコンテキスト
予算からの支払いであり、**欲しくなかった 9 件ぶんの文書を読んで、
欲しかった 1 件を見つける**ことになる。0067 §4 が「結果が文書を 10 件
運ぶのは、読まない 9 件に呼び出し元のコンテキストを使わせる」と書いた
のと同じ計算が、一段ずれた場所でそのまま起きていた。

## 2. 決定: 本文で一致したときだけ、その一節を運ぶ

ヒットに `snippet` を足す。クエリの語が本文のどこに落ちたかを、読める
幅(140 文字前後)で切り出し、切った端に … を付ける。

**出さない場合が二つあり、どちらも「指させる一節が無い」である。**

- **名前か description に落ちたとき。** 行が既に一致を見せているので、
  同じものを繰り返すのは呼び出し元のバイトを使って何も伝えないことに
  なる。
- **ベクトルで見つかったとき。** 意味で一致した concept に、指させる
  文字列は無い。本文の冒頭を代わりに出すのは、「なぜ一致したか」に
  一致の理由でないもので答えることである。

一覧(`sort=`)にも出ない。問いが無いので、一節の選びようが無い。

## 3. なぜ Go で切るのか(`ts_headline` ではなく)

PostgreSQL には `ts_headline` があり、tsvector と同じ辞書で強調を作る。
採らなかった理由は二つある。

- **本文はもう手元にある。** スコアリングは id と真偽値だけを窓関数に
  通し、上位 N が決まってから実体を引く([0020](0020-attachment-search.md) の
  構造)。その最後の select が既に本文を運んでいるので、切るのに問い合わせ
  も往復も増えない。`ts_headline` は同じ行に対する追加の関数呼び出しで、
  しかも**候補全体ではなく上位 N に対してしか意味が無い**ので、置き場所は
  結局ここになる。
- **一致の単位がこちらの規則だからである。** 日本語の探索は移行 0036 の
  二文字窓で、`ts_headline` に渡すのは同じ窓を組み直した tsquery になる。
  切り出しの規則(どこから始めるか、何文字か、どちらの端を … にするか)は
  結局こちらが決めることになり、二つの実装が同じ規則を持つことになる。

## 4. 面

- **REST** — `SearchHit.snippet`。契約が宣言し、凍結の外の追加として
  golden を再生成した(0082)。
- **CLI** — `ochakai search` の行末に ` · ` で続ける。最初の四つの
  フィールドはタブ区切りのままなので、切り出すパイプラインは影響を
  受けない。
- **Web UI** — 検索カードに、description の下へ本文の一節として。
  markdown ではなく素のテキストで描く: 文の途中で切ってあるので、
  markdown として解釈すると壊れた強調が出る。
- **MCP** — 応答には出る(同じ `SearchHit` である)。**ツールの説明文には
  足さない** — 説明文はエージェントのコンテキストから支払われ
  ([0067 §1](0067-four-faces-and-what-they-decline.md))、応答に現れる
  キーはそれ自身が説明である。

## 5. 採らなかった案

- **description の代わりに出す。** 二つは別のことを言う。description は
  concept 全体、snippet はこの問いへの答えであり、片方をもう片方で
  置き換えると、問いに依らない情報が失われる。
- **常に出す(ベクトルのヒットにも冒頭を)。** §2 のとおり、理由でない
  ものを理由の欄に入れることになる。欠けていることが「テキストでは
  一致していない」という情報である。
- **もっと長く(段落まるごと)。** 50 件が段落を運ぶと、節約したはずの
  往復より高くつく。140 文字は端末二行ぶんで、「開くかどうか」を決めるに
  足りる長さである。
- **一致箇所を強調して返す(`<mark>` や `**`)。** ワイヤに表示の指示を
  載せることになり、面ごとに解釈が割れる。位置は … の間にある本文で
  十分に分かる。
