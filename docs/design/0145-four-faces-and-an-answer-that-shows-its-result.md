## 0. この記録が決めたこと

1. **エージェントは REST の一本の操作の後ろにいる。** `POST /api/v1/agent`
   が唯一の入口で、Web UI はそのクライアントである。REST が唯一の契約で
   あること(§1)は動かない — 自分のエージェントも契約の外に面を持たない。
2. **「LLM を使う機能は載せない」は「LLM に裁定させる機能は載せない」に
   なる**(§5.2)。0142 が手段を替えて性質を残したのと同じ線で、面の
   一覧を書き直す。
3. **答えは自分の結果を見せる。** Web UI は、人が自分の身元で走らせた
   クエリの結果を表で見せ、結果の形が許すときはグラフも描く。**どの
   グラフにするかはページが結果の形だけから決める** — モデルは軸を
   選ばない。ダッシュボード — 保存し、ピン留めし、定期に走らせ、共有する
   ボード — は持たない(§5.4)。ochakai が競うのはナレッジであって、
   BI ではない。
4. **残りは 0143 のままである。** 0143 は 0067 と、その上に積まれた
   四冊(0076・0106・0108・0118)を決定を動かさずに畳んだ記録で、ここは
   その本文を節の番号ごと引き継ぐ。論証の全文は各記録の墓標が指す
   コミットに残る。

## 1. 四つの面の役割

- **REST は唯一の契約。** すべての機能は `/api/v1` に載るか、どこにも
  載らない。他の三面は全部そのクライアントであり、上限・enum・既定値は
  サーバー側に一元化する。
- **MCP はエージェントの目的特化入口。** ツールスキーマはエージェントの
  コンテキストから支払われるので、**ツール数は予算である**。REST の 1:1
  ミラーは目指さず、エージェントのループが要るものだけを載せる。いまは
  `search_concepts` / `list_concepts` / `get_concept` / `get_file` /
  `put_concept` / `report_outcome` の 6 本。
- **CLI は完全性の面。** REST の純クライアントとして操作を覆う。完全性とは
  **能力の完全性**であって、畳まれた面をコマンドとして保存することではない
  ([0068](0068-how-a-face-is-added-and-removed.md) §1)。
- **Web UI はループの人間側。** 検索・ブラウズ・裁定・履歴の閲覧と、
  **デプロイ自身のエージェントに問い、その答えを読むこと**まで。答えには、
  問うた人が走らせたクエリの結果が表と(形が許せば)グラフで付く(§5.4)。
  BI ツールではない — ダッシュボードを持たない。ページは認証を知らず、
  自分では何も判断しない
  ([0130](0130-the-web-ui-and-the-fields-of-a-document.md) §1)。結果から
  どのグラフを描くかも判断ではなく、結果の形から決まる規則である。

## 2. CLI は REST の薄いクライアントである

サーバー側に CLI 専用の面を作らない。**DB の隣でしか動かないコマンドは
`serve` だけ**である。同じ成果物に二つの経路があると、仕様追加のたびに
片方だけ直る。API 経由なら actor は OS のユーザー名からの合成ではなく、
Cloud Run が検証した呼び出し元になる(0065 §2)。

- **同一バイナリ。** `internal/apiclient` は `internal/service` を import
  せず、OpenAPI 契約をミラーした型を自前で持つ。
- **フラットな動詞コマンド**(`ochakai search`)。接頭辞が名前空間を担う。
- **接続先の解決順は `--url` > `OCHAKAI_URL` > `ochakai use` の設定。**
  config が持つのは URL だけで、トークンは存在しない。
- **`ochakai login` は作らない。** 資格情報の状態は `ochakai whoami` が
  「どこに・誰として・届くか」で見せる。
- **終了コードは 0 / 1**(`stats --exit-code` のキュー判定だけが 2 を足す)。
- **引数なしの `ochakai` はヘルプ。** `serve` へは落ちない。

## 3. MCP の転送 — `mcp-stdio` は面ではなく経路で、`/mcp` は状態を持たない

`ochakai mcp-stdio` は stdin/stdout と remote の `/mcp` を JSON-RPC
メッセージ単位で素通しするブリッジで、サーバーには何も足さない。**ツール
定義を写さず、JSON-RPC を解釈しない** — 解釈しないことが、後から仕様に
足された何かが橋を素通りできる理由である。**stdout はプロトコル専用**で、
診断はすべて stderr に出す(テストで留める)。REST や Web UI に対応物は
作らない。

`/mcp` は **stateless の streamable HTTP** で、プロトコル 2026-07-28 で
答える。`Mcp-Session-Id` は発行も参照もせず、GET と DELETE は 405
(`Allow: POST`)。一回の POST が protocol version・クライアントの名前・
capabilities を自分で運ぶ。ochakai の状態はナレッジベースであって接続では
ないので、失うモードは一度も使っていないモードで、インスタンスは何台でも
並べられる。

- **名乗り(producer)は毎回の呼び出しから読む**(0065 §4 の改訂)。契約は
  ヘッダ `Ochakai-Producer` のままで、`clientInfo` はその好意の側の
  フォールバックである。2026-07-28 より前のクライアントでは `initialize`
  にしか名乗りが無く、stateless ではそれが後続の呼び出しに届かない —
  自称が落ちるだけで、identity は一字も変わらないので受け入れる。
- **構築時に決まる三つの一覧**(`tools/list`・`resources/list`・
  `resources/templates/list`)は **5 分持つ**と答える。`resources/read` は
  0 のまま — 線は一覧かどうかではなく、知識かどうかである。`cacheScope`
  は SDK 既定の `public` で、認可は呼び出しごとに service で効く
  ([0109](0109-a-directory-has-readers-and-writers.md))。

## 4. 同じ機能が、面によって別の意味を持ってはならない

- **エージェントの読みは search → get である。** 検索 + 全文 + リンク
  一 hop + バイト予算を一回で返す pack(`/context`・`get_context`・
  `ochakai context`)は**どの面にも無い**。何を読むかを決めるのは読む側で、
  サーバーではない — 自分のエージェントも同じ search → get で読み、近道を
  持たない。
- **検索の hits は順位である。** ポインタとして、fetch するかを判断できる
  だけの情報を持つ。
- **単読は `linked_from` を運ぶ。** REST の単読・`get_concept`・
  `ochakai get` に、その concept を本文から指している concept の**行**
  (id / type / title / description / status / trust)が付く。住所順、
  上限 20 で静かに切れ、却下済みの linker は出ない。**行はポインタで
  あって配達ではない** — 本文を持たず、返しても fetched に数えない。
  完全でページングできる逆引きは検索の `links_to` が持ち続ける。
- **書き戻しの hint は `get_concept` の応答に乗る**(0096 §3 の改訂)。
  知識が実際に配達される場所で、常駐ではなく応答ごとの一文の定数である。
- **エージェントの答えは、どの面から問うても同じ操作の答えである。**
  Web UI の棚卸しも、REST を直接叩く利用者の問いも `POST /api/v1/agent`
  の一本で、画面ごとの別の振る舞いを持たない。

## 5. 意図して載せないもの

### 5.1 MCP に載せないもの

ツール数は予算なので、既定は no である。**能力を MCP から降ろしてよいのは、
それが他の面に残るときだけ**である — 唯一の入口だからこそ、そこに何を
載せるかは選ばれていなければならない。

- **ブラウズ**・**履歴**・**被リンクのツール**(単読の `linked_from` が
  運ぶ、§4)。
- **ファイルの書き込み**(base64 をツール引数に載せない)、**バルク**
  (export / import)、**purge**、**reembed**、**`stats`**、**`fm.` の
  フィルタ**。
- **削除。** 削除は裁定である。誤りなら `report_outcome` failed、より
  良いものがあれば別 id の draft。消すのは人が REST・CLI・Web UI で行う。
- **利用回数の合計。** エージェントの判断に要る信頼シグナルは hit と
  `get_concept` に載っている。数そのものは `GET /api/v1/usage/{id}` と
  `ochakai usage`。
- **裁定**(verify / reject)と、**人が判断を下した concept の上書き・
  復活**(§6)。
- **デプロイ自身のエージェント。** MCP の向こうはすでにエージェントで、
  エージェントにエージェントを渡すのはツールの予算の浪費である
  (0142 §7)。

### 5.2 REST に載せないもの

- **サーバーでの SQL 実行。** ochakai はウェアハウスの資格情報を持たない。
  自分のエージェントが SQL を走らせる日も、走らせるのは問うた本人の身元で
  ある(0142 §4)。
- **LLM に裁定させる機能。** 自動検証、LLM による順位付け、知識の代わりに
  配る要約。**配る中身を変えるのは人の裁定だけ**で、それが人の検証への
  信頼の根拠である(0142 §3)。エージェントの一本は答えと提案を返すだけで、
  どの concept の tier も動かさない。
- **認証・ユーザー管理。** 認証は Cloud Run IAM の仕事で、ユーザー DB を
  持った瞬間 secret-zero が壊れる(0065)。
- **Web UI の配信**(ページを持たないサーバー)。
- **バルクの OKF import。** import は CLI が既存の書き込みを一件ずつ叩いて
  合成する。README の「CLI は REST の薄いクライアント」の唯一の例外で
  あることは認める。踏み切るトリガは、バイナリを持ち込めない環境からの
  リストア要求が実際に来たときである。

### 5.3 CLI に載せないもの

- **DB 直結コマンド**(`serve` を除く)。
- **レビューキューのヒューリスティック再実装**(素材の提供まで)。
- **TUI・対話モード**、**ローカルキャッシュ・オフラインモード**。
- **エージェントへの問い(いまは)。** CLI を使う人はシェルを持ち、たいてい
  自分のエージェントを持っている — ochakai のエージェントが買うものは
  Web UI だけで裁定する人の前にある。**能力は REST に残る**ので完全性は
  欠けない。見直す条件: シェルはあるが自分のエージェントを持たない人が、
  問えずに実際に詰まった一件が出たとき。

### 5.4 Web UI に載せないもの、載せるもの

**答えの結果は載せる。** エージェントが提案し、人が自分の身元で走らせた
クエリの結果を、ページは答えの隣に描く。

- **表は常に描く。** 返った行(上限 50 行)をそのまま。数は右に揃える。
- **グラフは、結果の形が一つの読み方しか許さないときだけ描く。** 最初の
  列が行のラベルで、残りの列がすべて数(1〜4 本)のとき。ラベルが日付・
  時刻なら時間軸の折れ線、文字列なら返った順の横棒(20 本まで)。それ
  以外の形 — ラベルが二列ある、数が五列以上ある、ラベルが数である — には
  描かない。描けば、どれかの読み方をページが勝手に選ぶことになる。
- **線は、結果に無い値を描かない。** NULL で切れ、行の無い期間 —
  行の間隔がふだんの間隔(隣り合う行の間隔の中央値)の 1.5 倍を超える
  ところ — をまたいでつながない。前後とつながらない一点は点として描く。
  つないだ線は、そこに値があったと読まれる。
- **軸は一本。** 桁が 20 倍以上違う系列は、同じ軸に載せず一本ずつの小さな
  グラフにする。二本目の y 軸は、どちらかの系列に嘘をつかせる。
- **色は列の位置に付く**(4 色、固定の順)。どの小さなグラフに載っても
  同じ系列は同じ色で、凡例と表が色だけに頼らない読み方を残す。
- **描くのはページ自身のコードで、外のライブラリを読まない。** ページの
  ポリシー([0094](0094-the-page-runs-under-a-policy.md))の `script-src`
  は `'self'` のままである。
- **グラフは会話と一緒に消える。** 保存もリンクも無く、会話の記録
  (0142 §6)にも結果は残らない — 残るのは SQL の文だけで、それは 0142 §6
  のままである。

**同意は会話ごとに一度。** 人は、提案された SQL を以後クリック無しで
走らせることに、会話ごとに一度同意できる。走るのは同じく本人の身元で、
読み取りだけ、同じ課金上限の下である。BigQuery が断ったクエリは、エラー
ごと次のメッセージとしてエージェントに返り、エージェントが直す。人が
何も書かずに続けて走るのは 6 本までで、サインインが切れれば止まる。
変わるのは誰がクリックするかだけで、0142 §4 のどれも動かない。

載せないもの:

- **ダッシュボード。** グラフを保存し、ピン留めし、定期に走らせ、共有する
  ボード。そこから先は BI ツールで、ochakai が競うのはナレッジである。
- **モデルが設計するグラフ。** §8。
- **サーバーでの SQL 実行。** ページが SQL を実行するなら、それは本人の
  身元でブラウザから行う(0142 §4)。
- **結果報告のボタンを concept に置くこと。** outcome は知識に基づいて
  実行した結果の証跡で、実行していない画面の報告は再検証フィードの信号を
  汚す。**エージェントの答えへの判定**としてだけ置く — その答えを読んで
  使った人が、使った concept について言う報告である(0142 §3)。
- **OKF import のアップロード**(§5.2 の帰結)、**ログインフォーム**、
  **purge**、**reembed**、**`fm.` のフィルタ**、**producer の申告**。

## 6. 人が判断を下した concept は、エージェントから動かせない

`put_concept` は、対象が検証済み・deprecated ならば拒否する。create による
**墓標の復活**も同じく拒否する(draft の墓標は復活できる — 誰も判断を
下していない)。検証済みから deprecated への遷移も MCP からはできない。
**デプロイ自身のエージェントにも同じ制限を課す**(0142 §3)。

**これは認可ではない。** 制限するのは、前提条件を表明できない面からの
黙示的な置き換えだけである。`If-Match`
([0030](0030-optimistic-locking.md))は REST の ETag に乗っており、
MCP にはその通り道が無い — MCP の書き込みは後勝ちで、draft には許容でき
るが人がキュレーションしたものには許容できない。**非対称性の根拠は復旧
可能性ではなく可視性である**: 検証済みの golden query の本文が黙って
置き換わっても、誰かが間違った数字を得るまで誰も気づかない。人の面
(REST / CLI / Web UI)は従来どおり動かせる。

## 7. やらないこと

- **能力を他の面に残さないまま MCP から降ろすこと**(§5.1)。
- **新しいサーバー面**(CLI 専用エンドポイント、トークン)、**公開
  エンドポイント**(`mcp-stdio` は listen するポートを持たない)、
  **ブリッジでのリトライやキャッシュ**。
- **縮小版の pack。** hit に本文の冒頭を足す、get に companions を同梱
  する — pack を別の名前で作り直すことである。見直す条件: シェルも MCP
  の反復も無いホストのエージェントが、一回の HTTP 呼び出しで読むべきもの
  一式を要すると実際に詰まったとき。
- **被リンクのツール、行に文書を載せること、行の順序に順位を持ち込む
  こと**(§4)。
- **エージェントに第二の入口を作ること。** 会話をサーバーに持つ面、
  ストリーミングの別経路、MCP のツール。一本の操作に会話ごと運ぶ
  (§0、0142 §7)。

## 8. 退けた案

- **エージェントがグラフを指定する**(軸・種類・系列を返すツールと、
  応答の新しいフィールド)。結果の形が曖昧なときに意図に沿った絵を描ける
  が、同じ行が問い方しだいで別の絵になり、モデルが軸の名前を取り違えれば
  正しい数から誤った絵ができる — 人が確かめる経路の無い主張が、答えの
  中で一番目を引く場所に載る。ツールも一本増える。見直す条件: 形の規則が
  描かない結果について、グラフが無くて読めなかった一件が実際に出たとき。
- **グラフのライブラリを CDN から読む。** ページのポリシーに第三者の
  スクリプトを足すことになる(0094)。要るのは折れ線と横棒の二つだけで、
  自前の SVG で足りる。
- **サーバーが画像を描く。** 結果はすでにサーバーを通るが(0142 §4)、
  描画をサーバーに置くと、ページのための REST の面が一つ増える。
- **グラフを持たないまま(0143 のまま)にする。** 表だけで答えは読めるが、
  推移や比較を問う人の多くは、表から形を読み取る手間を払っている。
  ROADMAP の第一段(2026-09-25)が目指す、自前のデータエージェントを
  作らなくてよい状態には届かない。
