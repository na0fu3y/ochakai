# ochakai 設計ドキュメント 0127: アーカイブは、自分がどの部分かを言う

Status: Accepted(2026-08-23)。[0109](0109-a-directory-has-readers-and-writers.md) §3 の
「export はバンドル全体を取る操作なので管理者のもの」を改訂する — **全体は
管理者のまま**で、**subtree は読める者のもの**になる。断る理由だった
「欠けたアーカイブもバックアップと呼ばれる」を、断ることではなく
**アーカイブに自分が何かを言わせること**で解く。
[0123](0123-the-numbers-say-what-they-counted.md) §4 が「宣言では直らない」と
書いた当のもので、**測ったら形が違った**(§1)。
[0119](0119-an-operated-fleet-is-deployments-or-directories.md) §5 の宿題の
二番目、その最後
Date: 2026-08-23

## 1. 測ったら、危険の形が違った

0109 §3 と 0123 §4 はこう言っていた — 欠けた export もバックアップと
呼ばれ、**戻したときに残りが消える**。

**消えない。** `ochakai import` は加算的で、削除を一度もしない。空の
インスタンスに部分アーカイブを戻せば部分的なベースが手に入り、**失われた
のは戻した瞬間ではなく元を失った瞬間**である。

**本当の危険はもっと静かで、しかも今日ここにある。** subtree のアーカイブを
実際に取って中を見た:

```
=== archive of "" (whole base)      disposition: filename="ochakai-okf.tar.gz"
    index.md, log.md, <root>/teams/growth/…, <root>/glossary/…
=== archive of "<root>/teams/growth"  disposition: filename="ochakai-okf.tar.gz"
    index.md, log.md, <root>/teams/growth/…
```

**二つは同じ形をしている。** どちらも根の `index.md` を持ち、どちらも
`ochakai-okf.tar.gz` という名前で届く。中身が違うだけで、**どちらが
どちらかを言うものが一つも無い。**

だから 0109 §3 が恐れた事態は、**管理者だけが使える今日、既に作れる**。
断ることは、恐れていたものを一度も防いでいなかった。

## 2. 決定: アーカイブが、自分がどの部分かを言う

**読む人が出会う二箇所**に書く。

- **根の `index.md`** — frontmatter に `bundle_scope: "<prefix>"`(機械が
  読む)と、本文に「これは大きなベースの一部であってバックアップではない」
  の一文(人が読む)。**深い階層の `index.md` は一字も変わらない** —
  subtree アーカイブに欠けているのは彼らの*上*であって下ではない。
- **ファイル名** — `ochakai-okf-<subtree>.tar.gz`。**ここが効く**: 復旧する
  人はアーカイブを展開する前にファイル名を打つ。`ochakai import
  ochakai-okf-teams-growth.tar.gz` は、それ自体が何であるかを言っている。

**全体のアーカイブは一字も変わらない** — 名前も、根の index も、今までの
ままである。

## 3. 決定: subtree は読める者のもの、全体は管理者のもの

§2 で見分けが付くようになった以上、**断ることが買っていたものは無くなる。**

- **subtree のアーカイブは、その subtree を読める呼び出し元のもの。**
  そこに入っているのは、その呼び出し元が **concept を一つずつ取れば既に
  得られるもの**である。断っていたのは知識ではなく便宜だった。
- **全体(根)は管理者のまま。** スコープを持つ呼び出し元に「見える範囲の
  全体」を渡せば、それは 0109 §3 が恐れた形そのもの — **どの全体から来たかを
  名乗らない部分**である。根を求めるのが「全体を求める」の綴りであり、
  そこは 403 で断る。
- **読めない subtree は 404。** そこに何かあるかへの答えが境界である
  (0109 §4)。

これで **C1 が、ディレクトリの形の組織にも成り立つ** — 0119 §4 が
「出口(C1)に運用者が要る」と代金に数えたものが、返る。

## 4. 面

**数はどれも動かない。**

| 面 | 現れ方 |
|---|---|
| REST | 操作もパラメータも増えない。`GET /api/v1/bundle/{path}` に `Accept: application/gzip` は**元から subtree を取る**。変わったのは誰が呼べるかと、応答が自分を名乗ることである |
| CLI | `ochakai export --prefix <dir>`。**`FLAG` は動かない** — `--prefix` は `search`・`list`・`stats` の綴りで、面は名前を数える |
| MCP | **載せない**(0067 §5.1 のまま) |
| Web UI | 変わらない。curation の面であって、持ち出しの面ではない |

## 5. 検査する不変条件([0035](0035-verifiability.md))

- 全体のアーカイブが、名前も根の index も**変わっていない**こと。
- subtree のアーカイブが、名前と `bundle_scope` の**両方**で自分を名乗る
  こと。片方だけなら、片方しか見ない人には届かない。
- subtree のアーカイブが、その外の path を一つも運ばないこと。
- 管理者は全体も subtree も取れ、スコープを持つ呼び出し元は**読める
  subtree だけ**取れ、全体は 403、読めない subtree は 404 であること。

## 6. 採らなかった案

- **import に `bundle_scope` を読ませて警告を出すこと。** 検討して外した。
  import は予約ファイル(`index.md`)を読み戻さないと 0075 §4.2 が決めて
  おり、この一件のために例外を開けば、**手で書いたバンドルに同じ鍵を書いた
  人が意味の分からない警告を受け取る**。そして §2 のファイル名が、復旧する
  人には import を打つ**前**に届く — 後から言うより早い。
- **subtree を prefix で切り直して(re-root して)出すこと。** id が変わり、
  外を指すリンクが直せない形で壊れ、戻す場所も変わる。契約が既に
  「re-root しない」と書いており、それは**subtree のコピーであって移動では
  ない**からである。0119 §1 の「変換なしにデプロイへ卒業できる」も、この
  形だから成り立つ。
- **`ochakai export` とは別のコマンドを作ること**(`ochakai take` など)。
  CLI の数が増える。`--prefix` は既にある綴りで、**名前を増やさずに同じ
  ことが言える**なら増やさない。
- **スコープを持つ呼び出し元に、見える範囲の「全体」を渡すこと**(§3)。
- **アーカイブに署名やマニフェストを足すこと。** 完全性の証明は別の問題で、
  ここで解こうとしているのは**取り違え**である。
