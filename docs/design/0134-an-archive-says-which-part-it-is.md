# ochakai 設計ドキュメント 0134: アーカイブは、自分がどの部分かを言う

Status: Accepted(2026-08-28)。[0127](0127-an-archive-says-which-part-it-is.md)
を Superseded にして吸収する — **決定は一つも変わらず**、自分を名乗る二箇所の
うち、根の `index.md` の綴りだけが変わる。SPEC §8 は予約ファイルの
frontmatter に `okf_version` 以外の鍵を置く場所を持っておらず、§11 の
適合条件 3 が予約ファイルを §8 に縛るので、`bundle_scope` を書いた
`--prefix` のアーカイブは **OKF v0.2 に適合していなかった**(§2)。
[0109](0109-a-directory-has-readers-and-writers.md) §3 の改訂は 0127 の
ものをそのまま引き継ぐ。[0128](0128-a-number-is-for-an-area-not-a-rule-inside-it.md)
§2.2 に従い、差分ではなく領域を丸ごと述べ直している
Date: 2026-08-28

## 1. 測ったら、危険の形が違った(0127 §1、変わらず)

0109 §3 と [0123](0123-the-numbers-say-what-they-counted.md) §4 はこう言って
いた — 欠けた export もバックアップと呼ばれ、**戻したときに残りが消える**。

**消えない。** `ochakai import` は加算的で、削除を一度もしない。空の
インスタンスに部分アーカイブを戻せば部分的なベースが手に入り、**失われた
のは戻した瞬間ではなく元を失った瞬間**である。

**本当の危険はもっと静かで、しかも 0127 の前には既にそこにあった。**
subtree のアーカイブを実際に取ると、全体のアーカイブと**同じ形をしていた** —
どちらも根の `index.md` を持ち、どちらも `ochakai-okf.tar.gz` という名前で
届き、**どちらがどちらかを言うものが一つも無かった**。だから 0109 §3 が
恐れた事態は、管理者だけが使える時点で既に作れた。断ることは、恐れていた
ものを一度も防いでいなかった。

## 2. 変わったこと: 機械向けの一言が、SPEC の置き場を持っていなかった

0127 §2 は根の `index.md` の frontmatter に `bundle_scope: "<prefix>"` を
置いた。SPEC §8 にその場所が無い:

> Index files contain no frontmatter, with one exception: a bundle-root
> `index.md` MAY carry an `okf_version` key (§12).

そして §11 の適合条件 3 は "Every reserved filename (`index.md`, `log.md`)
follows the structure in §8 and §9 respectively when present" である。
`index.md` は予約ファイルなので、**未知の鍵を許す §4.1 の拡張規則はここには
届かない** — あれは concept 文書の規則である。つまり `--prefix` で出した
アーカイブは、C3 が満たすと言っている当の仕様に適合していなかった。

**そして、その一言は三度目だった。** 同じことを、根の `index.md` の見出しが
言い(`# ochakai knowledge bundle: teams/growth`)、その下の一文が言い、
ファイル名が言っている。**機械が読む口も既に一つある** — 見出しは本文で
あって、§8 が形を決めている当のものである。

## 3. 決定: アーカイブが、自分がどの部分かを言う

**読む人が出会う二箇所**に書く。

- **根の `index.md`** — 見出しが subtree を名乗り、本文の一文が「これは
  大きなベースの一部であってバックアップではない」と言う。frontmatter は
  `okf_version` だけで、SPEC §8 が許す姿そのものである。**深い階層の
  `index.md` は一字も変わらない** — subtree アーカイブに欠けているのは
  彼らの*上*であって下ではない。
- **ファイル名** — `ochakai-okf-<subtree>.tar.gz`。**ここが効く**: 復旧する
  人はアーカイブを展開する前にファイル名を打つ。`ochakai import
  ochakai-okf-teams-growth.tar.gz` は、それ自体が何であるかを言っている。
  ASCII の外の綴りは percent-encode し、素の名前は `filename*`(RFC 6266)で
  隣に運ぶ。

**全体のアーカイブは一字も変わらない** — 名前も、根の index も、0127 の前から
今までのままである。

## 4. 決定: subtree は読める者のもの、全体は管理者のもの(0127 §3、変わらず)

§3 で見分けが付く以上、**断ることが買っていたものは無い。**

- **subtree のアーカイブは、その subtree を読める呼び出し元のもの。**
  そこに入っているのは、その呼び出し元が **concept を一つずつ取れば既に
  得られるもの**である。断っていたのは知識ではなく便宜だった。
- **全体(根)は管理者のまま。** スコープを持つ呼び出し元に「見える範囲の
  全体」を渡せば、それは 0109 §3 が恐れた形そのもの — **どの全体から来たかを
  名乗らない部分**である。根は 403 で断る。
- **読めない subtree は 404。** そこに何かあるかへの答えが境界である
  (0109 §4)。

これで **C1 が、ディレクトリの形の組織にも成り立つ** —
[0119](0119-an-operated-fleet-is-deployments-or-directories.md) §4 が
「出口(C1)に運用者が要る」と代金に数えたものが、返る。

## 5. 面

**数はどれも動かない。**

| 面 | 現れ方 |
|---|---|
| REST | 操作もパラメータも増えない。`GET /api/v1/bundle/{path}` に `Accept: application/gzip` は**元から subtree を取る** |
| CLI | `ochakai export --prefix <dir>`。**`FLAG` は動かない** — `--prefix` は `search`・`list`・`stats` の綴りで、面は名前を数える |
| MCP | **載せない**([0067](0067-four-faces-and-what-they-decline.md) §5.1 のまま) |
| Web UI | 変わらない。curation の面であって、持ち出しの面ではない |

## 6. 検査する不変条件([0035](0035-verifiability.md))

- 全体のアーカイブが、名前も根の index も**変わっていない**こと。
- subtree のアーカイブが、**名前と根の index の見出し**の両方で自分を名乗る
  こと。片方だけなら、片方しか見ない人には届かない。
- **根の `index.md` の frontmatter が `okf_version` だけ**であること —
  全体のアーカイブでも subtree のアーカイブでも。
- subtree のアーカイブが、その外の path を一つも運ばないこと。
- 管理者は全体も subtree も取れ、スコープを持つ呼び出し元は**読める
  subtree だけ**取れ、全体は 403、読めない subtree は 404 であること。

## 7. 採らなかった案

- **`bundle_scope` を残し、適合しないままにすること。** C3 は八つの条件の
  一つで、「保存もワイヤも往復も OKF」と書いてある。仕様に合わない一鍵を、
  既に三箇所が言っていることのために残す理由が無い。
- **`bundle_scope` を根の `index.md` の本文に、機械の読める形で置くこと**
  (HTML コメント、定型の一行)。**新しい綴りを一つ発明することになる。**
  §8 が本文の形を決めており、見出しはその形の中にある。
- **import に scope を読ませて警告を出すこと。** 0127 が外したまま。import は
  予約ファイルを読み戻さないと [0075](0075-the-bundle-is-the-address-space.md)
  §4.2 が決めており、§3 のファイル名が復旧する人には import を打つ**前**に
  届く。
- **subtree を prefix で切り直して(re-root して)出すこと。** id が変わり、
  外を指すリンクが直せない形で壊れる。契約が既に「re-root しない」と書いて
  おり、それは**subtree のコピーであって移動ではない**からである。
  0119 §1 の「変換なしにデプロイへ卒業できる」も、この形だから成り立つ。
- **`ochakai export` とは別のコマンドを作ること**(`ochakai take` など)。
  CLI の数が増える。`--prefix` は既にある綴りである。
- **スコープを持つ呼び出し元に、見える範囲の「全体」を渡すこと**(§4)。
- **アーカイブに署名やマニフェストを足すこと。** 完全性の証明は別の問題で、
  ここで解こうとしているのは**取り違え**である。
