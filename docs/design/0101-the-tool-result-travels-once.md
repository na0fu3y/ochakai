# ochakai 設計ドキュメント 0101: ツールの答えは一通で運ばれる

Status: Accepted(2026-08-15)。
[0015](0015-surface-consistency.md) §3.1 が置いたツール本数の予算と、
[0076](0076-two-tools-leave-mcp.md) がそれを守るために降ろした二本の
延長線上にある — **予算が数えていなかった半分**を数え、その半分自体を
畳む。[0067](0067-four-faces-and-what-they-decline.md) §1 の「MCP の既定は
no、ツールスキーマはエージェントのコンテキストから支払われる」を、
スキーマだけでなく**応答**にも適用する。
Date: 2026-08-15

## 0. この記録が決めたこと

1. **MCP のツールは `outputSchema` を宣言しない。** 七本すべてから
   消える(§3)。
2. **ツールの答えは text コンテントブロック一つで返る。** 同じ JSON を
   `structuredContent` にも入れることをやめる(§3)。
3. **MCP-BYTES は wire が運ぶスキーマを全部数える** — 入力側だけでなく
   出力側も(§5)。今日はどちらも空なので数は動かない。

## 1. 数えていた側より、数えていなかった側が大きかった

`docs/surface.md` の MCP-BYTES は、クライアントが会話の間ずっと保持する
バイト数に天井を置いている。実測でその上限 13,500 に対し 13,474 —
残り 26 バイトまで詰めた、この文書で最も真面目に守られていた数字である。

同じセッションの `tools/list` が実際に運んでいたもの:

| | bytes |
|---|---|
| 数えていた(name + description + inputSchema + instructions) | 13,474 |
| 数えていなかった(outputSchema 七本) | 14,986 |

**数えていない方が大きい。** 天井は半分を見ていた。

呼び出しごとの費用にも同じことが起きていた。`get_context` 一回の応答:

| | bytes |
|---|---|
| `content[0].text` | 10,384 |
| `structuredContent` | 10,439(**中身は同一**) |
| 応答全体 | 22,009 |

エージェントが一回の読みで払う量が、必要な量のちょうど二倍だった。

## 2. どれも書いた覚えのない行だった

三つとも go-sdk の既定である。

- `mcp.AddTool` はハンドラの戻り型 `Out` から `outputSchema` を導出する。
  型を書いたことが、スキーマを公開したことになっていた。
- `outputSchema` があると SDK は結果を `structuredContent` に入れる。
- そして `Content` が空なら、**同じ JSON を text ブロックとしても積む** —
  MCP 仕様が SEP-2106 以前のクライアントのために勧めている後方互換の
  fallback である。

つまり重複は仕様準拠であり、スキーマは型注釈の副作用だった。
[0035](0035-verifiability.md) が言う「規約を信じるのではなく外から不変条件を
読む」の、外から読んでいなかった側である — テストは
`tool.InputSchema` を読み、`OutputSchema` を読まなかった。

## 3. 決定: 型付きの出力をやめ、text 一通にする

ハンドラの登録を通す `tool()` アダプタが `any` を SDK に渡し、
自分で JSON を text ブロックに積む。`Out` が `any` なら SDK はスキーマを
導出せず、返り値が `nil` なら `structuredContent` も埋めない。

失うのは `structuredContent` を読むクライアントの型付き出力である。
運ぶ JSON は一バイトも変わらず、text コンテントは**どの MCP クライアント
でも読める**唯一の形である。ochakai の答えはもともと JSON 文書であって、
REST も CLI (`--json`) も同じ形で返している — この面だけが同じものを二つの
場所に置いていた。

`get_file` だけは例外的に見えるが例外ではない: ファイルのバイト列は
それ自身のコンテントブロックで返り、メタデータの JSON はその**隣に**積む。

## 4. 却下した案

- **`outputSchema` を残し、`Content` を自分で埋めて重複だけ消す。**
  重複は消えるが、SEP-2106 以前のクライアントが受け取るのは中身の無い
  ブロックになる。仕様が用意した後方互換の逃げ道を、自分の都合で塞ぐ
  ことになる。
- **天井を 28,500 に上げて、両方数える。** 数えるべきものを数えるのは
  正しい。しかし [docs/surface.md](../surface.md) の三つ目の問いは
  「何が畳めるか」であり、**畳めるものがあるのに天井を上げるのは、その
  問いに答えないことである**。エージェントのコンテキストを 15KB 買う
  理由が、この面には無かった。
- **ツールを減らして帳尻を合わせる。** 0076 が既に二本降ろしている。
  本数は今回の問題ではない。

## 5. 予算の定義を直す

`residentBytes` は両方のスキーマを読む。今日は出力側がどれも `nil` なので
合計は 13,460 — この記録が数え方を変えたことによっては**一バイトも
増えない**(13,474 との差 14 は [0102](0102-a-ruling-travels-with-its-reason.md)
が `put_concept` の説明文を一語縮めたぶんである)。**数は動かないが、
意味が変わる**: 天井が見ているのは「wire が運ぶツール定義の全部」になり、
次に `outputSchema` を宣言する変更は、この面の三つの問いを通ってからで
ないと通らない。

呼び出しごとの重複の側は、テストのヘルパ `answerOf` が持つ:
結果を読むテストはすべてそれを通り、`structuredContent` があれば落ちる。
一箇所の専用テストではなく**結果を読むたびに主張される**のは、これが
「誰かが書き忘れる」種類の不変条件だからである。

## 6. 互換性

MCP は 0.x で不安定な面である([docs/compatibility.md](../compatibility.md)、
[0088](0088-a-retired-name-answers-for-one-release.md))。REST は動かない —
`/api/v1` の応答は初めから JSON 一通であり、この記録はそれに合わせる
変更である。
