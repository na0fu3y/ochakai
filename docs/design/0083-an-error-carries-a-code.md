# ochakai 設計ドキュメント 0083: エラーは機械が読む符号を運ぶ

Status: Accepted(2026-08-08)。[0064](0064-rest-stops-at-api-v1.md) と
[docs/compatibility.md](../compatibility.md) の下で、エラー応答に
`code` を足す — [0082](0082-what-the-freeze-holds-still.md) が凍結の外と
定めた応答専用スキーマへの追加である。どの決定も動かさない
Date: 2026-08-08

## 1. 何が起きたか

エラー応答は `{"error": "<英語の散文>"}` の一種類しか無かった。

問題は文言ではなく、**文言しか無いこと**である。三つの条件が 409 を返す。

| 条件 | 意味 |
|---|---|
| `ErrAlreadyExists` | その id は埋まっている |
| `ErrNotDeleted` | 生きている concept に purge を求めた(削除が先) |
| `ErrNoRejection` | 却下されていない concept に取り下げを求めた |

区別する手立ては散文の照合だけで、しかも
[docs/compatibility.md](../compatibility.md) は**その散文が minor で
変わってよい**と宣言している。つまり REST を自分のサービスに埋め込む
開発者(C6)に、ochakai は「壊れると分かっている方法」しか渡していな
かった。`If-Match` を使うクライアントも同じで、412 と 409 の取り違えを
避けるには結局メッセージを読むことになる。

## 2. 決定: 散文の隣に、閉じた語彙の `code` を置く

エラー応答は必ず二つのキーを持つ。

- **`error`** — 人のための一文。これまでどおり、いつでも書き直してよい。
- **`code`** — クライアントが分岐してよい語。
  [`internal/domain/errorcode.go`](../../internal/domain/errorcode.go) の
  12 語の閉じた集合で、契約が同じ集合を enum として宣言する。

12 語は `invalid` / `forbidden` / `read_only` / `not_found` /
`method_not_allowed` / `already_exists` / `not_deleted` / `no_rejection` /
`precondition_failed` / `too_large` / `unsupported` / `internal`。

**ステータスが既に条件を決めている場合も、`code` は繰り返す。** 一部の
エラーにしか付かない鍵は、クライアントが「今回は付いているか」を先に
聞かなければならず、分岐の道具にならない。冗長さはその代金である。

**符号は sentinel から引く。** 写像は `writeError` 一箇所にあり、
呼び出し側 60 余箇所は一行も変わらない — クライアントが分岐する対象は
条件であり、条件は sentinel が既に名指している。

## 3. なぜ凍結を破らないか

0082 §2 が凍結の対象を「住所・リクエストの形・応答からの削除と変更」と
定め、応答専用スキーマへの**追加**をその外に置いた。`code` はまさに
それである。エラー封筒は `components/responses/Error` に直接書かれた
スキーマで、`requestBody` から参照される綴りが OpenAPI に存在しない以上、
定義からして応答専用である(0082 §3 に、その二つ目の置き場所を明記した)。

指紋の再生成は要る。追加が黙って通らないことが 0082 の狙いであり、本書の
PR でも golden は同じ diff に出ている。

## 4. なぜ RFC 9457(`application/problem+json`)ではないか

標準の封筒は `type` / `title` / `status` / `detail` / `instance` を持ち、
`type` は URI である。採らない理由は三つある。

- **メディアタイプが変わる。** `application/problem+json` は
  `application/json` の**置き換え**であり、応答の content type を動かすのは
  0082 が凍結の本体と呼んだ「住所」の変更である。セキュリティ上の欠陥では
  ないので、これは通らない。
- **`type` の URI はホスト名を要求する。** 意味のある URI は
  ochak.ai の下に置くことになり、**契約が一つのドメインの生存に依存する**。
  C1(資産は利用者のもの)を掲げる製品が、エラーの読み方だけ自分の
  ドメインに預けるのは筋が通らない。
- **運ぶ情報が同じである。** `status` は HTTP のステータス行と重複し、
  `title`/`detail` は `error` と重複する。増えるのは鍵の数だけである。

将来 1.0 で封筒ごと置き換える選択肢は残る。そのときは 0064 の凍結が
明ける場所であり、今日の追加はその邪魔をしない。

## 5. 採らなかった案

- **散文の照合を続ける。** クライアントに壊れる方法を渡し続ける。
  compatibility.md が散文の自由を宣言している以上、これは不作為ではなく
  矛盾である。
- **409 を三つの別ステータスに割る。** 割れるステータスが無い(409 が
  正しい)。415 や 413 も同じで、HTTP のステータスは条件より粗い。
- **エラーごとに一意な符号を発行する(`E1042` 形式)。** 番号は読めず、
  意味の変化を隠す。閉じた語彙を数え、増やすときに数が動くほうが、
  この repo の他の面と同じ扱いになる。
- **`code` を任意にする。** §2 のとおり、任意の鍵は分岐の道具にならない。
- **詳細フィールド(`field`・`details`)も同時に足す。** 足りないと
  分かってから足せばよい。今日困っているのは条件の区別だけである。

## 6. 面と、数えること

- **REST** — 全エラー応答。契約が enum を宣言する。
- **CLI / MCP / Web UI** — 出さない。CLI は人が読む一文を印字し、MCP の
  ツールはエラーを文字列で返す([0067](0067-four-faces-and-what-they-decline.md) §2:
  三面は REST のクライアントであり、面ごとに符号を再輸出する理由は無い)。
  `internal/apiclient` は符号を読んで保持するので、CLI がいつでも使える。
- **VOCAB は 34 → 46 に上がる。** 12 語はクライアントが覚える語であり、
  [docs/surface.md](../surface.md) の語彙の節が数える対象そのものである。
  天井を上げる決定であり、そう言って上げている — 買っているのは「散文に
  依存しない分岐」という能力で、代金は 12 語である。
  surface.md 自身が「エラーの文言は数えていない」を**次の逃げ道**として
  名指していた。散文のままなら数に出ないまま契約になっていたはずのものが、
  語彙として数えられる側に移った。
