# ochakai 設計ドキュメント 0111: 目のための重みを、目にだけ出す

Status: Accepted(2026-08-17)。`ochakai search` / `list` / `browse` の
人間向けの行に、太字と dim を足す。標準出力が端末のときだけで、パイプと
リダイレクトが受け取るバイト列は 1 バイトも変わらない。
[0110](0110-the-first-column-is-the-key-you-asked-for.md) が第一列を
落とした行に続く決定であり、そこで落とした列を戻すものではない。
[0067](0067-four-faces-and-what-they-decline.md) §5.3 が断る「TUI・対話
モード」は断られたままである(§3)。`NO_COLOR` を読むので
[docs/surface.md](../surface.md) の ENV が 14 → 15 になる。
Date: 2026-08-17

## 1. 何を変えるか

行の**綴りは変えず、重みだけを足す**。

```
ochakai://metrics/revenue	stable	売上 — 完了した注文の合計 · …返品を差し引く…
└────── 太字 ──────┘	素	素     └──────── dim ────────┘
```

規則は一つである。**住所は太字、後ろに続く散文は dim、間は素のまま。**

- 太字になるのは、読み手が次のコマンドに写す欄 — `search` / `list` の
  URI、`browse` のディレクトリ名・セグメント・ファイル名。
- dim になるのは、行の末尾に続く散文 — `— description` と、なぜ一致した
  かを言う `· snippet`([0084](0084-a-hit-says-why-it-matched.md))。
- 素のままなのは、その間にある値 — `status`、`type`、そしてフィードの
  第一列。フィードの第一列は読み手が「これで並べてくれ」と言った鍵で、
  上下の行と**比べる**ものである(0110)。比べる列を薄くしてはいけない。

出るのは**標準出力が端末のときだけ**である。パイプ、リダイレクト、
`--json`、そしてテストが読むバッファには何も出ない。`NO_COLOR` に空で
ない値が入っていれば、端末でも出ない。

`ochakai stats` と `ochakai get` は飾らない(§5)。

## 2. なぜ — 0110 の後の行を、人が読むから

0110 がスコア列を落として、`search` の行はこうなった。

```
ochakai://metrics/revenue	stable	売上 — 完了した注文の合計
```

第一列が住所になったのは正しい。だが**全欄が同じ重み**なので、10 行
返ってくると、ある行の description が次の行の URI と地続きに見える。
ターミナルは行を折り返すので、1 行が 2 行に見え、2 行が 1 行に見える。

これは新しい情報が要る問題ではない。**行の中の役割の切れ目が、区切り
文字にしか書かれていない**という問題であり、区切り文字は目には見えない。
タブは機械のためのもので、人のためのものではなかった。

足すのは情報ではなく重みである。**エスケープを剥がせば、行は今日と 1
バイト違わない** — これが本文の全体で、テストもそれを検査している
(`TestStyledLineStripsBackToThePlainOne`)。0110 が落とした列は「意味を
説明できない数」だったが、太字は数ではないので、説明すべき較正が無い。

三つの問い([docs/surface.md](../surface.md))には、こう答える。

- **誰が詰まったか。** 端末で `ochakai search` を打った人。この面の
  既定の読み手である(CLI は完全性の面、0067 §1)。
- **既存の面で足りるか。** 足りない。Web UI は同じ検索を読みやすく
  描くが、それは**別の面へ移れ**という答えであって、CLI の行を読める
  ようにする答えではない。
- **代わりに何を畳めるか。** 何も畳んでいない。畳んでいない代わりに、
  **払える代金の側を削った**: フラグを足していないので数が動くのは
  `NO_COLOR` の 1 語だけで、その 1 語も ochakai が発明した綴りではない
  (§4)。

## 3. これは 0067 §5.3 が断った TUI ではない

0067 §5.3 は「TUI・対話モード」を CLI に載せないと決め、理由をこう書いた
— **パイプで合成できる行指向出力が CLI の価値**である、と。

その価値は 1 ミリも減らない。判定は**標準出力が character device か**の
一点で、パイプもファイルもキャプチャバッファもそうではないので、
`ochakai search q | cut -f1` も `> hits.txt` も、この決定の前と同じ
バイト列を受け取る。TUI が持つもの — 画面の所有、カーソル、キー入力を
待つループ、再描画 — は一つも増えていない。増えたのは、1 行ずつ吐く出力
の中の**属性**である。

判定を一度だけ、`main` で行うのもこのためである。行ごとに聞けば、聞き
忘れた印字だけがパイプにエスケープを漏らす。

## 4. 色ではなく太字と dim、そして `NO_COLOR`

**色相を使わない。** 理由は三つある。

- [0094](0094-the-page-runs-under-a-policy.md) が Web UI で直した欠陥は
  「『ここに居る』を言っていたのは色だけだった」ことである。ここでの
  同じ規則は「剥がしても行は全部言っている」で、太字と dim は**何の
  情報も運んでいない**から満たせる。色で `status` を塗った瞬間、これは
  破れる(§5)。
- 端末の配色は**利用者のもの**である。8 色パレットの各色が実際に何色に
  なるかはテーマ次第で、読みやすくするつもりの緑が読めない緑になる。
  太字と dim はテーマを持たない。
- 色覚は人によって違う。重みは違わない。

dim(`\x1b[2m`)を描かない端末はある。そのとき出るのは**素の行**で、
つまり今日の行である — 劣化の先が「壊れた表示」ではなく「元の表示」で
あることが、この属性を選ぶ三つ目の理由である。

**`NO_COLOR` は ochakai が定義した変数ではない。** 端末の装飾を止める
合図として既に多くのプログラムが読んでいる綴りで、値は見ず、**在ること
だけ**を見る、というところまで含めて既存の慣習である。ここで
`OCHAKAI_COLOR` を発明すれば、利用者は ochakai のためだけにもう一つ
名前を覚えることになる。それでも surface の ENV に載るのは、あの節が
数えているのが接頭辞ではなく**呼び出し**だからで、`PORT` がそこに載って
いるのと同じ理由である。

## 5. 採らなかった案

**`--color=auto|always|never` フラグ。** FLAG が 28 → 29 になり、覚える
綴りが二つになる。`always` が要るのは「端末でない出力に色を残したい」
場合 — CI のログを色付きで見る、`less -R` に流す — だが、ochakai の CLI
にその用途は無い。実需が来たら、そのとき 1 本足す判断をする(§7)。

**`status` を色分けする(draft=黄、stable=緑)。** 信頼は status では
なく provenance で判断する、というのがこの製品の中心の一つである
(0065、OKF SPEC §5.3)。緑の `stable` は「安全」と読まれ、誰も検証して
いない `stable` がそう読まれる。**色が判断を先回りする**ので、採らない。

**却下された行を色で区別する。** [0104](0104-a-ruling-travels-with-its-reason.md)
は、却下された concept の行を他と**同じ綴り**にすると決めている — 列は
concept のものであり、このインスタンスの裁定はその一つではない。色で
戻せば、決定を綴りではなく描画で覆すことになる。

**クエリ語をハイライトする。** どこが一致したかはサーバが `snippet` と
して既に運んでいる(0084)。クライアントが語を再検出すれば、ベクトルで
当たったヒットに**嘘の下線**を引く — 埋め込みが当てた行に、字句として
一致した箇所は無い。

**`get` と `stats` も飾る。** `get` が印字するのは文書そのもの
(markdown)で、飾り始めればシンタックスハイライトを実装することになり、
それは端末の中に第二の Web UI を作る道である。`stats` は `key\tvalue` の
一行一値で、飾るべき構造が無い(そして 0069 が `cut -f2` を約束している)。

**何もしない。** 新機能の既定の答えはこれである。それでも採ったのは、
代金が **ENV 1 語**、契約への影響が**ゼロ**、そして剥がせば同じ行、
という三つが揃ったからである。どれか一つでも欠けたら答えは no だった。

## 6. 互換性

[docs/compatibility.md](../compatibility.md) は CLI の契約に「印字する
ものの形」を含める。**この決定はそれを変えない**: 端末でない出力は 1
バイトも動かないので、スクリプトから見た ochakai は今日と同じである。
0110 が **BREAKING** だったのと対照的で、違いは、あちらが**列を落とした**
のに対しこちらが**属性を足した**ことにある。

## 7. 見直す条件

`--color=always` の実需が来たら — 端末でない出力に装飾を残したい理由が
具体的に出てきたら — FLAG を 1 本足す判断になる。そのときも既定は
`auto` のままで、フラグは既定を上書きするだけのものである。
