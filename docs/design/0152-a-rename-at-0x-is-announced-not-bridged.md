# ochakai 設計ドキュメント 0152: 0.x の改名は、橋を架けずに告げる

Status: Accepted(2026-09-27)。[0088](0088-a-retired-name-answers-for-one-release.md)
を Superseded にする — MCP と CLI の安定性契約の現行ドキュメント。
Date: 2026-09-27

## 1. 何が起きたか

0088 は、MCP のツール名か CLI のコマンド名を改名したリリースのあいだ、
古い綴りも答えさせると決めた。`tools/list` には載せずに呼び出しだけを
転送するミドルウェアと、窓が一リリースで閉じることを CHANGELOG と
突き合わせるテストが一組になっていた。

**0088 が入ってから 0.29.3 までの七週間、この表は一度も使われなかった。**
改名は一件も起きず、二つの一覧(`mcpserver.RetiredToolNames` と CLI の
`retiredCommands`)はずっと空で、テストの中の架空の行だけが通っていた。
それでも約 475 行(うちテスト 336 行)と、release の準備手順の一段と、
CONTRIBUTING の一段落を毎リリース払っていた。

## 2. 決定

- **0.x の改名と削除は、橋を架けない。** 改名したリリースから、古い
  綴りは答えない。CHANGELOG はその項目を **BREAKING** と印し、release の
  規則どおり minor を上げる。MCP の古い名前は、プロトコルの unknown tool
  の誤りになる。`tools/list` と `ochakai help` が、いま呼ぶべき名前を言う。
- **機構は消える。** 転送ミドルウェア、CLI の読み替え、二つの一覧、
  窓を閉じるテスト、release 手順の一段。
- **REST は変わらない。** OKF コアの凍結([0107](0107-the-freeze-holds-the-okf-core.md))
  はこの記録の外にある。

## 3. なぜ、今それでよいか

0088 §1 の懸念 —— エージェントの設定はツール名を名指しで持ち、
CHANGELOG を読むのは人だけ —— は正しく、消えていない。変わったのは
値段の見積もりである。

- [compatibility.md](../compatibility.md) は、0.x のあいだ MCP と CLI は
  不安定で、**最新のリリースだけを支える**と既に言っている。窓は
  その約束に一リリースぶんの例外を足すものだった。
- ツール名はいま六本で、改名は面を畳むとき
  ([0054](0054-concept-is-the-okf-word.md)・[0076](0076-two-tools-leave-mcp.md))
  にしか起きていない。起きる頻度に対して、常設の機構は重い。
- 壊れ方は黙っていない。古い名前での呼び出しは失敗として返り、
  `tools/list` がその場で行き先を教える。0088 が避けたかったのは
  「黙って違うことをする」形ではなく、エージェントの仕事が一度止まる
  ことで、それは 0.x が既に払うと言っている代金である。

## 4. 戻す条件

**1.0 を切るときに、MCP と CLI の安定性契約を改めて決める。** 凍る面が
増えれば、名前の窓はその契約の一部として意味を持つ。0088 の全文は
下の commit にあり、その時点で読み直せばよい。0.x のあいだでも、
改名したせいで設定が壊れたと実際に報告されたら、それが戻す理由になる。

## 5. 面

どの数も動かない。0088 の古い名前は `tools/list` にも `clientCommands`
にも出ていなかったので、MCP も CLI も元から数えていなかった。
[docs/surface.md](../surface.md) の「数えていないもの」から改名前の
名前の項が消える。

## 6. 採らなかった案

- **機構を残し、次の改名で初めて使う。** 空の表を守るテストは、表が
  空であるかぎり何も守らない。必要になれば 0088 の commit から戻せる。
- **窓を文書だけの約束にする。** 0088 §7 が退けたとおり、文書は落ちず、
  閉じ忘れる。約束しないほうが正直である。
- **古い名前を unknown tool より丁寧な誤りにする。** 古い名前を覚えて
  おく表が要り、それはこの記録が畳む機構そのものである。
