# ochakai 設計ドキュメント 0122: 最初の一行を置けるのは、管理者だけである

Status: Accepted(2026-08-23)。[0109](0109-a-directory-has-readers-and-writers.md) §3 を改訂する
— 管理者の床を呼び出し元の側から読み直し、**最初の一行を置けるのも
`OCHAKAI_ADMINS` だけである**と言う。ポリシーに行を書くのは管理者の操作で
あって、「管理者の検査をたまたま通った」呼び出し元の操作ではない。付与の
規則も、deny を持たないことも、スコープ外を 404 と答えることも動かない。
[0120](0120-the-policy-is-replaced-only-as-it-was-read.md) が足した前提条件とも
直交する
Date: 2026-08-23

## 1. 何が起きていたか

`SetPolicy` は管理者の検査を通してから書き、**書いたあとにもう一度**
`Policy` を呼んで結果を返していた。`Policy` はまた管理者の検査をする。

付与が一つも無いデプロイでは、**呼び出し元が誰であれ最初の検査は通る** —
0109 §2 の「行が一つも無いデプロイは、この記録の前と一行も違わない」が
そう決めているからである。だから `OCHAKAI_ADMINS` に名前の無い呼び出し元が
最初の一行を書くと、こうなる:

1. 入口の検査が通る(まだ付与が無いので、全員が通る)。
2. 行が書かれ、**コミットされる**。
3. ログに `access policy replaced` が出る。
4. 出口の再読み込みが、**いま自分が作ったポリシー**に照らして拒否される。
5. 呼び出し元は **403 を、`ETag` もポリシーの本文も無しで**受け取る
   (返るのは `forbidden` の error 本文だけである)。

**403 は「何も書かなかった」と言う符号である。** 書いてから言えば嘘に
なる。しかも境界は既に入っているので、その呼び出し元はこのあと**自分の
書いたポリシーを読むことも消すこともできない** — 編集できるのは
`OCHAKAI_ADMINS` だけになったからである。**やり直せば、そのたびに
ポリシーが置き換わる** — 失敗に見える操作を再送するのは、自動化が
必ずすることである(0119)。

**この形は統合テストの側にも跡を残していた。** wire でポリシーを試す
テストが `OCHAKAI_ADMINS` に `*` を置いており、そう置かないと最初の
`PUT` が通らなかった。**設定を緩めないと書けないのは、検査ではなく
機構のほうがおかしい**という合図だった。

## 2. 決定: 行を書くのは管理者である。断るのは書く前である

`PUT /api/v1/access` が付与を一つ以上持つとき、呼び出し元が
`OCHAKAI_ADMINS` の名指す principal でなければ **403 で、何も書かない**。

- **これは 0109 §3 の床そのものである。** あちらは「編集できる者を
  ポリシーの中で決めることはできない」と、設定の側から書いた。同じ床を
  呼び出し元の側から読むと、「最初の一行を置いた瞬間からポリシーは
  `OCHAKAI_ADMINS` のものになるので、その一行を置けるのも
  `OCHAKAI_ADMINS` である」になる。§3 が言い落としていたのは、**床が
  効き始める瞬間そのもの**だった。
- **§2 の約束は動かない。** 「付与の無いデプロイは前と同じ」は
  **知識について**の約束である。ポリシーは知識ではない — 0109 §5 が
  `/api/v1/bundle` の下に置かないと決めた当のもので、バンドルの外に
  ある文書には §3 の床が最初から立っている。
- **付与を空にする置き換え**(ポリシーを消す)は変わらない。境界を
  無くす操作の結果は「全員が全部できる」であり、締め出しは起きない。
  付与を持つデプロイでこれができるのは、入口の検査を通る管理者だけで
  ある。
- **管理者を一人も名指していないデプロイ**は、これまでどおり 400 で
  断る(0109 §3、`OCHAKAI_ADMINS` を先に設定せよ)。呼び出し元では
  なく設定の問題なので、符号も文面も別のままにする。

**互換性の話ではない。** ここで断る呼び出しは、**これまでも例外なく
403 で終わっていた** — 出口の検査が通ることは決してなかったからである。
変わったのは符号ではなく、**403 が本当のことを言うようになった**こと、
つまり行が残らなくなったことである。成功していた呼び出しは一つも
失敗しない。

## 3. 書き込みの後ろで、断らない

出口の再読み込みは `Policy` を通らなくなった。**書き終えた操作の
戻り道に、拒否できる検査を置かない** — 置けば、起きたことを起きなかった
と報告する経路が必ず一本できる。返すのは保存されたポリシーとその版で、
`granted_at` と `granted_by` を埋めるのは store だからそのまま読み戻す
(0120 §3)。

これは §2 の決定より一般的で、この記録が本当に残したい規則である:
**符号が状態について言うことは、状態のほうが先に確定していなければ
ならない。**

## 4. 面

**一つも増えない。** 符号も文面の置き場所も既にある。

| 面 | 現れ方 |
|---|---|
| REST | `PUT /api/v1/access` の 403 が、行を残さなくなる。符号は `forbidden` のまま(0083 の語彙は動かない) |
| CLI | `ochakai access -f` が同じ 403 を表示する。フラグは増えない |
| MCP | **載せない。** 0109 §5 がポリシーそのものを載せていない |
| Web UI | 保存が 403 のとき、**管理者だけが編集できると名指して言う**。付与が無いあいだ読みは全員に開いているので、このタブは全員に出る |

**Web UI のタブは、付与が無いあいだ管理者以外にも出たままである。**
403 しか返さないボタンは嘘だ(0109 §6、0040 §2.3)という規則に、ここは
半分しか従っていない。従い切るには「あなたは管理者か」をサーバが応答に
書く必要があり、それは認可の答えを二つ目の綴りで配ることになる。
**代わりに保存の失敗が理由を名指す** — 型で防げないものは文章に任せる
(0066 §1)。付与が一行でも入れば、タブは読める呼び出し元にだけ出る
状態に戻る。

## 5. 検査する不変条件([0035](0035-verifiability.md))

- 付与の無いデプロイで、`OCHAKAI_ADMINS` の外の呼び出し元が最初の一行を
  書こうとすると 403 になり、**そのあと管理者が読んだポリシーが空である
  こと**。403 が本当かどうかは、断られた側からは確かめられない。
- 同じデプロイで管理者が同じ文書を書くと通り、版が返ること。
- 付与が入ったあとは、外の呼び出し元が入口の検査で断られること
  (0109 が最初から覆っていた側)。
- wire のテストが `OCHAKAI_ADMINS` に `*` を置かずに済むこと。
  **緩めた設定でしか通らない経路は、テストが隠している欠陥である。**

## 6. 採らなかった案

- **出口の検査だけ外し、最初の一行は誰でも書けるままにする。** 403 と
  状態の食い違いは直るが、`OCHAKAI_ADMINS` に居ない者が全員分の境界を
  引けることが残り、**その者は自分の引いた境界を undo できない**。
  0109 §3 の床は、まさにその状態を作らないために在る。
- **書けたことにして 200 を返す**(締め出しを受け入れる)。呼び出し元が
  自分を締め出したことに気づく契機が、**あとで 404 を見ること**しかない
  — 0120 §1 が「境界が効きすぎた形で現れる障害」と呼んだ形そのもので
  ある。
- **400 で断る。** 隣の「管理者が居ないデプロイ」の検査と符号を揃える案。
  採らなかったのは、断る理由が**要求の形ではなく誰が呼んだか**だから
  で、`ErrForbidden` はその意味に既に割り当てられている(0109 §4)。
- **最初の一行に限り、書いた本人を管理者として自動的に付与する。**
  ポリシーの中で編集者を決めることであり、0109 §3 が回転扉と呼んで
  断った当のものである。
- **応答に「あなたは管理者である」を載せて Web UI のタブを正確にする。**
  認可の答えが二箇所になり、片方が古びる。要るようになったら
  それ自身の記録を取る。
