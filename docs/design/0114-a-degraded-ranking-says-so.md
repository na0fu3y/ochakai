# ochakai 設計ドキュメント 0114: 退化した順位は、そう名乗る

Status: Accepted(2026-08-17)。[0080](0080-search-and-how-a-deployment-embeds.md)
§1 の融合が**片肺で走ったとき**に何が起きるかを決める。0080 が決めた
「何を融合するか」「どう埋め込むか」は一つも動かない。
[0082](0082-what-the-freeze-holds-still.md) §2 の下での応答への追加で
あり、そのとき §3 の「応答スキーマが住む場所は二つ」が**三つだった**
ことが分かったので、そこも改訂する(§5)。
Date: 2026-08-17

## 0. この記録が決めたこと

1. **クエリを埋め込めなかった検索は、応答で `degraded: true` と言う**
   (§1)。REST・MCP・CLI・Web UI の四面すべて。
2. **埋め込みを持たないデプロイは退化していない。** そこでは語の一致
   だけが答えであって、落ちた結果ではない(§2)。
3. **ワイヤに乗るのは値一つで、文は面ごとに書く**(§3)。
4. **0082 §3 の応答専用規則は、operation に直接書かれた応答スキーマ
   にも届く** — 置き場所は二つではなく三つだった(§5)。

## 1. 落ちても、答えは同じ顔をして返ってきた

0080 §1 の検索は三つのリストを融合する — レキシカル、concept の
ベクトル、ファイルのベクトル。後ろの二つはクエリの埋め込みから出るので、
**埋め込みが取れなければ融合はレキシカル一本になる**。

その退化は最初から意図されたものである。埋め込みの provider が落ちた
ときに検索ごと 500 にするより、語の一致だけでも返すほうがよい。問題は
そこではなく、**返したあと誰にも言わなかった**ことである:

```go
s.Log.Warn("query embedding failed; falling back to lexical-only", "error", err)
```

ログは運用者が**後から**見に行くものである。いま薄い結果を手にしている
のは呼び出し側で、その人には区別が付かない — 0089 §1 が切り捨てられた
ベクトルについて書いたのと同じ形で、**失敗が成功と同じ顔をしている**。

そして誰が困るかは C8 が決めている。**trigram の索引は二文字の日本語語を
引けない**([surface.md](../surface.md) C8、0080)。日本語のデプロイで
埋め込みが落ちるということは、検索が「ほぼ何も返さない」に近づくという
ことであり、そのとき利用者が最初に疑うのは自分の問いの立て方である。
**問いを書き直しても直らないことを、問いの側は知りようがない。**

C7(人間の改善ループが測れる)も同じことを言っている — 0089 §1 の
「測れない失敗は、無いことと見分けがつかない」。ここでは測る先が
`stats` ではなく**その応答そのもの**である。退化はデプロイの性質ではなく
一回の呼び出しの性質なので、集計に出しても手遅れになる。

## 2. 埋め込みを持たないデプロイは、退化していない

`OCHAKAI_EMBEDDINGS` を設定していないデプロイも、レキシカル一本で
答える。**そこに同じ旗を立てない。**

理由は旗の意味である。`degraded` が言っているのは「**このデプロイが
普段返すものより悪い**」であって、「ベクトルを使わなかった」ではない。
埋め込みを持たないデプロイでは語の一致が答えの全部であり、毎回立つ旗は
どの応答についても何も言わない — [0087](0087-a-sandbox-says-it-is-one.md)
が `sandbox` を毎回言うのは姿勢が**常に**真だからで、こちらは逆に、
**たまにしか真でないから意味がある**。

だから `s.Embedder == nil` は `false` である。境界はここ一箇所にあり、
テストがそれを一番強く留めている。

## 3. ワイヤに乗るのは値一つで、文は面ごとに書く

**REST** の検索応答に `degraded: true` が付く。無いときは**キーごと
無い** — `cursor` と同じで、毎回立つキーは誰も読まないからである。

残りの三面はこの値を読んで、**自分の読み手の言葉で言う**:

- **CLI** は stderr に `note:` の一行。標準出力は 1 ヒット 1 行のまま
  で、パイプが受け取るバイト列は退化しても変わらない
  ([0111](0111-weight-for-the-eye-and-only-for-an-eye.md) と同じ規則、
  一覧の「もっとある」の隣)。
- **Web UI** は日本語で言う。読んでいるのは日本語話者のキュレーターで
  あり、**サーバの英文をそのまま貼るのは翻訳をサボることである**。
- **MCP** は `search_concepts` の**説明文**に一行足して語を教える。
  この面には出力スキーマが無い(`residentbytes_test` が両半分を数えて
  いるのは、いつか declare する日のためである)ので、構造体に
  `jsonschema` タグを書いてもエージェントには届かない。**答えの形に
  ついてエージェントが読む唯一の文は、ツールの説明文である。**
  常駐は 11,629 → 11,788 バイトで、`MCP-BYTES` の 12,000 は動かない。

`list_concepts` はこの旗を持たない。一覧は埋め込むものを持たないから
である。そのために MCP の出力型を二つに割った — 検索の答えに `cursor`
が付いていたのは同じ種類の誤りで(検索はページしない、0050 §2.2)、
片方を直すついでに両方直した。**サーバが書かないフィールドをスキーマが
広告しない**という規則は、REST では検査されている
(`TestOpenAPISchemasMatchGoTypes`)。

## 4. やらないこと

- **どう落ちたかを言うこと。** provider の名前もエラー文も応答には
  乗らない。呼び出し側にできることは「あとでもう一度」だけで、それ以上
  は運用者のログの仕事である。
- **語彙にすること。** 真偽値なので `VOCAB` は 49 のまま動かない。
  退化の種類が二つ目に増えたら、そのとき語にすればよい — 一値の enum を
  先に作っても、読む人が覚える語が一つ増えるだけである。
- **ベクトル検索そのものの失敗を退化にすること。** `SearchVector` が
  落ちたら検索は失敗する(いまのまま)。埋め込みが取れないのは
  provider の外形的な不調で、索引が引けないのはこのデプロイの故障で
  ある。後者を「少し悪い答え」として返すのは、壊れていることを隠す。
- **`stats` に数を出すこと**(0089 §3 はそうした)。退化は一回の
  呼び出しの性質で、集計は薄い結果を受け取った人には届かない。

## 5. 応答スキーマが住む場所は、三つある

0082 §3 は置き場所を二つ挙げていた — `components/schemas`(応答専用か
どうかを到達可能性で判定する)と `components/responses/<名前>`(定義
からして応答専用)。**三つ目がある**: operation の `responses` に
**直接書かれた**スキーマで、検索と一覧の答えがまさにそれである。

`cmd/ochakai/frozenwire_test.go` はその三つ目を知らなかった。だから
0082 §2 が「凍結の外」と決めたはずの追加が、この一箇所に限って
**「セキュリティ上の欠陥を名指せ」と要求していた** — 規則が届かない
ぶんだけ、規則より厳しくなっていたわけである。

三つ目も**定義からして応答専用**である。指紋の行に ` response ` が
入るのは `responses` を通って読まれた節点だけで、その手前は空白を含み
得ない URL パスだから、リクエスト側の行がこの綴りになることはない。
`components/responses/` の腕が到達可能性を要らないのと同じ理屈が、
同じ強さで当てはまる。

**これは凍結を緩めていない。** 緩めたように見えるなら、0082 §2 が
最初から外に置いていたものに検査が追いついただけである — 0101 §5 が
任意のクエリパラメータについて同じことをした。追加が
`api/openapi.frozen.txt` の diff に出ることは変わらない(0082 §4)。
