# Design records, in English

The decision records in this directory are Japanese, immutable, and
authoritative. This file is neither immutable nor authoritative: it is a
reading aid for people who cannot read them, so that the citations to
"design doc NNNN" scattered through the README, the architecture doc and
`api/openapi.yaml` lead somewhere. Where a row here and its record
disagree, **the record is right** — say so in an issue and this file
gets fixed.

One row per record: the record it links to, its status, and the decision
in a sentence or two. The grouping follows [the index](README.md) — start
with the table at the top of it for which record still describes an area
today. Numbers have gaps: proposals that never landed stay in their pull
requests.

A record that has been superseded gets a one-line pointer to whatever
replaced it instead of a summary — that is enough to follow the trail and
is all the maintenance it earns (design record
[0048](0048-decision-records-for-wire-contracts.md) §2.5).
`TestEnglishDesignIndexCoversEveryRecord` holds every record to at least a
row, and `TestEnglishIndexSummarizesOnlyWhatIsCurrent` holds a superseded
one to the pointer and nothing more.

For the shape of the system rather than the history of it, read
[docs/architecture.md](../architecture.md) (Japanese) first.

| [0132 A directory moves whole or not at all](0132-a-directory-moves-whole-or-not-at-all.md) | Accepted; adds the directory form to [0075](0075-the-bundle-is-the-address-space.md) §2's move; reads [0129](0129-a-move-runs-when-its-rewrite-fits.md) at the prefix grain | **`move` takes a prefix**: `from_prefix` / `to_prefix` on `POST /api/v1/move`, `ochakai move --directory` on the CLI. Renaming a directory used to mean looping `move` over `ochakai list --prefix`, and **that loop is not merely inconvenient, it is incomplete by construction** — every listing stands on `deleted_at IS NULL AND id IS NOT NULL`, so a client cannot see the files sitting under the directory but not under a moved concept's own namespace, the rejected concepts (hidden by default), or the soft-deleted ones, which a per-concept `move` cannot shift either since it writes `WHERE deleted_at IS NULL`. All three keep the old addresses, so `old/` never empties and a later import collides with rows nobody can see. **Only the server can see a whole directory.** So everything under the prefix moves, in one transaction: live, rejected and soft-deleted concepts, and every file. The scope test is 0129's sentence one level up — everything the whole rewrite touches must be the caller's to write, and **a move that overflows is refused whole**, because a half-moved directory is worse than a refused one. Links that close inside the directory are rewritten as part of the move and take no `update` revision (the rule `rewriteReferences` already applies to the moved concept's own body, extended to the siblings that moved with it); a concept outside pointing in still gets one, since it did not move and its body changed. **Nothing is inferred**: 0075 §2 lets a concept and a directory share a name, so the server cannot decide which `old` means, and the key says it. Declined: per-concept transactions (the thing this exists to prevent), a count limit (no one has measured one; a timeout rolling the whole thing back is the promise working), `--prefix` as the CLI spelling (it is a filter on `search` and `list` — reusing it would build a second `usage`-shaped collision), and leaving the rejected and deleted behind. REST 13 and CLI 25 do not move; `FLAG` 28 → 29. |
| [0133 An OKF moment is an instant](0133-an-okf-moment-is-an-instant.md) | Accepted; the current record for how ochakai spells OKF's moment-valued keys; amends the mechanism of [0069](0069-the-loop-and-what-measures-it.md) §2.2 and [0074](0074-the-document-and-the-vocabulary-that-asks-it.md) §4.1 without superseding either | **`stale_after`, `sources[].last_modified` and `usage_window` take an RFC 3339 datetime as well as a `YYYY-MM-DD` date, because that is what OKF says they are.** SPEC §5 fixes the type in its opening line — "Every timestamp-valued key in OKF is an ISO 8601 datetime with an explicit UTC offset" — and §5.5 calls `stale_after` "an absolute instant". ochakai took only a date, **and said in code that this was the spec's own rule** (`DateLayout`'s comment, migration 0019's prose); "no timezone to argue about" was a preference written as a citation. The price was that **the spec's own worked example did not survive a read**: Appendix A writes all three keys as instants, midnights collapsed to dates and anything else was dropped with a note nobody reads on an import of hundreds. The stored bytes were never touched, so the export was fine and C1 held — what broke was **every reading surface**: the envelope reported no `stale_after` for a concept that declared one, the expiry feed never listed it, `stats` never counted it, and the web UI showed an empty field. Silently dropping a value is the failure [0130](0130-the-web-ui-and-the-fields-of-a-document.md) §3 refused by name, found in a place it had not looked. Both spellings are now taken and **neither is rewritten into the other**: a date is the UTC midnight that opens it, which makes one comparison of the two, and a datetime with no offset is not absolute and is still refused. A value goes back out in the spelling it arrived in, except that a UTC midnight reads back as the date alone — the two are one value and the date is what an ordinary writer writes. The column moves `date` → `timestamptz` (migration 0046) and the comparison becomes plain `now()`, which **strengthens what 0069 §2.2 was protecting**: both sides are absolute, so no session `TimeZone` can reach the answer — spelling UTC out by hand was what the bare-date column needed, not what the instant needs. The one place a timezone could have come back is the keyset cursor, whose value is normalized to RFC 3339 before the `::timestamptz` cast. `format: date` leaves the frozen contract, through the **OKF-conformance defect** door [0064](0064-rest-stops-at-api-v1.md) §11 left open (the same one 0100 and 0102 used), and it only widens: every value that was valid still is. 0069 and 0074 are amended rather than superseded because neither decision moves — only the mechanism prose — which is what [0128](0128-a-number-is-for-an-area-not-a-rule-inside-it.md) §2.1 says takes no supersession. No counted surface moves. Declined: keeping the `date` column and returning the original only in the envelope (index and envelope would hold different values for one key), normalizing everything to RFC 3339 on the way out (it returns a spelling nobody wrote), and dropping the date form (narrowing was the original error). |
