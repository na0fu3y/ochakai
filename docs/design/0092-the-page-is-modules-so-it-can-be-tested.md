# ochakai 設計ドキュメント 0092: ページはモジュールになる — テストできるように

Status: Accepted(2026-08-10)。[0072](0072-the-web-ui-serves-and-edits-documents.md)
を改訂する — §1 の「自己完結の `index.html` 一枚」を「一枚のページと、
それが読み込む ES モジュール」に直す。**0072 が決めたことは何も変えない**:
ビルドステップなし・フレームワークなし・CDN なし・ページは認証を知らない、
の四つはそのままである。0072 は現行のまま。
Date: 2026-08-10

## 0. この記録が決めたこと

1. **配信するのは一枚ではなく一式になる。** `index.html`、`app.css`、
   そして `js/` の下の ES モジュール。ブラウザが読むのは書いたそのもので、
   束ねるものは無い(§1)。
2. **依存は増やさない。** バンドラも、フレームワークも、npm パッケージも
   入れない。テストランナは Node に付いてくるものを使う(§2)。
3. **静的資産は ETag を持ち、`no-cache` で配る**(§3)。
4. **人が読む面のテストは、実行されるものになる。** 純粋なモジュールは
   `node --test` が値で確かめ、ページ全体はブラウザで一度動かす(§4)。

## 1. 一枚だったものが、なぜ一式になるか

0072 が「一枚」と書いたとき、それはビルドステップを持たないことの言い換え
だった。**そこは変わっていない** — 配信されるのは書かれたテキストそのもので、
`<script type="module">` を一行置く以外に組み立てるものは無い。変わったのは、
2,438 行が一つの名前空間に載っていたことである。

一つの名前空間には、境界が無い。境界が無いと**テストが書けない**: 関数を
一つ取り出して値で確かめるには、それを import できなければならない。
実際、この分割で最初に分かったのは、**四つの関数が宣言されたきり一度も
呼ばれていなかった**ことだった(`splitList`、`sourcePayload`、
`windowPayload`、`sameType`)。誰も気づけなかったのは、気づく手段が
無かったからである。

モジュールの切り方は面ではなく**依存の向き**で決めた。`escape.js` /
`format.js` / `markdown.js` / `vocab.js` / `documents.js` は
**ブラウザを必要としない** — document に触らないので Node が import できる。
これが§4 の前提である。

## 2. 増やさないもの

**バンドラを入れない。** 束ねる理由は本来リクエスト数だが、この UI は
自分のオリジンの、しかも同じプロセスが配る資産を読むだけで、往復は
§3 の検証子で 304 になる。ビルドを一つ入れると、**配信されるものと
書かれたものが別物になる** — それは 0072 が「ビルドステップなし」と
書いたときに避けたことそのものである。

**フレームワークを入れない。** 同じ理由に加えて、供給網が増える。

**npm の依存を入れない。** テストのためであっても、Go のリポジトリに
`package.json` と lockfile と `node_modules` を持ち込むことになる。
必要だったのはテストランナ一つで、それは Node 22 に付いてくる
(`node --test`)。ブラウザを動かす側も同じ姿勢で、Chrome DevTools
Protocol を Node 標準の `WebSocket` で直に叩く一ファイルにした
(§4)。**入れなかったものが無いことが、この節の内容である。**

## 3. 資産は検証子を持つ

一枚が二十個になったので、キャッシュの話が初めて発生する。埋め込まれた
ファイルは更新時刻を持たないため、検証子が無いとブラウザは毎回全部を
取り直す。

そこで **ETag は埋め込み一式のハッシュ**(全ファイルの内容から一つ)、
**`Cache-Control: no-cache`** とした。ファイルごとではなく一式で一つなのは、
これらが常に一緒に出荷されるからで、「半分だけ新しい」状態に到達できても
仕方がない。ビルド識別子を使わないのは、開発ビルドが全部 `dev` になり、
ブラウザが最初に見た版に固定されてしまうからである。

`max-age` にしないのは、**先に進んだ API に対して古いモジュールを
キャッシュから出す**ことになるからで、それはこのページが誰にも見せられない
唯一の壊れ方である。`no-store` にしないのは、それでは 304 が使えない。

## 4. テストは実行されるものになる

これまで Web UI のテストは 13 本あって、**そのすべてが HTML 文字列の
grep** だった(`webui_test.go` が自分でそう書いていた)。関数が何を返すかは
一度も確かめられていない。人の裁定はこの面でしか起きないのに、である。

分割後は三層になる。

| 層 | 何を確かめるか | 走らせ方 |
|---|---|---|
| `node --test` | 純粋なモジュールが**何を返すか** | `scripts/check ui` |
| ブラウザのスモーク | 全ルートが描画され、例外もエラーログも出ない | CI の `webui` ジョブ |
| Go | モジュール単体では言えないこと | `scripts/check core` |

Go に残したのは二種類だけである。**Go と JS にまたがる不変** — 型の語彙が
`internal/domain` と一致すること — と、**ページ全体についての主張** —
「もうどこもこれをしていない」「import した先が全部同梱されている」。
値で言えることは値で言うほうに移し、grep のままだったものは消した。

スモークが「ブラウザが無い」「サーバーが立っていない」で黙って skip する
のは手元だけで、**CI では失敗にする**(`OCHAKAI_SMOKE_REQUIRED`)。何も
試さずに緑になるのは、赤より悪い。

## 5. やらないこと

- **バンドル・フレームワーク・npm 依存**(§2)。
- **CSP・a11y・日本語切り替え・ループの推移**。どれも Web UI に必要な
  ものだが、この記録はそれらを**可能にする**だけで、決めていない。
  インラインスクリプトが無くなったことは CSP の前提であって CSP ではない。
- **モジュール境界を面の一覧にすること。** これは実装の構造であって、
  [surface.md](../surface.md) が数える九つのどれでもない — 利用者が
  覚える語も、叩く経路も、一つも増えていない。
