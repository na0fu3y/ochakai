# ochakai 設計ドキュメント 0109: ディレクトリに閲覧者と編集者を持つ

## 1. 何が起きたか

**見せてはいけない知識と、変えられては困る知識が、同じ一つのバンドルの
中にある利用者が現れた。** どちらか片方なら既存の答えがあった —
書けない人だけなら `read-only` のサービスをもう一本立てて Cloud Run IAM
で招く相手を変えればよく、読めない知識だけならデプロイを分ければよい
(0065 §1、[faq](../faq.md))。

**分けられなかったのは、共有語彙があるからである。** 部門ごとに
データベースを分けると全社の用語集が各バンドルにコピーされ、取り込みは
provenance を読み戻さないので([0075](0075-the-bundle-is-the-address-space.md)
§3.1、[0009](0009-provenance-portability.md))、コピーは `unverified` で
着地して `received:` の主張だけが残る。**分割の代金は、検証済みという
事実そのものだった。** C7(改善ループが測れる)が数えている当のものを、
境界を引くために捨てることになる。

## 2. 決定: 付与だけを持つ。無ければ何も変わらない

`access_rule` は **(prefix, principal) → 読める / 書ける** の付与表で
ある(migration 0041)。

- **prefix** はバンドルパスで、**セグメント境界で照合する** — 0075 §6 の
  `prefix=` フィルタと同じ規則で、`sales` は `sales/orders` に当たり
  `sales-legacy/orders` には当たらない。**この規則をここで発明しては
  いない**ことが重要で、素の前方一致だと隣にディレクトリを一つ作った
  だけで他人のスコープに入る。空 prefix はバンドル全体である。
- **principal** は台帳が既に使っている actor の綴り —
  `human:tanaka@example.co.jp` / `process:app@…`(0065 §2)— と、
  全認証済み呼び出し元を指す `*`。**綴りを共有していることが効く**:
  付与に書いた名前とリビジョンに残る名前が同じ文字列なので、「誰が
  書いたか」と「書いてよかったか」が一つの比較になる。委譲された
  書き込みはエンドユーザーとして解決する(`via` は照合しない)—
  identity を転送した目的がそれである(0065 §3)。
- **拒否規則は持たない。** deny を入れると評価順という文書に見えない
  ものが要り、「なぜ田中はこれを読めないのか」が**行の有無ではなく
  優先順位の問題**になる。付与だけなら、答えは常に表の中の一行である。
- **書ける は 読める を含む。** 読めない concept を書ける呼び出し元は
  盲打ちしており、安全に書くために要る `If-Match` の読み([0030](0030-optimistic-locking.md))が
  まさに拒まれる側になる。

**行が一つも無いデプロイは、この記録の前と一行も違わない。** 到達した
者が全部読み書きする。**最初の一行が、全員に対して同時に境界を入れる。**
段階的に有効化する仕組みは持たない — 「一部の人にだけ効いている境界」は
運用者が把握できない状態で、そこを狙って作る理由が無い。

## 3. 管理者は設定に置く。全体を取る操作は管理者のものである

**`OCHAKAI_ADMINS`** は何でもできる principal を並べる環境変数である。
**ポリシーを編集できる者を、そのポリシーの中で決めることはできない** —
編集できる者は自分に何でも付与できるので、それは規則ではなく回転扉に
なる。デプロイの設定は **ochakai を通しては誰も触れない唯一の場所**で
あり、そこが床になる。

secret は増えていない(C2)。増えたのは名前の一覧であり、
`OCHAKAI_DELEGATING_CALLERS` が既に同じ形で持っているものである。

**バンドル全体を取る操作は、絞らずに管理者へ寄せる** —
`stats`・tar の export・`reembed`・`move`・そしてこのポリシー自身。

- **stats を部分集合で返さない。** ループを測る数([0069](0069-the-loop-and-what-measures-it.md))に
  二つ目の意味を与えることになる。
- **export を黙って欠けた形で返さない。** 「入ったものは出てくる」は
  バンドルの唯一の不変条件であり(0075 §1、C1)、欠けたアーカイブも
  バックアップと呼ばれて、戻したときに残りが消える。
- **move は内向き参照を書き換える**(0075 §5)。スコープを持つ書き手が
  自分の concept を動かすと、書き換えは他人のスコープに及ぶ。書き換えを
  絞れば、飛ばしたリンクが切れる — move が防ぐために在るものである。

**細かく切るのは後からできる。** ここで管理者に寄せたものを、後で
「自分のスコープぶんの stats」に割ることは付与を増やす変更であって、
規則を壊す変更ではない。逆向き(先に割ってから統合する)はできない。

**ポリシーを持つのに管理者が空のデプロイは起動しない。** 綴りの読めない
`OCHAKAI_MODE` を起動エラーにするのと同じ形である(0066 §4): 締め出された
デプロイは、ログではなく知識の側でそれに気づく。

## 4. 読めないものは、無い

**スコープ外の読みは 404 で答える。403 ではない。** 「そのアドレスに
何かあるか」という問いへの答えが境界そのものであり、この機能を求めた
利用者が求めたのは答えが no になることである。403 は「ここに何かある、
あなたには見えない」と言う。

書きだけが 403 である — 読めるが書けない、は相手が既に知っていること
しか言わない。強制点は `service.Service` 一箇所で、read-only が
そこに居るのと同じ理由による(0066 §2): REST も MCP も同じ層を通るので、
後から書き込み面を足した人が middleware を知らなくても covered になる。

絞る先は二種類しかない。**フィルタを絞る**(検索・一覧・browse の三つの
問い合わせ・log)ことと、**id 指定の読み書きを一つのガードに通す**こと
である。フィルタを絞るのであって行を後から落とさないのは、**落とすと
ページングが壊れる**からである — 10 件のページが 3 件で届き、カーソルが
見ていない場所を指す。

### 4.1 塞げないものを、塞げると言わない

**可視な concept の本文が、隠した id を名指していたら、それは読める。**
0075 §3 が「サーバーは受け取った文書を書き換えない」と決めており、保存形
がバイト列そのものであることに C1 の往復と ETag が乗っている。redact は
その全部と引き換えになる。

だからこの記録が約束するのは **一覧・検索・取得・エクスポート・index・
log から出てこない**ことであって、**id が本文中に一度も現れない**ことでは
ない。ファイルの帰属とリンクも本文からの導出なので同じである
(0075 §5)。**言わずに配ると、守られていると思って守られていない状態を
作る** — それは境界が無いことより高くつく。

`log.md` の行数上限は store が先に効くので、狭い付与しか持たない
呼び出し元は上限より少ない行を見ることがある。文書が元から持っている
打ち切りと同じ形であり、塞ぐには store が持たないフィルタでページング
することになる。

## 5. 面ごとの現れ方([0015](0015-surface-consistency.md)・[0067](0067-four-faces-and-what-they-decline.md))

| 面 | 現れ方 |
|---|---|
| REST | `GET|PUT /api/v1/access`。スコープ外の読みは 404、書きは 403(`error.forbidden` — 符号は増えていない) |
| CLI | `ochakai access`(表示、`-f` で置き換え)。**フラグは一つも増えない** — `-f` と `--json` は既にある語である |
| MCP | **載せない。** ツールスキーマはエージェントのコンテキストから支払われ(0067 §4)、境界の編集は運用者の操作である。強制はサービス層なので、MCP から見える範囲は自動的に狭まる |
| Web UI | `#/access` — 表として読み、**同じ文書**を置き換える。タブはポリシーを読めた呼び出し元にだけ出る。読める範囲は自動的に狭まる |

**Web UI の答えが MCP と割れるのは、MCP の理由が二つあったからである。**
一つはツールスキーマの値段で、Web UI にそれは無い — 自分のアドレス空間を
持たない `/api/v1` の client なので([0072](0072-the-web-ui-serves-and-edits-documents.md) §2)、
数える面のどの数も動かない。もう一つは「運用者の操作である」ことだが、
**境界を引くのは誰が何を見るかを決めることであり、それは curation の側で
ある** — 0067 §1 が Web UI に置いた「ループの人間側」がまさにそれで、
`reembed` のような再計算とは別種である。

**文書一枚を丸ごと置き換える**のは、ポリシーが集合として読まれるから
である —「personnel/ を誰が見られるか」は全体を見て答える問いで、運用者は
たった今読んだものを編集する。行ごとの操作にすると面が三つになり、
それでも全体をレビューできる形は別に要る。**git に入る**のは、境界に
ふさわしいレビュー経路がそれだからである(0009)。

`/api/v1/bundle` の下に置かない。**ポリシーは知識ではない** — バンドル
パスに置けば知識と一緒に export され、identity が何も意味しない他の
インスタンスに import され、そのパスを書ける者が編集できてしまう。

### 5.1 誰として編集するかは、UI の配り方が決める

`ochakai ui` は利用者のトークンで代理するので `human:<本人>` だが、
`serve-ui` は呼び出し元を**サービスの SA 一つに畳む**(0072 §1)。その SA が
`OCHAKAI_ADMINS` に居れば、**その URL に届く全員がポリシーを編集できる**。
知識の書き込みと違うのは、soft-delete も履歴も無い(§7)ことで、戻すには
前の文書を持っている人が要る。IAP を前置したデプロイは本人に解決するので
(0065 §5)、この形は「IAP 無しの `serve-ui`」に限られる。

**それでも編集画面は、条件を付けずに両方を書く。** ページは認証を知らず
(0072 §1)、どちらの経路で配られたかを自分では言えない — 言えるようにするには
配信側からページへ経路を教える通り道が要り、それはこの分離そのものを崩す。
**型で防げないものは文章に任せる**(0066 §1)。

## 6. 検査する不変条件([0035](0035-verifiability.md))

- 付与の無いデプロイの挙動が、この記録の前と同一であること。
- スコープ外の read が 404 で、read できて write できない先が 403 で
  あること。
- 検索・一覧・browse・log・backlinks・ファイル一覧が、いずれもスコープ外の
  id を一つも運ばないこと。**backlinks は 0106 が足した面で、フィルタが
  通らないので個別に検査する。**
- browse の**ディレクトリ件数**がスコープ内だけを数えること — 行を
  落とすだけでは、数がスコープ外を数え続ける。
- ポリシーを持ち管理者を持たないデプロイが起動しないこと。
- `read-only` のデプロイでポリシーが書けないこと。**Web UI でも**:
  編集は `write-only` の内側にあり、read-only の面から消える。
- **Web UI のタブが、ポリシーを読めた呼び出し元にだけ出ること。** 403 しか
  返さないタブは、403 しか返さないボタンと同じ嘘である(0040 §2.3)。
- **書き込みメソッドの網羅** — 0066 §6 が read-only に対して置いたのと
  同じ形の反射テストで、スコープ外の id に対してどの書き込みも
  404 か 403 を返す。**書いた初回に二つ捕まえた**: `Delete` の guard
  漏れと、`Plan`(dry run)である。後者はこの記録の設計そのものと
  噛み合う話で、**スコープ外を 404 と綴った結果**、「id が空いているから
  この書き込みは create になる」と読む既存のコードが、拒否を空き番地と
  取り違えていた。dry run は差し止められた書き込みである(0061)以上、
  書き込みが断るところで断らなければならない。

## 7. やらないこと

- **deny 規則**、**継承の打ち消し**、**役割(role)**、**グループの
  レジストリ**。グループは発行者が claim に載せられる(0086)ので、
  要るようになればそこから読む — ochakai がメンバーシップを持つことは
  しない。
- **prefix 以外の粒度**(型ごと、タグごと、concept 一つごと)。住所が
  既にスコープであり、二つ目のスコープ機構を持てば必ずずれる
  (0075 §7)。
- **ポリシーの履歴。** 台帳をもう一つ持つことになり、保持期間の問いが
  ついてくる。読む人が要るのは現在の答えと、それを誰が置いたかである。
- **`prefix=` フィルタを認可として使うこと。** あれは誰でも任意の値を
  渡せる絞り込みのままである(0075 §6)。この記録が足したのは、その
  隣に立つ**呼び出し元が選べない**スコープである。
- **監査ログ・レート制限・実行時の姿勢切り替え**(0066 §7 のまま)。
