## 1. ochakai とは

ochakai は、データエージェント(Claude Code / 各種 Data Agents)に
「メトリクスの定義」だけでなく「その値をどう見るか」までを提供する
**Context Provider** である。メトリクス定義、検証済みのクエリ、解釈
ナレッジ(ベースライン・季節性・注意点)、用語集、テーブルカタログを
一つのナレッジベースに集約し、複数のエージェントに共有する。

**原則として LLM を使用しない。** 返すのは人間が検証したナレッジそのもの
であり、解釈はクライアント側エージェントの仕事である。エージェントは
学びをナレッジとして書き戻すことが推奨される — その双方向ループ
(エージェントが下書きし、人が検証する)がこの製品の中核仮説であり、
ループを何が締めるかと何がそれを測るかは 0069 が持つ。

**SQL を実行しない。** ochakai はウェアハウスへの認証情報を持たない。
攻撃面とサプライチェーンを最小化し、「Context Provider に徹する」を構造で
保証する。この二つの拒否が REST の面でどう現れるかは
[0067](0067-four-faces-and-what-they-decline.md) §5.2 が書いている。

**キュレーテッドなナレッジベースであってカタログではない。** コネクタで
自動収集せず、人間とエージェントが検証しながら書く。規模より信頼密度を
取る。類似サービスに対してこの位置がいま何を意味するかは
[docs/positioning.md](../positioning.md) が持つ生きた答えである。

## 2. 一つのバイナリと、PostgreSQL だけ

**言語は Go**、単一バイナリで MCP と REST を同一ポートに出す。

- 静的単一バイナリなので最小イメージ・再現可能ビルド・監査容易につながる
  (§3 の目標に直結する)。
- MCP の公式 Go SDK が存在する。
- 決定論的な処理は Go の得意領域で、LLM/ML ライブラリを要らないので
  Python の生態系優位が効かない。

**依存は PostgreSQL のみ。** Redis も、別のベクトルデータベースも、検索
クラスタも持たない。pgvector は Cloud SQL でもプレーンな Postgres でも
使えるので、ハイブリッド検索は追加のインフラを一つも要らない
(0080 §1)。実行環境として支えるのは Google Cloud だけだが
([0003](0003-gcp-only.md))、それは secret-zero の帰結であって依存の
軽さとは別の話である — ここで数えているのは**動かすのに何が要るか**で
あり、マルチクラウド対応の主張ではない。

**MCP のツール名は `動詞_対象` 形式である。** 複数の MCP サーバーを併用
するエージェントから見て `search` のような汎用名は他サーバーのツールと
紛らわしく、名前だけで用途が特定できることを優先する。いま何本あって
どこで線を引くかは [0076](0076-two-tools-leave-mcp.md) が持つ。

## 3. 配布とサプライチェーン

- GitHub Actions から GHCR にマルチアーキイメージを出す。`CGO_ENABLED=0`
  + `-trimpath` の静的バイナリを distroless static に載せる。ベース
  イメージ依存ゼロに近い構成である。
- SBOM 生成 + SLSA provenance + cosign keyless 署名。Actions は SHA で
  ピン留めする。**Go はビルド再現性が高く、「誰もが再現可能」に適する** —
  これは §2 の言語選択が支払われる場所である。

## 4. 却下の記憶

**「正しいと認められなかった」は残す。** 却下の記録が残ることで、
エージェントが同じ提案を繰り返すのを防ぐ。書き戻しループを回すなら、
**No を覚えていること**が verified を覚えていることと同じだけ要る。

- **台帳であって status ではない。** OKF の三つの status は concept が
  どれだけ準備できているかを言う値であり、「我々は否と言った」は段階では
  なく判断である。status にすると往復もできない — export が
  `deprecated`(かつて正しかった)に畳むしかなく、それは逆のことを主張する。
- **既定の一覧・検索から外れる。** 明示的に頼んだときだけ返る。
  エージェントが起草前に「同種の提案が過去に却下されていないか」を確かめる
  経路がこれである。
- 却下の理由は自由記述で残す。裁定を出す面と、却下を降ろす操作が削除では
  なく履歴の一行であることは [0068](0068-how-a-face-is-added-and-removed.md)
  §4 が持つ。

権限で縛らないのはこの製品が認可機構を持たないからで、担保は制限ではなく
記録である([0065](0065-identity-and-provenance.md) §1)。

## 6. やらないこと

- **LLM をこの製品の中に置くこと。** 要約もチャットも自動検証もしない。
  LLM を持たないことが、人の検証への信頼の根拠である。
- **SQL を実行すること。** ウェアハウスの資格情報を持たない。
- **コネクタによる自動収集。** 規模ではなく信頼密度を取る。
- **PostgreSQL 以外の実行時依存を足すこと**(§2)。
