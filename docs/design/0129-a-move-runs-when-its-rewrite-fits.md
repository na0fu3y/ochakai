# ochakai 設計ドキュメント 0129: move は、書き換えが収まるとき動く

Status: Accepted(2026-08-24)。[0109](0109-a-directory-has-readers-and-writers.md) §3 の
「バンドル全体を取る操作は管理者のもの」から **`move` を外す** —
[0123](0123-the-numbers-say-what-they-counted.md) §4 が「絞れば飛ばした
リンクが切れる」と書いた理由はそのままで、**絞らずに済む場合がある**こと
が答えである。爆風が呼び出し元の書ける範囲に収まるとき動き、はみ出すなら
**丸ごと**断る。export(根)・`reembed`・ポリシー自身は管理者のままである。
Date: 2026-08-24

## 1. 断っていた理由は正しく、対象が広すぎた

0109 §3 はこう書いた。

> **move は内向き参照を書き換える**(0075 §5)。スコープを持つ書き手が
> 自分の concept を動かすと、書き換えは他人のスコープに及ぶ。書き換えを
> 絞れば、飛ばしたリンクが切れる — move が防ぐために在るものである。

**この文の主語は「動かすと」である。** 及ぶかどうかは concept ごとに違い、
**及ばないほうが普通**である — ディレクトリとは、互いを参照し合うものを
一つの場所に置いたもののことだからで、`teams/growth` のチームが
`teams/growth` の concept を動かすとき、それを指しているのはたいてい
`teams/growth` の中にいる。0123 §4 が `move` を残したときも同じ文を引いて
おり、**及ぶ場合と及ばない場合を分けていなかった**。

分ければ、断る理由は及ぶ場合にだけ残る。

## 2. 決定: 三つとも自分のものであるとき動く

**書き換えが触れるものすべてが、呼び出し元の書ける範囲にあるとき move は
動く。** 三つあり、三つとも同じ権利である:

- **動かす concept** — 通常の書き込みと同じ。読めなければ 404、読めるが
  書けなければ 403(0109 §4)。
- **移動先** — でなければ、書けないディレクトリに concept を置ける。
  ここは**名指して 403** にする: そこにはまだ何も無いので、「書けない」と
  言うことがバンドルの中身について何も答えていない。404 にすると、作ろうと
  している場所について「無い」と言うことになり、読む人を存在しない concept
  探しに送る。
- **その concept を指している live な concept すべて** — move はそれぞれに
  `update` revision を書く。範囲外にあるものへ書けば、**それを読めない
  principal の名前で revision が積まれる**(0065 §2)。台帳が「tanaka が
  teams/personnel/x を更新した」と言い、tanaka はそれを読めない。

**はみ出すなら丸ごと断る。絞らない。** 書き換えを範囲内だけに絞れば、
飛ばしたリンクは**消えた id を指す**ことになる — 0109 §3 の文はここで
そのまま効いている。**部分的な move は、断られた move より悪い。**
管理者の move は範囲を持たず、それが「はみ出す move」の実行手段である。

## 3. 判定は書き込みと同じトランザクションの中で行う

参照元の集合は `rewriteReferences` が `FOR UPDATE` で読む、まさにその
集合である。トランザクションの外で数えれば、**数えた後に範囲外の参照が
一つ生まれる窓**が開く。だから prefix の一覧を store へ渡し、書き換えの
直前・同じトランザクションの中で照合する — ポリシーの置き換えが
自分の partition をトランザクションの中で行うのと同じ形である
([0124](0124-a-directory-can-have-its-own-administrator.md))。

問い合わせは増えない。既に読んでいる行を見るだけである。

## 4. 漏れる一ビットと、それを引き受ける理由

範囲外から参照されているときの 403 は、呼び出し元に**一つだけ**新しい
ことを教える: 自分の concept を、どこかの何かが指している。

**これは 0109 §4 の逸脱であり、そう認めた上で採る。** §4 が守るのは
「そのアドレスに何かあるか」であり、ここで出るものには**アドレスが無く、
件数も無く、中身も無い**。`linked_from` が範囲で絞られている(0106 の
逆引きは `scopeRows` を通る)ので、今日は得られない一ビットではある。

引き受ける理由は、**代わりの案がどれも高いから**である:

- **黙って通し、範囲外の書き換えを行う** — §2 の provenance が壊れる。
  さらに、人気のある concept を動かすだけで**全チームの concept に
  revision を積める**。
- **理由を言わずに断る** — 呼び出し元は自分の何が悪いのか分からず、
  管理者に持って行く手がかりも無い。そして 403 が返る事実そのものが同じ
  一ビットを運ぶので、**隠せていない**。
- **move ごと管理者に残す** — 今日の姿であり、及ばない場合まで巻き込む。

漏れるものの形が「中身の無い一ビット」であることが、0123 §3 が miss を
差し止めたのと**逆の答えになる理由**である: あちらは他チームが何を
探したかという**中身**だった。

## 5. 面

**数はどれも動かない。**

| 面 | 現れ方 |
|---|---|
| REST | `POST /api/v1/move` のまま。操作もパラメータもボディの鍵も増えない。変わったのは誰が呼べるかだけで、403 と 404 は元から宣言されている |
| CLI | `ochakai move` のまま。**`FLAG` は動かない** |
| MCP | **載せない**(0067 §5.1 のまま)。move は curation の操作であって、エージェントのループが一回で要るものではない |
| Web UI | 変わらない。detail の「移動…」もツリーの drag & drop も同じエンドポイントを叩いており、**断られていた呼び出し元が通るようになる** |

## 6. 検査する不変条件([0035](0035-verifiability.md))

- 範囲内で完結する move が通り、範囲内の参照元が**書き換わっている**こと。
- 移動先が範囲外なら 403、動かす concept が読めなければ 404、読めるが
  書けなければ 403 であること。
- 範囲外から参照されている concept の move が 403 で、**concept が動いて
  おらず、範囲内の参照元も書き換わっていない**こと — 部分的な move が
  存在しないことの検査である。
- 同じ move を管理者が行えば通り、範囲外の参照元が書き換わること。
- ポリシーが一行も無いデプロイでは、この記録のどれも効かないこと。

## 7. 採らなかった案

- **書き換えを範囲内に絞って通すこと。** §2 のとおり、飛ばしたリンクが
  切れる。0109 §3 のこの一行は今も正しい。
- **範囲外の参照元への書き込みを、呼び出し元ではない何かの名前で行う
  こと。** ochakai の台帳に「システム」という actor は無く(0065 §2)、
  作れば**誰も名乗らない書き込み**が一つできる。provenance を守るために
  provenance に穴を開けることになる。
- **参照元が何件あるかを 403 に載せること。** §4 の一ビットが数になる。
  管理者に頼むという次の一歩は、件数を知らなくても踏める。
- **読める範囲から参照されているぶんだけ許すこと**(書ける範囲ではなく)。
  読めても書けない concept に revision を積むことになり、0109 §2 の
  「書きは読みを含む」を逆向きに使うことになる。
- **`reembed` も同時に割ること。** 理由が別である — ベース全体への一巡で
  あり、割ること自体は `stats` と同じ形でできるが、**詰まった人がいない**。
  0109 §3 の「後からできる」は、一つずつ、要る順に行う。
