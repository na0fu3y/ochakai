# ochakai 設計ドキュメント 0131: できないことは面が言い、直し方は直せる人にだけ言う

Status: Accepted(2026-08-24)。[0087](0087-a-sandbox-says-it-is-one.md) が
**姿勢**について置いた形を**能力**に当てる — 姿勢の四つ + 一つは動かない。
ファイルが GCS を要ること自体は
[0075](0075-the-bundle-is-the-address-space.md) §1 のままで、ページが
自分では何も判断しないことは
[0130](0130-the-web-ui-and-the-fields-of-a-document.md) §1 のままである。
Superseded にする記録も、改訂する記録も無い
Date: 2026-08-24

## 1. 何が起きたか

`OCHAKAI_GCS_BUCKET` を設定していないデプロイは、markdown の concept だけ
を保存する(0075 §1)。ファイルの読み・書き・一覧はどれも 501 で断られる。

**それでも Web UI は「ファイル」タブに「ファイルを選択…」と「ファイルを
追加」を出し続けていた。** 押すまで分からず、押すと toast にこう出る:

```
ファイルの追加に失敗しました: files are not supported without GCS:
this instance stores markdown concepts only; set OCHAKAI_GCS_BUCKET
```

二つ別の失敗が重なっている。

- **常に 501 になるボタンは嘘である。** [0040](0040-read-only-mode.md) が
  read-only について書いたのと同じ形で、そこでは面が消える(`write-only`
  を隠す)。ファイルについては同じ規則が無かった。
- **その文はキュレーターの文ではない。** 環境変数の名前を渡されても、
  ナレッジを書きに来た人はそれを設定できない。設定できる人は、その日
  その画面を見ていない。

CLI にも同じ穴があった。`ochakai stats` は姿勢(`sandbox`・`insecure_dev`)
を数の前に印字するのに、**この面が無いこと**は言わなかった。

## 2. 決定: `GET /api/v1/stats` が `files` を答える

```json
"files": { "enabled": false, "variable": "OCHAKAI_GCS_BUCKET" }
```

- **`enabled` は全員が読む。** 嘘をつかれるのは全員だからである。
- **`variable` はバンドル全体を持つ呼び出し元にだけ載る。** 既に有効な
  ときも載らない。
- **オブジェクトごと無いのは「このサーバは訊かれたことがない」である。**
  `enabled: false` とは別の答えで、分岐する側はまず存在を見る。姿勢の
  二つ(`sandbox`・`insecure_dev`)は不在が「ふつう」なので真偽値で足りた
  が、ここは不在を「無効」と読むと、古いサーバに向けた画面から動いている
  面が消える。

`stats` に載せる理由は 0087 §4 と同じである。REST は `/api/v1` で凍って
おり([0064](0064-rest-stops-at-api-v1.md))、凍結の外に置かれているのは
**応答専用スキーマへのプロパティ追加**であってヘッダ名ではない
([0082](0082-what-the-freeze-holds-still.md))。そして `stats` は既に
「このデプロイは何であるか」を数と一緒に答える面である。

## 2.1 なぜ二つに割れるのか

**能力は全員のものであり、変数は運用者の一文である。** 宛先の無い指示は
雑音であって、秘密ではない(変数名は README にもマニュアルにも書いて
ある)。共有デプロイで全員に見せれば、直せない人が全員それを読む。

判定は `Service.RequireAdmin` と同じ `Scope.Everything()` を使う —
`OCHAKAI_ADMINS` が名指す者、**そして付与が一つも無いデプロイでは全員**で
ある。そこで全員なのは正しい: そのデプロイでは export も `reembed` も
ポリシーの最初の一行も、その全員が通る([0109](0109-a-directory-has-readers-and-writers.md)
§2 の「付与が無ければ境界も無い」)。

[0122](0122-the-first-rule-is-an-administrators-to-write.md) の狭い判定
(`OCHAKAI_ADMINS` に名前があること)を採らなかったのは、それだと
**`ochakai ui` を自分の手元で動かしている人に誰も何も言わなくなる**から
である。その人は `OCHAKAI_ADMINS` を設定していないことが多く、そして
その人こそ変数を設定できる唯一の人である。0122 が狭い判定を要るのは、
間違えるとポリシーを書いた本人が締め出されるからで、ここで間違えた代償は
**行動できるかもしれない人が一文を読む**ことに留まる。

## 3. 面

- **REST** — `stats` に応答フィールドが一つ。0082 の下の追加である。
- **Web UI** — ファイルを足す面が消える。`<body>` のクラス一つ
  (`no-files`)で CSS が切り替え、タブは「このデプロイはファイルを保存
  しません」に変わる。`variable` が載っていた呼び出し元には、全ページの
  バナー一枚。**ページは誰が管理者かを知らない** — 答えに `variable` が
  あるかどうかだけで、これは read-only バナーとアクセスタブが既に通って
  いる形である(0130 §1)。
- **CLI** — `ochakai stats` に一行増える(`files off …`)。0087 §6 は
  「CLI には出さない」と書いたが、その後 posture の二行は CLI に載った
  — ページを開かない呼び出し元には他に伝わる先が無いからで、完全性の面
  はここである([0067](0067-four-faces-and-what-they-decline.md) §1)。
- **MCP** — 出さない。**MCP はそもそもファイルを差し出さない**(ツール
  6 本に書き込みの面が無い)ので、止める嘘が無い。

## 4. 採らなかった案

- **タブごと隠す。** バケットを外した後のデプロイでは、既にあるファイル
  が見えなくなる。「まだ無い」と「置けない」は別の文であり、後者を言う
  ためにタブは残る。
- **ボタンを `disabled` にする。** 0040 と同じ理由で隠す — 灰色のボタン
  はクリックを誘って、何も説明しない。
- **無効な機能の一般リスト**(`unavailable: [{feature, variable}]`)。
  今日の要素は一つで、増えるとしても一つずつである。**`feature` の綴りは
  覚える語**になり、[docs/surface.md](../surface.md) の VOCAB がそれを
  数える。同じ問いに `embedding.enabled` と `misses.recording` が既に
  欄で答えているので、三つ目も欄にする。次に同じ形が出たら足すのは欄で
  あって語彙ではない。
- **埋め込みを同じ欄に載せる。** 載せない。`embedding.enabled` が既に
  言っており、退化したランキングは自分でそう言う
  ([0114](0114-a-degraded-ranking-says-so.md))。そして
  `OCHAKAI_EMBEDDINGS` は「設定すれば付く」変数ではない — Google Cloud
  の上でサービス識別子が Vertex AI を呼べれば既定で付く
  ([0080](0080-search-and-how-a-deployment-embeds.md) §1)ので、変数名を
  渡すのはむしろ誤答である。
- **`variable` を全員に見せる。** §2.1。
- **新しいヘッダで言う。** 凍結が止めているのはヘッダ名である(0082)。
