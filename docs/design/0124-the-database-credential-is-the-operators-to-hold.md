# ochakai 設計ドキュメント 0124: データベースの資格情報は、運用者が持てる

Status: Accepted(2026-08-23)。[0003](0003-gcp-only.md) §1 の「Cloud Run +
Cloud SQL を前提とし、それ以外の実行環境をサポートしない」を**データベース
について撤回する** — 接続先は PostgreSQL であって Cloud SQL ではなく、
Cloud SQL IAM は secret-zero の**買い方の一つ**である。
[0115](0115-the-second-footing-waits-for-search.md) §4 の順序(埋め込みの
条件が先)を改訂する — **§3 の条件 a/b/c は一字も動かない**。埋め込みは
Vertex AI か無いか([0080](0080-search-and-how-a-deployment-embeds.md))、
ファイルは GCS か無いか([0013](0013-attachment-files-gcs-only.md))のままで、
認証の第二の経路は [0086](0086-a-second-way-to-say-who-is-calling.md) が
既に開いている
Date: 2026-08-23

## 0. この記録が決めたこと

**`OCHAKAI_DB_IAM_AUTH` を立てないデプロイは、自分の資格情報を持つ。**
それは事故ではなく選択で、デプロイはそれを起動時に言う。

決めるのは**宣言のほう**である。実装は既にそうなっている — `store.New` は
IAM 認証を頼まれたときだけメタデータサーバの短命トークンを挟み、それ以外は
接続文字列のとおりに繋ぐ。にもかかわらず [FAQ](../faq.md) は「本番では
動かせない」と書き、[configuration](../configuration.md) は
`OCHAKAI_DATABASE_URL` を「**Cloud SQL の**接続文字列」と書いていた。
**動くものを支えないと書いてあるページは、読む人に事実と決定のどちらを
信じるかを選ばせる。**

## 1. 三つの形と、それぞれが持たないもの

| 形 | 誰が呼んでいるか | 埋め込み | ファイル | secret |
|---|---|---|---|---|
| (i) Cloud Run + Cloud SQL | Cloud Run IAM | 既定で有効 | GCS | **一つも持たない** |
| (ii) Google Cloud 内・Cloud SQL 以外の PostgreSQL | Cloud Run IAM | 既定で有効 | GCS | DB の資格情報 |
| (iii) Google Cloud の外 | OIDC(0086) | 無し(字句のみ) | 無し(501) | DB の資格情報 |

**(ii) は 0115 が見ていなかった形である。** 0115 §1 は「Cloud SQL IAM の
外では、パスワードなり別のクラウドの IAM なりが運用者の仕事に戻る」と書き、
その外を Google Cloud の外と同じものとして扱った。同じではない — AlloyDB
も、GCE の上に自分で立てた PostgreSQL も、**Cloud SQL IAM の外で Google
Cloud の中**である。そこにはメタデータサーバがあるので埋め込みは 0080 §1 の
とおり既定で有効になり、GCS もそのままである。**0115 §2 の反論(C8 が
乗っているのは検索である)は、この形には当たらない。**

## 2. (iii) も今日宣言できる理由 — 0115 の前提が一つ変わった

0115 §2 は「外ではその機能が奥にあるのではなく、**無い**」と書き、§3 は
「支える価値の無い足場を『支える』と宣言するのは、嘘を一つ増やすことで
ある」と結論した。当時それは正しかった。**外の検索が測られていなかった
からである。**

**二日後に測られた。** golden set は lexical のみの設定を毎回走らせており、
その数字が README と [positioning](../positioning.md) に出た — 29 concept・
88 問で recall@10 = 1.00、MRR = 0.91、74 問が 1 位、85 問が 3 位以内。

測る前と後で、同じ文が同じ意味を持たない。

- **「無い」のは埋め込みであって、検索ではない。** 日本語の二文字語を索引で
  引くのは lexical 側の機構(移行 `0036`)で、書き手が与えた別名を索引に
  入れるのも([0105](0105-a-concept-answers-to-its-other-names.md))外で
  同じに動く。C8 が名指している「日本語話者にとって」の部分は、埋め込みの
  無いデプロイでも product が持っている。
- **C8 は「最適な選択肢の一つであること」であって、「Google Cloud 上の
  ochakai と同じであること」ではない。** 前者は測れて、測った結果は
  「立つ」だった。
- **測定が言っていないことも、そのまま引き継ぐ。** 29 concept は上限に近い
  floor であって数千のベースの予測ではなく、fused 側の encoder は lexical と
  語彙を共有する代役なので、**埋め込みが何を足すかはこの数字では測れない**。
  だから 0115 §3 の条件は残る(§4)。

そして 0115 §0 の論法を、この記録は自分に当てる。**区別できない決定は
物差しとして働かない** — 動くのに支えないと書いてある状態は、その論法の
裏側の同じ穴である。

## 3. デプロイは、自分が secret を持っていることを言う

0115 §2 が (1) と (3) を返してよいとした条件は「**何が失われるかを起動時と
文書で言えば**、そこから先は運用者の選択になる」だった。三つのうち二つは
既に言っている — `files disabled (no OCHAKAI_GCS_BUCKET); markdown concepts
only` と `semantic search disabled; using lexical search only`。**言って
いなかったのは資格情報のほうである。**

だから起動時の一行が増える。IAM 認証のデプロイは自分が何も持たないことを
言い、それ以外のデプロイは**自分が持っているものと、持たない買い方の名前**を
言う。[0087](0087-a-sandbox-says-it-is-one.md) と同じ形である — 言わない
デプロイは、運用者に自分が何を抱えているかを気づかせない。

**ヘッダにも API にも出さない。** デプロイが secret を持っているかどうかは
運用者の関心であって呼び出し元の関心ではない。0087 が `stats` に出したのは、
呼び出し元が**書いたものが消える**からだった。ここで消えるものは無い。

## 4. 動かないもの

- **埋め込み**(0080)。Vertex AI か無いかであり、0115 §3 の a/b/c は
  一字も動かない。**残る条件の意味だけが変わる** — 「外を支えるかどうか」を
  測る条件ではなく、「外でも埋め込みが既定になるかどうか」を測る条件になる。
- **ファイル**([0013](0013-attachment-files-gcs-only.md)・
  [0075](0075-the-bundle-is-the-address-space.md))。`OCHAKAI_GCS_BUCKET` が
  無ければ非 markdown の書き込みは 501 で、起動時のログがそう言う。
- **依存は PostgreSQL 一本**([0081](0081-what-ochakai-is-and-what-it-refuses-to-hold.md)
  §2)。二つ目のストレージエンジンは足さない。
- **表面**。環境変数は一つも増えず(ENV は 15 のまま)、REST・MCP・CLI・
  Web UI のどれも動かない。

## 5. 何を払うか

- **C2 の言い方が変わる。** 「secret を一つも置かない」は**性質**で、それを
  無設定で買うのが Cloud Run IAM + Cloud SQL IAM である。(ii) と (iii) では
  **買い方が運用者に移る** — 性質のほうを保ちたいデプロイは Cloud SQL IAM を
  使い、そうでないデプロイは自分の資格情報を持って回す。
  [surface.md](../surface.md) の C2 行はそう読み替える。
- **positioning の負けが一行短くなる。** 「Google Cloud の外で動かす —
  どれか一つでも真なら、FDE 型を買う理由はまだそこにある」から、この一つが
  落ちる。落ちない理由(埋め込みと、それが運ぶ検索の上積み)はそのまま残る。
- **支える先が増える。** 外のデプロイの PostgreSQL は運用者のもので、
  ochakai はそのバージョンも拡張も選べない。README が既に書いている要件
  (PostgreSQL 17、`pg_trgm` を作れること)が、推奨ではなく前提になる。

## 6. 採らなかった案

- **二つの番号に割ること。** (ii) と (iii) の決定は一つ — 資格情報は運用者に
  返せる — で、違うのは**そのデプロイが他に何を持たないか**の一覧だけである。
  割れば同じ一行の決定に Status ヘッダが二本立ち、読む人はどちらが現行かを
  引けなくなる。
- **`OCHAKAI_DATABASE_URL_FILE` のような secret の受け取り口。** 面が一つ
  増え、製品が secret の受け渡しを扱い始める。資格情報の置き場は運用者の
  プラットフォームの仕事であり、返したものをまた持つことになる。
- **二つ目のストレージエンジン。** 0115 §5 のまま。単一ファイルの
  データベースは資格情報を消すが検索には何もせず、store が二重化して以後の
  移行が二度書きになる。
- **外部 API キーの埋め込みプロバイダ。** 0115 §5 と §3 b のまま。鍵は
  secret であり、C2 の性質そのものを壊す。
- **外のデプロイに「退化している」と名乗らせること。**
  [0114](0114-a-degraded-ranking-says-so.md) §2 が既に断っている — 字句が
  毎回答えの全部であるデプロイは退化していない。名乗るのは起動時の一行で
  足りる。
- **「マルチクラウド対応」と言うこと。** 0081 §2 が数えているのは動かすのに
  何が要るかであって、どこで動くかの主張ではない。要るものは PostgreSQL
  一つのままである。
- **外の構成に配布の道具を足すこと。** `deploy/terraform` は Cloud Run +
  Cloud SQL のモジュールのままで、二つ目のモジュールも compose の本番版も
  足さない。**支えるとは、動くことと何を持たないかを言うことであって、
  すべての形に道具を配ることではない**(C4 が要求するのは自分でデプロイ
  できることで、道具の数ではない)。
- **黙って動くままにしておくこと。** 0003 は守られ続けるが、守られている
  ことと、読む人がそれを事実として読めることは別である(0115 §0)。
