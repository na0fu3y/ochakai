# ochakai 設計ドキュメント 0060: 姿勢は一語で言う

Status: Accepted(2026-07-30)。**BREAKING。**
`OCHAKAI_READ_ONLY` / `OCHAKAI_PUBLIC_READ_ONLY` / `OCHAKAI_INSECURE_DEV`
を廃し、`OCHAKAI_MODE`(未設定 / `read-only` / `public` / `dev`)一本に
する。[0040](0040-read-only-mode.md) と [0042](0042-public-read-only.md)
が**決めたことは何も変えない** — 変えるのは、それを書き下す綴りだけで
ある。0042 §2.1 の含意と §2.3 の拒否は、**書けなくなるので消える**。
[0002](0002-authn-authz.md) の「認可を持たない」も、
[0051](0051-instance-metrics-and-search-misses.md) §3.4 の
「公開デプロイは検索ミスを残さない」も不変
Date: 2026-07-30

## 1. 問題: 3 つのブールが、4 つの排他的な姿勢を表していた

デプロイの姿勢を決める変数は 3 つあった。ブールが 3 つなら書き下せる
組み合わせは 8 通りだが、**意味のある姿勢は 4 つしかない**。差は規則で
埋められていた:

| 書けたもの | 実際に起きること |
|---|---|
| `PUBLIC_READ_ONLY=true` + `READ_ONLY=false` | `READ_ONLY` が黙って `true` に補正される(0042 §2.1) |
| `PUBLIC_READ_ONLY=true` + `RECORD_MISSES=true` | `RECORD_MISSES` が黙って `false` に補正される(0051 §3.4) |
| `PUBLIC_READ_ONLY=true` + `INSECURE_DEV=true` | 起動を拒否する(0042 §2.3) |

つまりデプロイする人が読むものは、**変数 3 つと、変数どうしの規則 3 つ**
だった。うち 2 つは「書いたとおりにならない」規則であり、1 つは「書ける
が起動しない」規則である。

規則そのものはどれも正しい。0042 §2.1 が含意を*適用*として書いたのは
「危険な組み合わせが拒否される対象として存在しないように」であり、その
判断はこの文書でも変えない。**変えるのは、そもそも書けるようにして
おいたこと**である。

### 1.1 4 つの姿勢は 2 軸の 4 象限である

実際にあるのは 2 つの軸である — **呼び出し元が特定されるか**と、
**誰かが書けるか**:

| | 書ける | 書けない |
|---|---|---|
| **identity を読む** | 既定(0002) | read-only(0040) |
| **identity を読まない** | dev(ローカル専用) | public(0042) |

4 象限がすべて意味を持ち、しかも**互いに排他である**。3 つのブールは
この 4 値を冗長に符号化していたので、余った符号を規則で潰す必要があった。

`INSECURE_DEV` が姿勢の一つだと見えにくかったのは、名前が姿勢ではなく
機構(「認証を切る」)を言っていたからである。だが**やっていることは
public と同じ軸の上の別の点**であり、0042 §2.3 が両立を拒否したのは、
まさに 2 つが同じ軸を別々に動かそうとしていたからである。

## 2. 決定

### 2.1 `OCHAKAI_MODE` 一本

```
未設定       Cloud Run IAM が到達を決め、到達した者は読み書きできる(0002)
read-only    呼び出し元は特定される。すべての書き込みを拒否する(0040)
public       identity を一切読まない。すべての書き込みを拒否する(0042)
dev          認証を切る。すべて human:anonymous で、書ける。ローカル専用
```

`Config` の `ReadOnly` / `PublicReadOnly` / `InsecureDev` は残る — 面の
側(httpauth・restapi・mcpserver・webui)は今までどおりこれを読む。
違いは**この 3 つを立てられるのが `FromEnv` の switch 一箇所だけ**に
なったことで、0042 §2.1 の含意はその case の中の 2 行になり、§2.3 の
拒否は**書けなくなったので消えた**。

### 2.2 `dev` は姿勢として並べる

`OCHAKAI_INSECURE_DEV` は名前で危険を伝えていた。`OCHAKAI_MODE=dev` は
名前で**用途**を伝える。危険の伝達は名前から
[configuration.md](../configuration.md) の説明とドキュメントに移る —
これは弱くなる方向であり、代わりに得るのは「public と dev を同時に
書けない」ことである。

そのトレードは受け入れる。`INSECURE_DEV` の名前が守っていたのは
*うっかり本番に置くこと*で、それはドキュメントと deploy ガイドが今も
守っている(どちらも `dev` を「ローカル専用」としか書かない)。一方
0042 §2.3 が守っていたのは*姿勢の衝突*で、これは名前では守れず、
実際に起動時チェックを書く羽目になっていた。**型で防げるものを型で
防ぎ、防げないものを文章に任せる**ほうが順序として正しい。

### 2.3 綴りが読めなければ起動しない

`OCHAKAI_MODE=readonly` や `=true` は**起動エラー**にする。既定に落とし
たりしない。理由は [0053](0053-embeddings-by-default.md) §2.4 が
`OCHAKAI_EMBEDDINGS` について書いたものと同じである — read-only の
つもりで書ける姿勢にしてしまったデプロイは、**ログではなく知識のほうで**
それに気づく。

## 3. 選ばなかった案

### 3.1 何もしない

3 つのブールと 3 つの規則は動いている。**動いていることは、読む人が
払っていないことを意味しない。** C4(No FDE)を掲げる以上、デプロイする
人が読む変数と規則の数は「自分で立ち上げられるか」に直接効く。

### 3.2 `OCHAKAI_READ_ONLY` だけ残し、public と dev を畳む

`READ_ONLY` は一番よく使われる姿勢で、名前も分かりやすい。だが残すと
軸が二つに割れる(`READ_ONLY` と `MODE`)ので、**組み合わせの問題が
そのまま戻る** — `MODE=public` + `READ_ONLY=false` をまた補正することに
なる。

### 3.3 `dev` を残し、read-only と public だけ畳む

同じ理由で採らない。§1.1 のとおり `dev` は同じ軸の上の点であり、
0042 §2.3 の拒否は**まさにその二つの間**にあった。畳むなら 4 つ全部で
ある。

### 3.4 姿勢を CLI フラグや設定ファイルにする

Cloud Run の設定面は環境変数であり(0003)、`gcloud run deploy
--update-env-vars` がデプロイガイドの全編で使う道具である。第二の設定
経路を作ると、C4 が良くなるどころか悪くなる。

## 4. サーフェス(0015)

| 面 | 変化 |
|---|---|
| REST | なし。応答も、`Ochakai-Read-Only` ヘッダの意味も不変 |
| CLI | なし |
| MCP | なし。read-only のとき書き込みツールを出さない挙動は 0040 のまま |
| Web UI | なし |

**どの面の数も動かない。** 動くのは `docs/surface.md` の ENV だけで、
16 → 14 に下がる(上限も一緒に下げる)。

`OCHAKAI_MODE` の 3 つの綴りは VOCAB に数えない。VOCAB が数えるのは
**キュレーターが頭に入れておく語**であり、姿勢はデプロイする人の語で
ある — それは既に ENV が数えており、`OCHAKAI_EMBEDDINGS` の `on`/`off`
も同じ扱いになっている。**数え方をここで変えないことが、この畳み込みを
「ENV -2」と正直に言うための条件である。**

## 5. 互換性

**BREAKING。** 3 つの変数は読まれなくなる。設定したまま上げると:

- `OCHAKAI_READ_ONLY=true` だけのデプロイは、**書けるようになる。**
- `OCHAKAI_PUBLIC_READ_ONLY=true` だけのデプロイは、**identity を要求し、
  書けるようになる。**

どちらも安全側ではないので、**上げる前に `OCHAKAI_MODE` を設定する**。
古い変数は無視されるだけで起動は成功するため、これは静かな変化である
— 姿勢を変える変数について静かなのは望ましくないが、代案(古い綴りを
見つけたら起動を拒否する)は**3 つの変数を読むコードを残す**ことになり、
畳み込みの目的そのものと衝突する。

移行は 1 行である:

```sh
gcloud run services update ochakai \
  --update-env-vars=OCHAKAI_MODE=read-only \
  --remove-env-vars=OCHAKAI_READ_ONLY,OCHAKAI_PUBLIC_READ_ONLY,OCHAKAI_INSECURE_DEV
```

0.x に deprecation window は無い([compatibility.md](../compatibility.md))。
`deploy/compose.yaml` と Terraform モジュールの記述はこの PR で追随する。
