## 0. この記録が決めたこと

1. **配信経路は二つのまま**、`ochakai ui`(手元)と `ochakai serve-ui`
   (常設)。`ochakai serve` は UI を配信しない(§1)。
2. **クロスサイトの書き込みは両方の経路が断る**。`serve` には置かない
   (§1.1・§1.3)。
3. **配信するのは一枚ではなく一式** — ビルドなし・フレームワークなし・
   CDN なし・npm 依存なしのまま(§2)。
4. **保存されるのは文書である。**(§3)
5. **frontmatter には欄がある。** 埋めるのも書き戻すのもサーバ側の
   `POST /api/v1/frontmatter` 一本で、ブラウザは YAML を読みも書きも
   しない(§3.3)。**これが 0072 から動く唯一の決定である。**

## 1. 一枚のページ、二つの配信経路

**ページは認証を知らない。** 自オリジンの相対パス(`/api/v1`)を叩く
だけで、資格情報の付与は手前に立つプロキシの仕事である。この分離がある
から、同じ一式を二通りに配れる。

| | `ochakai ui`(クライアント) | `ochakai serve-ui`(サーバー) |
|---|---|---|
| 想定用途 | 個人利用。デプロイ不要 | チーム共有の常設 URL(Cloud Run) |
| トークンの出所 | 利用者の ADC / gcloud | サービスのメタデータサーバー |
| ヘッダ | `Authorization` | `X-Serverless-Authorization` |
| 記録される identity | `human:<本人>` | `process:<サービスの SA>`、IAP があれば本人(0065 §5) |
| 待受 | 127.0.0.1 のみ | `:$PORT`(保護は Cloud Run IAM / IAP) |

両者は同一バイナリ・同一コンテナイメージに同居する。デプロイは `serve` と
同じイメージに `--args=serve-ui` を渡すだけで、**UI とサーバーのバージョンは
常に一致する**。

サーバー同梱型(単一バイナリのサーバーが UI も配信する形)は採らない。
Cloud Run IAM の背後ではブラウザが ID トークンを付けられず、認証モデルと
衝突する。採ったのは「CLI が資格情報を貸してローカルに UI を立てる」形で、
`kubectl proxy` + Dashboard や `go tool pprof -http` と同型である。

### 1.1 プロキシが守る四つ

`ochakai ui` は**利用者のトークンで書けるプロキシ**である。だから:

- **127.0.0.1 固定バインド**(可変なのはポートだけ)。LAN 共有の要件は
  `serve-ui` が担う。
- **Host ヘッダ検証** — loopback 名以外は 403。攻撃ページが自ドメインを
  127.0.0.1 に解決させて same-origin でプロキシを叩く DNS リバインディング
  への防御であり、**クロスオリジン検査が原理的に見えないのがこの攻撃**
  なので畳めない。
- **ブラウザ由来の `Authorization` は転送前に必ず破棄**し、CLI が解決した
  トークンで置き換える(委譲ヘッダも同じ — 0065 §5)。

四つめは**両方の経路に掛かる**。安全でないメソッド(GET・HEAD・OPTIONS
以外)の要求は、ブラウザが別のサイトから来たと言っているなら、プロキシが
署名して転送する前に 403 になる。`serve-ui` のほうが条件が揃っている側で
ある — IAP を前置したデプロイではブラウザが資格情報を持っており、他人の
サイトのページが書かせられるなら**その人が頼んでいない書き込みがその人の
名前で台帳に載る**。`readJSON` は `Content-Type` を見ないので
`enctype="text/plain"` のフォームで JSON を本文にでき、フォーム送信は
simple request なので preflight は起きない。CORS ヘッダを一つも返して
いないことは、読みを防ぐだけで書きを防がない。

機構は Go 標準の `net/http.CrossOriginProtection` である。`Sec-Fetch-Site`
を読み、無ければ `Origin` のホストを `Host` と突き合わせる。**買っている
のは、この検査が何を*しない*かである**: どちらのヘッダも無い要求は通すので
CLI・エージェント・curl は一行も変わらず、状態を持たないので渡す secret も
無く、表面はどの次元も動かない。読みは断らない — GET を断てば `/health` と
ページ自身が道連れになる。

`/mcp` もプロキシするので、proxy プロセス無しで MCP クライアントを本人の
identity で繋げられる副効果がある。

### 1.2 コマンドを二つに分けるのは、危険な組み合わせを書けなくするため

一つのコマンドのフラグ(`ui --public` の類)にはしない。二つのモードは
バインド先・identity の出所・ヘッダが反転しており、共有されるのは静的
ページとプロキシの骨組みだけである。分けると:

- `ui` は決して loopback 以外にバインドしない — **本人のトークンで書ける
  プロキシを LAN に晒す事故が、構造的に起きない。**
- `serve-ui` は決して個人の資格情報を使わない。

### 1.3 `ochakai serve` には置かない

ブラウザが資格情報を持って ochakai に届く経路は、二つの UI コマンドだけで
ある。Cloud Run IAM の後ろではブラウザは Bearer トークンを持てず、自分で
検証するデプロイ([0086](0086-a-second-way-to-say-who-is-calling.md)・
[0121](0121-each-path-reads-its-own-header.md))が読む `Authorization` は
ブラウザが勝手に付けるものではなく、`dev` は手元、`public` は read-only、
`sandbox` は匿名である。**発火しうる構成が今日は一つも無い。** 変わる
条件は書ける — `serve` の前にブラウザのセッションを持つ何かを ochakai
自身が案内したときである。

## 2. UI のスコープと、ページの形

UI は `/api/v1` の薄いクライアントに留める — **UI にできることはすべて
エージェントにもできる。** サーバー側状態や LLM を要する機能は UI ではなく
エージェント側に属する。API の全機能を UI が追随する義務はなく、
キュレーションに要るかどうかで都度判断する
([0067](0067-four-faces-and-what-they-decline.md) §5.4 が載せないものを
数えている)。

配信するのは `index.html`、`app.css`、そして `js/` の下の ES モジュール
一式である。**ブラウザが読むのは書いたそのもので、束ねるものは無い。**
「一枚」だったのはビルドステップを持たないことの言い換えで、そこは
変わっていない。変わったのは 2,438 行が一つの名前空間に載っていたことで、
境界が無いとテストが書けない — 分割で最初に分かったのは、**四つの関数が
宣言されたきり一度も呼ばれていなかった**ことだった。切り方は面ではなく
**依存の向き**で決めてある: ブラウザを必要としないモジュールは Node が
import できる(§4 の前提)。

**増やさないものが、この節の内容である。** バンドラを入れない — 束ねる
理由は本来リクエスト数だが、この UI は同じプロセスが配る資産を読むだけで、
往復は検証子で 304 になる。ビルドを一つ入れると**配信されるものと書かれた
ものが別物になる**。フレームワークを入れない(供給網が増える)。npm の
依存を入れない — テストのためであっても Go のリポジトリに `package.json` と
lockfile と `node_modules` を持ち込むことになり、必要だったテストランナは
Node に付いてくる。

静的資産の **ETag は埋め込み一式のハッシュ**、`Cache-Control: no-cache`。
一式で一つなのは常に一緒に出荷されるからで、`max-age` にしないのは
**先に進んだ API に対して古いモジュールをキャッシュから出す**ことになる
から — このページが誰にも見せられない唯一の壊れ方である。

## 3. 編集は文書であり、frontmatter には欄がある

詳細画面は投影で描き、**編集画面は文書をそのまま渡す。保存されるのは
文書である。** ここは動かない。動くのは、その文書の frontmatter を欄で
書けるようになることである。

### 3.1 0072 が断ったのは書き出しではなく読み取りだった

0072 §3 は `sources` と `parameters` の行エディタを撤去し、理由を
こう書いた。書き出しだけならフォームでも解ける(全値を JSON で書けば、
JSON は YAML の部分集合なのでクォート規則にも日付の誤読にもぶつからない)。
**解けないのは読み取り側である** — フォームに値を入れるにはサーバが正準化
した本物の YAML をパースする必要があり、ブラウザにその能力は無い。

残る二つの道を、0072 はどちらも断った。**ブラウザに YAML の部分集合パーサを
書く**のは、「限定的な入力しか来ないはずのパーサ」が想定外の値で壊れる典型で
あり、しかも壊れ方が**フォームが黙って値を落とす**形になる。**読み取り応答に
封筒の構造を併走させる**のは、こちらのほうが重い —
**キュレーション面が、形式と違う形を教えてしまう。**

そして 0072 §3.1 は、失うものを「値引きではなく支払い」と書いたうえで、
**戻す条件と、そのとき何を作るかまで書いた**: 「行エディタの需要が実運用で
戻ってきたら、読み取りの既定形を二重にするのではなく、**サーバ側に
「文書 → 構造」の面を足す**」。

### 3.2 条件は満たされた

`sources` に一行足す、`parameters` の `required` にチェックを入れる —
その操作を、書き手は YAML のインデントを自分で数えて行っていた。0072 §3.1
自身が「行エディタは実際に便利だった」「YAML のインデントを人が数えるより
速くて安全である」と書いている当のものである。**この記録は、0072 が自分で
書いた条項を実行するだけで、判断を覆さない。**

### 3.3 決定: 面は一本の関数である

`POST /api/v1/frontmatter` は**文書を受け取り、文書を返す**。読みは
frontmatter を JSON として — キーを文書自身の順で、値を YAML が言ったまま —
併せて返し、書きは名指したキーだけを文書に書き戻す。**保存はしない**:
id も ETag も前提条件も無く、記録するものも無い。concept は文書のままで、
これはその上の関数である。

三つが 0072 の理由づけを満たす。

- **読み取りの既定形は二重にならない。** `GET /api/v1/bundle/{path}` の
  答えは一バイトも変わらない。構造が要る呼び出し元だけが、要ると言って
  呼ぶ。
- **ブラウザは YAML を読まない。** 断られたパーサは書かれない。
- **ブラウザは YAML を書きもしない。** 0072 は書き出しを「解ける」と
  書いたが、JSON の一行で解いた `sources:` は**人が diff で読む文書では
  ない**。書く側も形式を持つプロセスに任せる。

### 3.4 欄が、書いていない行を壊さないために

書き戻しは**名指したキーのブロックの差し替え**であり、文書の作り直しでは
ない。どの行がそのキーのものかは**パースが答える** — 行頭の `key:` を
探す走査ではない。YAML にはキーの綴り方が複数あり、走査が取り逃した綴りは
生き残って追記と衝突する(`StripServerKeys` が同じ理由で同じ読み方をする)。

だから**名指さなかったものは一バイトも動かない**: キーの順、コメント、
空行、値のクォート、そして本文。**欄の無いキーも動かない** — producer の
拡張キー(SPEC §4.1)はその人が置いた場所に残り、**画面はそれを名指して
そう言う**。「フォームは文書である」が願望でなく事実であることを、書き手が
確かめられるのはそこだけだからである。

追記されるキーは frontmatter の末尾に付く。この instance が足すキーが
すべてそこへ行くのと同じ規則で(`WithServerKeys`)、キーの並び順について
ochakai の意見を新しく発明しないためである。

### 3.5 何が欄にならないか

- **`generated` と `verified`。** provenance は観測記録であり
  ([0009](0009-provenance-portability.md))、書き込み経路はこれらを無視
  する。欄にすることは、押しても何も起きないボタンを置くことである。
  この面は `set` にも `unset` にも、これらのキーを 400 で断る。
- **`okf_version`。** バンドル根の生成物である。
- **producer の拡張キー。** 欄は持たない(§3.4)。ochakai が知らないキーに
  欄を発明することは、知らないと言っているものの形を決めることである。

一方、**型に応じて欄を出し分けることはしない**。`runtime` も `parameters`
も常に出ている。**型ごとのスキーマを ochakai は持たない** — 書き込み経路が
型を見て検証する唯一のキーは Attested Computation の `runtime` である
([0071](0071-the-recommended-type-vocabulary.md) §5)。UI がそれ以上の規則を
持つと**面が形式に無い規則を教える**ことになり、それは §3.1 が断ったのと
同じ失敗である。

## 4. テストは実行されるものになる

| 層 | 何を確かめるか | 走らせ方 |
|---|---|---|
| `node --test` | 純粋なモジュールが**何を返すか** | `scripts/check ui` |
| ブラウザのスモーク | 全ルートが描画され、例外もエラーログも出ない | CI の `webui` ジョブ |
| Go | モジュール単体では言えないこと | `scripts/check core` |

Go に残すのは二種類だけである。**Go と JS にまたがる不変**(型の語彙が
`internal/domain` と一致すること)と、**ページ全体についての主張**
(「もうどこもこれをしていない」「import した先が全部同梱されている」)。
値で言えることは値で言うほうに置く。スモークが「ブラウザが無い」で黙って
skip するのは手元だけで、**CI では失敗にする** — 何も試さずに緑になるのは、
赤より悪い。

## 5. やらないこと

- **UI のための新しい認証機構。** ブラウザの per-user identity は IAP の
  領域である(0065 §5)。
- **`ochakai serve` から UI を配信すること**(§1)、**`serve` に
  クロスサイト検査を置くこと**(§1.3)。
- **バンドラ・フレームワーク・npm 依存**(§2)。
- **文書のシンタックスハイライト。** 依存を増やす。textarea と等幅フォントで
  足りる。
- **エクスポート形の編集。** 編集画面が渡すのは正準形(サーバ所有キーなし)
  である(§3.5)。
- **`POST /api/v1/frontmatter` を CLI と MCP に載せること。** §6。
- **型ごとの契約セクションの出し分け**(§3.5)。

## 6. サーフェス(0067 §1)

- **REST**: `POST /api/v1/frontmatter` 一本。12 → 13 で、
  [surface.md](../surface.md) の天井を上げる決定であり、そう言って上げて
  いる。凍結の外である — コアは bundle の往復と search
  ([0107](0107-the-freeze-holds-the-okf-core.md))。
- **Web UI**: 編集画面が二つのペインになる。人の curation に要るかどうかが
  Web UI の基準で、これは要る側だった。
- **CLI**: **載せない。** 完全性の面の既定は yes だが、これは知識ではなく
  **フォームを描くための道具**である。端末の書き手は文書をエディタで開いて
  おり、`ochakai get | (何か) | ochakai put` の中間に置きたい形は
  ochakai の意見ではなく `yq` の仕事である。
- **MCP**: **載せない。** 既定が no であることに加えて、エージェントは
  文書を直接書ける — 欄が要るのは、YAML のインデントを数える人のほうだけで
  ある。

**畳んだもの。** ページの `withType` — 型を変えたときに必要キーを運ぶ行編集
は、この面が行うようになったので消える。設計記録も三本が一本になる
(0072・0092・0126 → 本書)。

## 7. 互換性

**破壊的変更は無い。** 既存の面はどれも動かない。`GET /api/v1/bundle/{path}`
の答えも、`PUT` が取るものも、保存される文書も同じである。新しい操作を
呼ばないクライアントは、何も変わったことに気づかない。
