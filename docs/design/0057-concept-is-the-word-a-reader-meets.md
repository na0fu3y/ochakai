# ochakai 設計ドキュメント 0057: concept は読む人が出会う語でもある

Status: Accepted(2026-07-29)。**BREAKING(文言のみ)。**
[0054](0054-concept-is-the-okf-word.md) を Superseded にする — 0054 が
決めた MCP ツール名 5 本の改名(§0)を引き継ぎ、**利用者が読む英語の
散文は `entry` のままだった**ものも `concept` にする: README・`docs/`・
`examples/`・`deploy/` の英語、CLI のヘルプと標準出力、Web UI のラベルと
ツールチップ、MCP のツール説明と `jsonschema` の説明文、OpenAPI の
`description`、サーバのエラー文。0054 §3.4 の「`domain.Knowledge` は
改名しない」は維持し、**JSON のフィールド名 `entries` も動かさない**
(§3.2)。ワイヤの形・引数・応答・能力・保存形はどれも 1 バイトも変わらない
[0064](0064-rest-stops-at-api-v1.md) §7 が §3.2 の JSON フィールド名の
除外を撤回し、`entries` を `concepts` に改名した(issue #411)。
Date: 2026-07-29

## 0. 0054 が決めたこと: MCP ツール名 5 本の改名

同じものに二つの名前が残っていた — OKF SPEC §2 はバンドル中の知識の
単位を **concept** と定義し、ochakai 自身の文書やコードコメントも
既に「概念(concept)」と書いていたが、MCP のツール名だけが
`knowledge` のままだった([0046](0046-bundle-address-space.md) §3.5 の
畳み込みが終わった時点で、ワイヤ上に残る `knowledge` はこの 5 本だけに
なっていた)。0023・0038 と同じ「綴りが割れたら OKF を採る」の三度目
として、次のように改名する。

| 旧 | 新 |
|---|---|
| `search_knowledge` | `search_concepts` |
| `get_knowledge` | `get_concept` |
| `put_knowledge` | `put_concept` |
| `delete_knowledge` | `delete_concept` |
| `get_knowledge_usage` | `get_concept_usage` |

**検索だけ複数形**である — `concept` は可算で、検索は複数を返し残りは
一つを扱う。リソーステンプレートの表示名(`Name` / `Title`)も同じ語に
揃える。**変えないもの**: `get_context` / `report_outcome` / 
`get_attachment`(いずれも concept を名指していない)、ツールの本数 8、
引数・応答・スキーマ、`domain.Knowledge`(Go の型名。内部パッケージの
名前を利用者が覚える必要はない、§3.4)。改名であって能力の変更では
ないため、ツール名を設定に書いているクライアントだけが影響を受ける。

## 1. 問題: 翻訳表は消えず、置き場所が変わった

0054 の根拠は一行で言える — 「**二つの語彙は利用者に翻訳表を持たせる**」。
そして §1 は「ワイヤ上に残る `knowledge` は MCP のツール名 5 本だけ」と
数え、§2 は「**ochakai 自身が既にその語で書いている**」と書いた。

後者が指していたのは、0046 §2 の日本語の表と `internal/restapi` の
コメントである。**利用者が読む英語ではなかった。** 改名が 0.16.0 で
出た直後に数えると、こうだった。

| どこ | `entry` / `entries` | `concept` / `concepts` |
|---|---|---|
| README + `docs/`(英語) | **287** | 6 |
| `internal/mcpserver` のツール説明 | 78 | 2 |
| CLI のヘルプと出力 | 143 | 3 |
| Web UI のラベル | 193 | 1 |
| `api/openapi.yaml` の `description` | 201 | 42 |

> `get_concept` という名前のツールが、自分の説明で
> **"Fetch one entry as an OKF document"** と言っていた。

`docs/knowledge.md` は "**An entry** is an OKF v0.2 document" で始まり、
Web UI のボタンは "**New entry**" だった。翻訳表は消えていない。
**ツール名からドキュメントへ移っただけ**であり、しかも移った先のほうが、
初めて来た人が最初に読む場所である。

## 2. 世界観: 名前を変えることと、語を変えることは別の仕事

0054 は正しいことをした。足りなかったのは範囲ではなく**数え方**で、
「ワイヤ上の綴り」を数えたことである。ワイヤは利用者が出会う場所の
一つでしかない。

[docs/surface.md](../surface.md) が VOCAB を数え始めたのは同じ発見に
よる — 機構を数えていた間、圧力は語へ逃げていた。本ドキュメントは
その系である: **語を一つに決めたなら、その語を使う場所も一つに揃う。**

揃えないものもある。**識別子は語彙ではない。** 0054 §3.4 が
`domain.Knowledge` を射程外に置いた理由がそのまま効く — 利用者は内部
パッケージを覚えなくてよい。

## 3. 決定

### 3.1 読む語はすべて `concept`

- **文書**: `README.md`、`docs/`(設計ドキュメントを除く英語)、
  `examples/`、`deploy/` の英語散文。
- **CLI**: `ochakai help`、各コマンドの `-h`、標準出力の文言、
  シェル補完の説明文。`docs/cli.md` はそこから生成される。
- **Web UI**: ボタン、ラベル、ツールチップ、空状態の文。
- **MCP**: ツールの `Description` と引数の `jsonschema` 説明文。
  ツール名は 0054 が既に改めている。
- **REST**: `api/openapi.yaml` の `description`(**キー名は除く**)、
  およびサーバが返すエラー文。

### 3.2 動かさないもの — 境界は「読む語」と「識別子」

- **JSON のフィールド名 `entries`。** `GET /api/v1/context` などの応答
  で**配列**を名指すキーであり、単位の名前ではない。これは 0054 が
  最初から引いていた線と同じである — あの決定は「ツール**名**を変える
  が引数と応答は変えない」だった。動かすとすれば、それ自身の理由で、
  破壊的変更として動かす。
- **Go の識別子・型名**(0054 §3.4)、**データベースの列名**。
- **日本語の設計ドキュメント**(不変)と **CHANGELOG の過去の記述**。
  リリース済みの記録は歴史であって、書き換える対象ではない。
- **英語として別の意味の "entry"。** `catalog entry`(カタログの項目)、
  `sources` の要素、changelog の 1 項目、Web UI の CSS クラス
  `.tree-entry`。**同じ綴りでも同じものではない。**

### 3.3 `entry` が消えない場所があってよい理由

§3.2 の線を引くと、`ochakai stats` の出力に `entries` という行が残る
(応答の `entries` キーをそのまま印字している)。これは二重語彙では
ない — その行は**キーの名前**を出しているのであって、単位を呼んでいる
のではない。同じ理由で、`--json` の出力と表形式の出力は同じ語を使う。

### 3.4 各サーフェス(0015)

四面すべてに及ぶが、**どの面でも変わるのは文言だけ**である。REST の
契約、MCP のツール本数と引数、CLI のコマンド名とフラグ、Web UI の
できることは、どれも動かない。

## 4. 却下した代替案

- **何もしない。** 0054 の目的が達成されていない。ツール名だけが
  OKF の語で、説明文が別の語という状態は、0054 §1 が問題として挙げた
  ものそのものである。
- **逆に揃える — 文書に合わせてツール名を `entry` に戻す。**
  0023・0038・0054 が三度下した「綴りが割れたら OKF を採る」を覆す
  ことになる。OKF SPEC §2 が `concept` と定義している以上、バンドルを
  読む人は必ずその語に出会う。
- **JSON のキー `entries` も `concepts` に変える。** 能力は変わらない
  のに REST・MCP・CLI・Web UI・OpenAPI・apiclient を同時に動かす破壊的
  変更になる。買えるのは「応答の配列の名前が単位の名前と同じ」だけで、
  §3.2 のとおりそれは別の問いである。やるなら単独の決定として。
- **「定義している場所」だけ直す**(`docs/knowledge.md` と OpenAPI の
  スキーマ説明)。二つの語が並ぶ状態が部分的に残る。中途半端な統一は、
  読む人にとっては統一されていないのと同じである。
- **Go の識別子も揃える。** 0054 §3.4 のとおり、外形を 1 バイトも
  変えない機械的差分である。射程外。

## 5. 壊れるもの

- **何も壊れない** — 呼べるもの、送る形、返る形、保存されるものはどれも
  変わらない。
- 影響を受けるのは、**ヘルプの文言やエラー文の部分一致に依存している
  スクリプト**だけである。0.x では文言は契約ではない
  ([docs/compatibility.md](../compatibility.md))。
