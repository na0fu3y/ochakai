# ochakai 設計ドキュメント 0119: 任された運用の単位は、デプロイかディレクトリである

Status: Accepted(2026-08-23)。決定を一つも動かさない — [0003](0003-gcp-only.md)・
[0065](0065-identity-and-provenance.md) §1・[0109](0109-a-directory-has-readers-and-writers.md)
が別々に置いた「境界はデプロイかディレクトリで引く」を、**複数の組織の
運用を一人が引き受ける形**について言い直し、その形を閉じる変更を名指す。
[0115](0115-the-second-footing-waits-for-search.md) と同じく、足すのは
決定ではなく**物差し**である
Date: 2026-08-23

## 0. この記録が決めたこと

ochakai を使う組織が数十になり、その運用を一人(一つの組織)が任される
日が来ても、ochakai が**別の製品にならずに済む形**を、その日より前に
書いておく。

[faq](../faq.md) は「ホスティング版は無い」と言い、[SUPPORT](../../SUPPORT.md)
は「商用サポートは存在しない」と言う。**どちらも今日も真で、この記録は
どちらも変えない** — 提供するかどうかは製品の決定ではない。変えるのは、
その形を閉じてしまう PR を**測れる**ようになることである。0115 §0 が
書いたとおり、区別できない決定は物差しとして働かない: 「テナント列を
一つ足す」提案は、断る記録が無ければ内部変更に見える。

## 1. 形: 単位はデプロイかディレクトリ、principal は一組

**境界の単位は二つあり、どちらも既にある。** 隔離が要る組織は
**デプロイ** — 一つの Cloud Run サービスと一つのデータベース(別 project
でも、同じ Cloud SQL インスタンスの中の別 database でもよい。
[deploy ガイド](../../deploy/cloudrun/README.md) §2c、
[faq](../faq.md#誰が読み書きできるか))。到達は Cloud Run IAM が、開ける
データベースは Cloud SQL IAM の GRANT が分ける。一つの failure domain —
リージョン・埋め込みモデル・復旧の単位が他の組織と同じであること — を
受け入れる組織は、同じデプロイの中の**ディレクトリ**で、0109 の付与が
その境界である。[deploy/terraform](../../deploy/terraform) の module を
組織ごとに apply するのが前者、付与の一行を置くのが後者で、**どちらも
製品に足すものは無い。**

**二つは同じ道の上にある。** ディレクトリは住所であり
([0075](0075-the-bundle-is-the-address-space.md))、その下を export した
ものは普通の OKF バンドルである。ディレクトリで始めた組織が隔離を要する
日には、export して自分のデプロイに import すれば、変換なしに前者へ移る。

**運用者は IAM の principal の集合であって、鍵の持ち主ではない。**
Cloud Run を更新できる役割、`maintenance_users` の IAM データベース
ログイン、`OCHAKAI_ADMINS` の一行 — 引き受けるときに増えるのは binding
で、手を引くときに減るのも binding である。預かる secret は一つも無く
(C2)、受け渡しに鍵の移動が起きない。

**知識は組織の project に置くのが既定の形である。** C1 も課金も
データ所在地も、そのままその組織のものになる。運用者の project に置く形も
同じ module で綴れるが、そのとき [0080](0080-search-and-how-a-deployment-embeds.md)
§1.2 のリージョン — 本文がどこの Vertex AI に送られるか — は運用者の
選択になるので、そう言って選ぶ。ディレクトリの形では、それが常に
運用者の選択である。

**運用者の行為は運用者として台帳に残る**(0065 §2)。バックアップからの
import は全 concept に運用者の名前を乗せ、検証は `unverified` で着地する
([運用ガイド](../guides/operating.md#backup-and-restore)) — 運用の復旧は
Cloud SQL のバックアップで、export は出口のためにある。

**アップグレードは `image_tag` を変えて apply することである。**
マイグレーションは起動時に走り、追加的で、advisory lock で直列化される
ので、N 個を順に上げる間に古いバイナリが新しいスキーマの上で動き続ける。
webui を API より先に上げる順序は一つのままで、N 倍になる。

## 2. 何がこの形を開けているか

四つあり、どれも既に別の記録が決めている。**この四つを壊す変更が、この
形を閉じる変更である。**

1. **境界は住所で引く**(0065 §1、0109、0075 §7)。デプロイが分かれて
   いればデータベースが isolation で、分かれていなければディレクトリが
   isolation である。どちらも**既にある一つのスコープ**の上に立つ。
2. **secret-zero**(0003、0065)。運用者が預かるものが無いから、引き受けも
   手放しも IAM の binding で済む。
3. **バンドルは丸ごと出て、丸ごと戻る**(0075、C1)。組織が運用者から
   離れる道が、今日あるコマンドで通る。消すのは [0031](0031-purge.md) と
   [0099](0099-a-purge-reaches-the-bytes.md) である。
4. **ochakai は誰にも問い合わせない**([faq](../faq.md#維持者が止まったらどうなるか))。
   運用者が見るのは、その組織の project に出るログと `stats`
   ([0069](0069-the-loop-and-what-measures-it.md))であって、製品が
   運用者へ報告する経路ではない。

## 3. 断るもの

- **テナント列。** テーブルに tenant 列を足し、住所の横に二つ目のスコープ
  を置くこと。0109 §7 と 0075 §7 が既に言っている — 「住所が既にスコープ
  であり、二つ目のスコープ機構を持てば必ずずれる」。§2.1 を壊し、以後の
  すべてのクエリと移行が二つのフィルタを持ち、バンドルに tenant が無い
  以上 export と import が変換を要る。**買えるものは無い**: 隔離の強さは
  ディレクトリと同じ一箇所の強制(0109 §4)で変わらず、テナントごとに
  違う設定 — 姿勢・埋め込み・管理者・所在地 — はデプロイが無料で持って
  いる。隔離が要るならデプロイ、安さが要るならディレクトリで、列の
  居場所が無い。
- **運用者向けの telemetry と管理プレーン。** 艦隊の版や状態を製品が
  運用者に報告する経路。§2.4 を壊す。版は Cloud Run のリビジョンが、
  状態は `stats` と Cloud Logging が、組織の project の中で答える。
- **艦隊の道具と登録の面をこのリポジトリに置くこと。** N 個の Terraform
  root、版の棚卸し、ロールアウトの順序、そして「登録」— ochakai は
  ユーザ DB を持たず(0065)、登録は発行者の仕事で、付与の一行を置くのは
  運用者の自動化の仕事である。[docs/surface.md](../surface.md) の DOC に
  載る理由が無く、module の `image_repository` がフォークを想定している
  のと同じ側にある。
- **「マネージド版」を README や positioning で約束すること。** faq の
  「無い」は今日も真である。

## 4. 今日の代金 — 運用者が払うもの

- **identity は Google のものである。** Cloud Run IAM の前提は、組織の
  利用者が Google の identity を持つことで、運用者の project に置くなら
  Domain Restricted Sharing にその組織のドメインを加える。
  [0086](0086-a-second-way-to-say-who-is-calling.md) の OIDC は「Google
  Cloud の外」のために書かれており、**Cloud Run 上で公開 invoke にして
  自分で検証する姿勢は綴られていない** — deploy ガイドと module は
  `allUsers` を断り、[0116](0116-the-connector-price-changed-not-its-condition.md)
  がそれを宿題と名指している。CLI と stdio 橋が作るのも Google の
  トークンだけである(0086 §6)。調査 [#703](https://github.com/na0fu3y/ochakai/issues/703)
  の最有力セグメント — Google Cloud 上の国内組織 — では、この代金は零である。
- **互換性の窓。** 最新リリースのみ、改名は一リリース
  ([0088](0088-a-retired-name-answers-for-one-release.md))、CLI はサーバと
  一緒に上げる([compatibility](../compatibility.md))。N 個を順に上げる
  運用は、一歩で二つ以上のリリースを跨がないか、組織側のクライアントが
  追従することを要る。これは方針であって機構ではなく、動かすなら 1.0 か
  0088 の改訂([#597](https://github.com/na0fu3y/ochakai/issues/597))で、
  **この記録は動かさない**。
- **共有インスタンスの経済。** f1-micro を N 個か、一インスタンスに N
  database か。後者は安いが、PITR はインスタンス単位で、接続は
  インスタンス数の 4 倍になる([運用ガイド](../guides/operating.md#capacity))。
  運用者の選択であり、製品は知らない。
- **ディレクトリの形で、0109 §3 が管理者に寄せたもの。** `stats`・
  export・miss はバンドル全体のもので、ディレクトリの組織は自分のぶんを
  自分で取れない — 出口(C1)に運用者が要る。`PUT /api/v1/access` は
  文書を丸ごと置き換え、`If-Match` を持たないので、付与を自動で置く
  並行は互いを消す。レート制限は無く([0066](0066-four-postures-one-word.md) §7)、
  Vertex AI の請求は一つである。

## 5. 製品が動いてよいもの、その順序

§4 の第四項は、0109 §3 が**自分で予告した分割**である — 「後で『自分の
スコープぶんの stats』に割ることは付与を増やす変更であって、規則を壊す
変更ではない」。だからこれは条件ではなく宿題で、順序だけをここで決める。

1. **公開 invoke で自分を検証する姿勢。** 0116 の宿題と同じもので、
   [PR #721](https://github.com/na0fu3y/ochakai/pull/721) が公開 URL と
   第三者の発行者で実走させている。ディレクトリの形に見知らぬ組織を
   入れるには、これが無ければ始まらない — Cloud Run IAM の policy に
   一人ずつ足す形は、登録を運用者の手作業にする。deploy ガイドが禁じて
   いる理由ごと測り、別の番号で決める。
2. **0109 §3 の分割。** スコープ内の `prefix` で非管理者に返す `stats` と
   export、スコープで切る miss、`PUT /api/v1/access` の `If-Match`
   ([0030](0030-optimistic-locking.md) の形)、自分の prefix の下にだけ
   規則を置ける principal。ワイヤに触るので、それぞれ記録を持つ。
3. **レート制限。** 0066 §7 が断ったままで、見知らぬ相手を入れる日に
   払う。前の二つの後でよい — 測る相手がまだいない。

第一項と第三項は deploy ガイドと SECURITY.md の脅威モデルを動かし、
第二項は動かさない — **だから第二項は第一項を待たない**。自分のぶんの
`stats` が欲しい部門は今日の Cloud Run IAM の中に既におり、順序が言って
いるのは「見知らぬ組織を入れる日には第一項が先に要る」ことだけである。
**この記録はどれも実装しない** — 0115 §3 と同じく、機構は候補が現れた
ときの評価が選ぶ。

## 6. 採らなかった案

- **何も書かないこと。** 0115 §5 の最後の項と同じ理由で、黙っていても
  §2 は守られるが、守られている理由を読み手が知っているかは別である。
- **ROADMAP の一行だけ。** あの節の各行には記録が要る。
- **運用ガイドに「複数組織の運用」節を書くこと。** 存在しないサービスの
  runbook を、`DOC-LINES` を払って想像で書くことになる —
  [docs/surface.md](../surface.md) の問い 1 が断る形そのものである。
  手順が要る日には、それを書く運用者がいる。
- **ディレクトリの形を「マルチテナント」と呼ぶこと。** その語が指す
  ものは §3 の第一項であり、ochakai が持つのは 0109 の付与である。
  [0115](0115-the-second-footing-waits-for-search.md) §5 が「マルチ
  クラウド対応」という語を断ったのと同じ理由で、機構の名前で約束を
  増やさない。

## 7. 面

**一つも動かない。** REST も MCP も CLI も Web UI も、環境変数も語彙も
同じである。増えるのは、この形を閉じる PR に対して引ける一本の線と、
§5 の順序だけである。
