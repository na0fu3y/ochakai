# ochakai 設計ドキュメント 0078: このデプロイがどう埋め込むかを、一つの変数で言う

Status: Accepted(2026-08-02)。**埋め込みの設定面の現行ドキュメント。**
[0073](0073-search-and-when-embeddings-apply.md) を改訂する — §1.4 の off
スイッチ、§2 の次元、§4 のモデル選択が**どう書かれるか**を変える。
[0073](0073-search-and-when-embeddings-apply.md) が決めたことは何一つ
変えない: Google Cloud の上で埋め込みが既定であること、使えるかを決める
のが IAM であること、ベクトルが導出物であることは、そのままである。
姿勢を一語にした [0066](0066-four-postures-one-word.md) と同じ形の
畳み込みで、対象が違うだけである
Date: 2026-08-02

## 1. 一つの機能に、五つの間違えられる場所があった

```
OCHAKAI_EMBEDDINGS       on | off
OCHAKAI_VERTEX_PROJECT   プロジェクト。無ければメタデータサーバから
OCHAKAI_VERTEX_LOCATION  既定 us-central1
OCHAKAI_VERTEX_MODEL     既定 gemini-embedding-001
OCHAKAI_EMBEDDING_DIM    既定 768
```

五つのうち三つ(project・location・model)は、**Vertex AI が既に一つの
文字列で言っていること**を分解して持っていた。呼び出し先の URL に現れる
綴りがそれである:

```
projects/<project>/locations/<location>/publishers/google/models/<model>
```

だから `OCHAKAI_EMBEDDINGS` 一語で言う — 未設定 / `on` / `off` / その
resource name:

```
未設定・on   メタデータサーバが答えたプロジェクトで、製品既定のモデルと
             リージョンで埋め込む(0073 §1.1)
off          埋め込まない。Vertex AI を一度も呼ばない(0073 §1.4)
resource     そのプロジェクト・リージョン・モデルで埋め込む
```

**畳めたのは、五つが一つの問いの答えだったからである** — 「このデプロイ
はどう埋め込むか」。0066 が四つの姿勢を一語にしたのと同じ形で、そこでも
減ったのは変数の本数だけではなかった。ここで書き下せなくなるのは、
`OCHAKAI_VERTEX_MODEL` だけを変えてプロジェクトを既定に残す、といった
**部分的な設定**である。モデルはリージョンに、リージョンはプロジェクトに
依存する(`gemini-embedding-2` は `global`/`us`/`eu` にしか居ない)ので、
三つを独立に置けることは自由ではなく、**合わない三つ組を書ける余地**で
あった。

C4(No FDE)が数えているのはまさにこれである。デプロイする人が読む変数
は 15 から 11 になり([docs/surface.md](../surface.md) の ENV)、埋め込み
について読むのは 5 行ではなく 1 行になる。

## 2. 三つのどれでもない綴りは、起動エラーである

`OCHAKAI_EMBEDDINGS=true` も `=my-project` も `=gemini-embedding-2` も
**起動を拒否し、三つの形を名指す**。既定に落とさないのは 0066 §4 と
同じ理由で、しかもここでは外し方が二方向ある:

- off のつもりで `false` と書いたデプロイは、頼んでいない課金を書き込み
  のたびに払う(0073 §1.4)。
- モデルを名指したつもりで綴りを外したデプロイは、**既定のモデルで
  埋め込み続ける**。気づくのはログではなく検索結果のほうであり、しかも
  検索は動いているように見える — 順位が悪くなるだけである。

**推測して外す方向がまずい種類の設定**という 0073 の判断が、値の集合が
広がっても変わらないということである。resource name は形が固いので、
`projects/…/publishers/google/models/…` の八片に分解できないものは
すべてこの拒否に落ちる。

## 3. 次元は消える — 幅はモデルのものであって、デプロイのものではない

`OCHAKAI_EMBEDDING_DIM` は残さない。0073 §2 が既に「ベクトルは導出物で
あり、次元の変更は製品が行う」と決めており、**運用者が回すつまみとして
残っていたのは、その決定の前の名残**だった。幅はモデルごとの定数として
コードに移る(現在は `gemini-embedding-001` も `gemini-embedding-2` も
768 で、Gemini の埋め込みは Matryoshka 表現学習なので短い出力は長い出力
の接頭辞であり、一つの幅が両方に効く)。

**768 は変えられない値である。** 保存済みのベクトルはすべてこの幅で
書かれており、変えれば全部が別空間の遺物になる。だからこの数は設定の
既定値ではなく、`TestModelWidths` が読み戻す**決定**である。

### 3.1 知らないモデルは、起動エラーにする

ochakai が幅を知らないモデルを名指されたとき、既定の 768 を当てにいく
道は採らない。**知らないモデルの幅は、推測である。** 外した場合に起きる
ことは §2 の二番目と同じ形をしていて、もっと静かである — 書き込みごとに
幅違いで拒否され、検索は字句だけになり、ログの外からは「埋め込みが効いて
いない」としか見えない。エラーは知っているモデルを名指すので、直し方は
メッセージの中にある。

これは [0073](0073-search-and-when-embeddings-apply.md) §4 と、型が閉じた
集合ではないという [0071](0071-the-recommended-type-vocabulary.md) の姿勢
に照らして選んだ。**型とモデルは、閉じているかどうかの問いが別である**:
型は利用者が書いて ochakai が解釈せずに往復させる値であり、知らない綴りを
拒む理由が無い。モデルは ochakai 自身が呼び出し、その答えの幅で**列を
作る**値である。知らないものを受け取るというのは、知らない幅で列を作ると
いうことである。

代償は正直に言える: Google が新しい埋め込みモデルを出した日に、ochakai の
リリースを待たずにそれへ移ることはできない。待つのは表の一行であり、
その間もデプロイは既定のモデルで動き続ける。**待てるものと、取り返せない
ものを比べている** — 幅の合わないベクトル空間は、埋め直しの請求書でしか
取り返せない。

## 4. 名指すことは、要求することである

resource name を書いたデプロイは、`Discovered` が false になる。0073 §1.3
の区別はそのまま生き、境界の綴りだけが変わる:

| 埋め込みの出所 | Vertex AI / pgvector が使えないとき |
|---|---|
| 発見(未設定・`on`) | 警告を一行出し、**字句検索だけで動く** |
| resource name(名指し) | **起動しない** |

`OCHAKAI_VERTEX_PROJECT` が担っていた「名指し」の役割は消えていない —
**移っただけ**である。そして意味は少し広くなった: プロジェクトだけを
名指すことはできず、モデルを選ぶこともまた「意味的検索を頼んだ」ことに
なる。それでよい。既定でないモデルを選ぶデプロイは、そのモデルで検索が
効くことを期待しており、黙って既定に落ちることを望んでいない。

Terraform の `vertex_model` / `vertex_location` / `embedding_dim` は
`embedding_model` 一つになる。0066 が `read_only` を残して
`OCHAKAI_MODE=read-only` を設定させたのと同じ扱いで、**モジュールの変数は
新しい綴りを書ければ名前を変える必要が無い** — ただし三つは一つの値の
断片だったので、ここでは一つに畳んでいる。

## 5. アップグレードで黙って変わる

退役した四つは**黙って無視される**。0066 のときと同じ形の危険であり、
現れ方はこちらのほうが静かである:

- `OCHAKAI_EMBEDDING_DIM` を既定以外にしていたデプロイ: 次の起動で
  ベクトルテーブルが 768 で作り直され、**空で戻る**(0073 §2)。
- `OCHAKAI_VERTEX_MODEL` を変えていたデプロイ: 幅が同じなので古い行は
  残るが、検索はモデルで絞るため**新しいモデルのクエリからは見えない**。
  `gemini-embedding-2` を使っていたなら、画像と PDF の検索も消える。

どちらも**知識は失われない**(ベクトルは導出物である)。失われるのは
ベクトル空間と、それを詰め直すための支払いであり、失われたことは
`ochakai reembed` を打つまで検索順位にしか現れない。だから
[CHANGELOG](../../CHANGELOG.md) は「アップグレードの**前**に
`OCHAKAI_EMBEDDINGS` を書け」と言い、コマンドを一行で示す。

## 6. やらないこと

- **旧変数の互換読み取り。** 黙って読み替えれば、五つの変数が一つ増えた
  状態で生き続ける。0066 も同じ選択をしている。
- **モデルごとの幅を設定可能にすること。** それは §3 を元に戻すことで
  ある。
- **未知のモデルを既定の幅で受け入れること**(§3.1)。
- **リージョンとモデルの組み合わせの検証。** 居ないリージョンを指せば
  Vertex AI がそう答え、名指したデプロイは起動しない — 製品が
  Google のリージョン表を持ち歩くより、答えを訊くほうが正しい。
- **次元変更後の自動 reembed。** 0073 §6 のまま、支払いは頼まれてから
  行う。
