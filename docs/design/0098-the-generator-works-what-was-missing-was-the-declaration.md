# ochakai 設計ドキュメント 0098: ジェネレータは動く。欠けていたのは宣言だった

Status: Accepted(2026-08-10)。[0064](0064-rest-stops-at-api-v1.md) §11 を
改訂する — 「どんなジェネレータもこの一つの住所については動く
クライアントを生成しない」は**事実ではなかった**。0064 の他の決定は一つも
動かない。凍結が守るものの範囲は
[0082](0082-what-the-freeze-holds-still.md) のままである(§2)。
Date: 2026-08-10

## 0. この記録が決めたこと

1. **`/api/v1/bundle/{path}` の `path` を、path item に一度だけ宣言する。**
   `get` だけが宣言し `put` と `delete` は宣言していなかった(§1)。
2. **これは凍結を破っていない。** 住所も、呼び出し側が送るものも、一つも
   変わらない — 契約が**自分と食い違っていたのを直した**だけである(§2)。
3. **0064 §11 の「生成できない」は取り下げる。** 実際に生成し、
   コンパイルし、走らせて確かめた(§3)。

## 1. 三つのうち一つしか宣言していなかった

```
/api/v1/bundle/{path}:
  get:    parameters: [- name: path, in: path, ...]   ← 宣言していた
  put:    parameters: [...]                            ← 無い
  delete: parameters: [...]                            ← 無い
```

OpenAPI では、path template に現れる名前は**その住所を持つすべての
操作**が宣言していなければならない。ジェネレータはここで止まる:

```
error creating operation definitions:
path '/api/v1/bundle/{path}' has 1 positional parameters, but spec has 0 declared
```

**契約が三つの操作について三つの違うことを言っていた。** 読む人が気付く
しかない種類の欠落であり(0064 §11 が「宣言の欠落そのものは、読む人が
気付くしかない」と書いた当のもの)、二年ではなく二か月で見つかったのは、
issue [#538](https://github.com/na0fu3y/ochakai/issues/538) が
「生成器が食える大きさへ」と書いて**実際に食わせてみた**からである。

直し方は path item 直下への移動である。OpenAPI は path item の
`parameters` をその住所のすべての操作に配るので、**一箇所に書けば三つが
揃う** — 三箇所に同じものを書くより、食い違いが起こらない形である。

## 2. 凍結は破っていない

[0082](0082-what-the-freeze-holds-still.md) §2 が凍結の対象に
「リクエストの形 — クエリパラメータ、リクエストヘッダ、リクエストボディの
スキーマ」を挙げている。ここで足したのは**パスパラメータ**であり、それは
住所そのものの一部で、`PUT /api/v1/bundle/metrics/revenue.md` を呼ぶ
クライアントは**最初からそれを送っていた**。

凍結の指紋(`api/openapi.frozen.txt`)は 2 行増える:

```
+ DELETE /api/v1/bundle/{path} path path required=true type=string
+ PUT    /api/v1/bundle/{path} path path required=true type=string
```

**消えた行も、変わった行も無い。** 呼び出し側が送るものも、サーバが返す
ものも、一つも変わらない。増えたのは、契約が既にある住所について
**言っていなかったことを言うようになった**分である。ラチェットの文面は
「セキュリティ上の欠陥だけが行を動かす」と言うが、それは**動いた**行の
規則であって、契約が自分の住所を記述し損ねていた欠落を埋めることまで
止める理由にはならない。止めるなら、契約は嘘のまま凍る。

## 3. 測って確かめた

主張を検証なしに置き換えないために、実際に走らせた
([0035](0035-verifiability.md))。

```
oapi-codegen v2.8.0 → types + client       生成できた(468 KB)
go build                                    通った
GET  /api/v1/bundle/metrics/revenue.md      200(3,195 バイト)
PUT  /api/v1/bundle/<slug>/metrics/probe.md 201
DELETE 同上                                  204
GET  /api/v1/bundle/(空パス)                501 — サーバの答えであって
                                             クライアントの欠陥ではない
```

**スラッシュを含む id も通る。** ジェネレータは `metrics/revenue.md` を
`metrics%2Frevenue.md` と符号化し、Go の `ServeMux` はそれを復号して
`{path...}` に渡す。0064 §11 が「動くクライアントを生成しない」と書いた
のはこの符号化を懸念してのことだったが、**懸念のほうが確かめられて
いなかった**。

確かめたのは **oapi-codegen(Go)一つ**である。他の言語のジェネレータが
同じように振る舞う保証はここには無い — 言えるのは「少なくとも一つは
動く」であって、「どれでも動く」ではない。0064 の「どんな…も…ない」を
取り下げるにはそれで足りる。

## 4. やらないこと

- **`{path}` を OpenAPI で正しく表現し直すこと。** ルートが空文字である
  ことも、`/` が区切りとして通ることも、OpenAPI の path template では
  表せない。0064 §11 のこの部分は**そのまま正しい** — 取り下げたのは
  「だからジェネレータは使えない」という帰結のほうである。
- **ジェネレータを CI に足すこと。** 生成が通ることを検査したい気持ちは
  分かるが、ネットワーク越しの第三者ツールを緑の条件にすると、
  こちらが何も変えていない日に赤くなる。**測るのは決めるときで、
  毎回ではない**(0035 が計測に求めているのは再現性であって常時性では
  ない)。
