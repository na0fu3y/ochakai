# ochakai 設計ドキュメント 0107: 凍結が握るのは OKF コアである

Status: Accepted(2026-08-16)。[0064](0064-rest-stops-at-api-v1.md) の
凍結の**範囲**を改訂する — 凍るのは bundle の往復と search の 4 操作に
なり、残りの `/api/v1` は 0.x の不安定な面に戻る。0064 の他の決定
(未知キーの 400、`/api/v2` を作らないこと、§11 の破ってよい理由)と、
[0082](0082-what-the-freeze-holds-still.md)・
[0100](0100-md-is-how-a-concept-is-spelled.md)・
[0101](0101-a-level-can-be-walked.md)・
[0102](0102-one-history-in-one-spelling.md) の規則は、適用先がコアに
なったまま全て残る。**これは公開した約束の撤回であり、この corpus で
初めての種類の記録である**(§1)。
Date: 2026-08-16

## 0. この記録が決めたこと

1. **凍結の対象は OKF コアである**: `GET` / `PUT` / `DELETE
   /api/v1/bundle/{path}` と `GET /api/v1/search`。指紋
   (`api/openapi.frozen.txt`)はコアの操作と、そこから到達できる
   コンポーネントだけを読む。
2. **残りの `/api/v1` は 0.x の不安定な面に戻る。** MCP・CLI・保存形と
   同じ体制 — 破壊は BREAKING として changelog に載り、設計記録を持ち、
   minor で出る。それぞれの操作は**動きを止めたとき、それ自身の決定と
   して**凍る(compatibility.md の 1.0 節が他の面に既に適用していた
   規則)。
3. **コアは二度と縮まない**(§4)。動かせる理由は今までの三つ —
   セキュリティ上の欠陥、OKF に適合しない出力、OKF が定義するものの
   二つ目の綴りの畳み込み — のままで、四つ目は増えない。

## 1. これは撤回である

0082 は「凍結は最初からそれを止めていなかった」と言えた。0101 も
言えた。**この記録は言えない。** 2026-08-02 から今日まで
compatibility.md は「REST is frozen at `/api/v1`」と書き、「SemVer の
含意ではなく*これ*に対して判断せよ」と言っていた。その*これ*を狭める。
解釈の訂正という語り口に逃げず、撤回と呼ぶのが、あの一文を書いた
文書に対する誠実さである。

代金の計算は [0082](0082-what-the-freeze-holds-still.md) §5 自身の
ものである — 「REST の外部利用者は実質ゼロで、**規則の欠陥を直す代金が
今より安いことは二度とない**」。あの論理は応答追加の規則に当てられた
が、範囲そのものの欠陥にも同じに当たる。この代金が払えるのは、凍結が
まだ若く、コア外に依存した外部利用者が確認されていない今だけであり、
その前提が崩れていたならこの記録は書かれるべきではなかった。

## 2. 二週間で四度直った境界は、間違った場所に引かれていた

凍結は 8/2 である。以後、0082(応答専用の追加は外)、0101 §5(任意
クエリパラメータの追加も外)が**解釈**を直し、0100 と 0102 が
**破ってよい理由**を二つ足した。約束が 14 日で免責を三つ持ったなら、
境界の場所を疑うのが素直で、しかも免責の向きは全部同じである —
**OKF**。0100 も 0102 も「SPEC がそう定義しているから」動かした。

そして compatibility.md は最後の節で既にこう書いていた: 「Your
knowledge outlives any of it. `ochakai export` writes an OKF bundle —
**which is the guarantee the project actually makes**」。本当にしたい
約束が何かは文章になっていて、凍結の範囲だけがそれとずれていた。
8/2 の凍結が凍らせたのは設計されたコアではなく、**その日たまたま
実装に在った表面**である — 11 操作の中で、bundle の往復と `reembed`
が同じ永遠性で並んでいた。0064 は `/api/v2` を永遠に作らないと決めて
おり、その永遠性は最も確かな操作にだけ与えるべきものだった。

## 3. コアの判定基準 — 列挙ではなく

**凍るのは、ナレッジがそこに在ることに直接触れる操作である**: OKF
バンドルの住所空間の読み・書き・削除(往復・archive export・派生する
`index.md` / `log.md`・ファイルの半分は、すべてこの三操作の中にある —
[0075](0075-the-bundle-is-the-address-space.md))と、それを見つける
唯一の読みの入口 search(順位と一覧 —
[0068](0068-how-a-face-is-added-and-removed.md) §2)。C1(資産は利用者の
もの)と C3(OKF)が往復を、C6(埋め込める REST)と C8 が読みの入口を
要求する。

コアの外に残るものは、それぞれ外である理由が言える:

- **`review` / `usage` / `stats` はループの計装である**(C7)。製品の
  中心だが、形がまだ動いている — 0090・0095・0104 がこの月に動かした。
  計装は磨かれてから凍ればよい。
- **`move` は運用の便宜である。** bundle の意味論では delete + create
  であり、コアだけで同じ結果に到達できる。
- **`reembed` は運用タスクである。** モデル入れ替え後に一度走るもの。
- **`context` は合成面である。** プリミティブの合成であり、行き先は
  [0108](0108-the-context-pack-retires.md) が決める。

次に「この操作はコアか」が問われたら、答えはこの基準からの分類で
あって、コアの再交渉ではない。

## 4. 新しい約束は、前より硬い

縮めた上で前と同じ硬さなら、信用を払って何も買っていない。だから:

- **コアは広がる向きにしか動かない。** 不安定な操作が動きを止めたら、
  `frozenCorePaths` にそれを足す記録を書く — 指紋の diff は増える形で
  しか動かない。
- **縮める記録はもう書けない。** 次に「コアから外したい」が来たら、
  それは本記録を Supersede する一冊ではなく、製品を別物にする決定で
  ある([docs/surface.md](../surface.md) が「九つ目の条件を足す」に
  ついて言うのと同じ桁)。撤回が一度きりであることは、この記録の
  内容の一部である。
- **検査は分割された指紋が持つ。** コア外の変更は golden に触れない
  代わりに、BREAKING + 設計記録の体制に従う(compatibility.md)。
  コアの側は今までどおり `frozenwire_test.go` が落とす。

## 5. 面への出方(0067)

ワイヤは 1 バイトも動かない。動くのは約束の文書
(docs/compatibility.md、CHANGELOG の前書き)と指紋の範囲だけである。
MCP・CLI・Web UI は元から不安定な面で、変わらない。

## 6. やらないこと

- **非コアの操作をこの記録で動かすこと。** それぞれの変更は
  それぞれの記録である(context は 0108)。
- **`/api/v2`。** 0064 のまま — 逃げ先を作らないことが、コアを選ぶ
  真剣さの担保である。
- **REST の住所への deprecation window。**
  [0088](0088-a-retired-name-answers-for-one-release.md) の窓は名前の
  改名のためのもので、非コアの削除は 0.x の BREAKING として届く。
- **コアの再縮小**(§4)。
