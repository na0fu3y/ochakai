# 同時実行と削除

同じ concept を人とエージェントが同時に直すとき、何が守られ、何が
後勝ちになるか。そして消すとき、何が残り、何が本当に消えるか。

## 前提条件(楽観ロック)

書き込みは全置換で、編集は必ず「読んで、直して、書き戻す」になる。二人が
重ねると、後から書いた側が前の変更を黙って消す。それを防ぐ手段を
**opt-in** で持つ。既定は後勝ちである(単発の編集やスクリプトに毎回二往復を
強いない)。

- **版(ETag)は保存したバイト列の SHA-256** で、引用符付きで返る
  (GET・PUT の応答、本文の `content_hash` も同じ値)。裁定とファイルの
  追加・削除は版を動かさない。整形だけの編集は動かす
  ([okf.md](okf.md))。
- **`If-Match: <版>`** を付けた PUT と DELETE は、読んだときの版がまだ
  立っている間だけ書く。違えば **412** で何も書かない。判定は条件付きの
  UPDATE の中で行い、確かめてから書くまでの窓は無い。
  - `If-Match: *` は 400(意味の無い前提条件を黙って受けない)。
  - `?purge=true` は `If-Match` を取らない(既に消えたものの二段目なので)。
  - ファイルは前提条件を取らない。
- **`If-None-Match: *`** を付けた PUT は、住所が空いているときだけ作る
  (既にあれば 412、`already_exists`)。版を渡す `If-None-Match` は 400。
- **GET の `If-None-Match`** が版と一致すれば 304。
- **MCP には版の通り道が無い**ので、MCP の書き込みは後勝ちである。代わりに
  サーバーが内部でこの機構を使う — 人が裁定した concept を拒むかの確認の
  ときに読んだ版を、そのまま前提条件にして書く([faces.md](faces.md))。
- Web UI の編集は、読んだ版を前提条件にして書く。
- アクセスポリシーも同じ意味の `If-Match` を取る([identity.md](identity.md))。

## 削除は二段階である

**一段目 `DELETE` はソフト削除**で、可逆である。行は残り、履歴も残り、
住所は墓標が握ったままになる。

- 同じ住所に作れば(PUT)、墓標は復活する。**人が裁定した concept の墓標は
  MCP からは復活できない**(draft の墓標はできる)。
- `note` を添えた削除は**却下**で、理由がリビジョンに載り `log.md` に出る
  ([loop.md](loop.md))。
- 削除された concept は検索にも一覧にも出ない。
- ファイルの削除は一回で終わる(墓標を持たない)。

**二段目 `DELETE ?purge=true` は不可逆な破棄**で、ソフト削除済みの concept
にだけ効く(生きている concept には 409 `not_deleted`)。

- 同じトランザクションで、その id を鍵に持つすべて — 行、リビジョン、
  パス配下のファイルとその台帳、利用集計、生イベント、埋め込み、検証の
  台帳 — を消し、**住所を解放する**。
- **purge した事実は残る**: `knowledge_purge` に id・型・題・消えた
  リビジョン数・実行者(via と producer 込み)・時刻を一行。内容は残さない
  (消せと言われたのは内容である)。ログにも出る。
- CLI は `ochakai purge`。**MCP にも Web UI にも出さない** — 履歴の破壊は
  人がコマンドで決めることである。

## バイト列の回収

ファイルのバイト列は SHA-256 で共有されるので、一つの削除では消せない。
purge とファイル削除の後に、**どの行からも参照されていないバイト列を消す
掃除**を走らせる。

- 問いは「どの object 行も attachment 行も参照していない blob」で、参照
  カウントの写しは持たない。
- 書き手はバイト列を上げてから行をコミットするまで共有ロックを持ち、掃除は
  排他ロックで走る — これから参照されるバイト列を消さないため。
- 消す順はバイト列が先、台帳の行が後。途中で落ちても、次の掃除が続きを
  やる。掃除の失敗は警告で、削除そのものは成り立っている。
- GCS でも PostgreSQL でも同じ約束である([okf.md](okf.md))。

これで「求められれば消える」(C1)がバイト列まで届く。

## やらないこと

- 前提条件の必須化。
- MCP に版を持ち回らせること(埋めるべき値を知らないエージェントに
  欄を渡すことになる)。
- 一回で消える破棄、purge の Web UI・MCP への露出、purge した内容の保存。
- 参照カウント。
