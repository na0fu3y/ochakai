# 住所・パス・move

concept とファイルが**どこに住み、どう名指され、どう動くか**。

## パスが住所であり、型は属性である

- concept の id は**バンドル・ルートからのフルパスから `.md` を除いたもの**で
  ある(SPEC §2)。第一セグメントに意味は無く、ルート直下の一セグメントの
  id も正規である。同じパスに二つの concept は無い。
- **型は「何であるか」、パスは「どこにあるか」で、両者は直交する。**
  型先頭(`metrics/sales/…`)もドメイン先頭(`sales/orders.md` に
  `type: Metric`)も一級で、サーバーはどちらも強制せず、パスから型を
  推測しない。推奨する原則は一つ — **一緒に読ませたいものを同じディレクトリに
  置く。**
- concept とディレクトリは同じ名前を持てる(`metrics/revenue.md` と
  `metrics/revenue/`)。
- **末尾セグメント `index` と `log` は予約**である(導出面の住所)。

### id の文字種

制約は**パスとして安全であること**だけである: セグメントは非空の正しい
UTF-8・128 バイト以下・制御文字なし・先頭 `.` 禁止、id 全体は 512 バイト
以下。`用語/売上` も BigQuery の `_intraday` も置ける。鍵として比較する
文字列は入口で NFC に正規化する([okf.md](okf.md))。

型の綴りは語彙であってパスではないので、この緩和は及ばない(ただし `/` は
型に使える — SPEC が未知の型への寛容を求めるので、`acme/Table` は合法で
ある)。

## 一つのアドレス空間

**`GET|PUT|DELETE /api/v1/bundle/{path}`** が唯一の住所である。

- **`.md` は住所の一部**である。concept は `<id>.md`、ファイルは自分の拡張子の
  ままのパス、ディレクトリの一覧は `<dir>/index.md`、その下の変更は
  `<dir>/log.md` で読む。裸の id を取るのは
  `/api/v1/review/{id}` と `/api/v1/usage/{id}` で、これは識別子であって
  住所ではない。二つの対象を持つ `move` だけが本文で名指す。
- **素の GET には、静的ファイルサーバーと同じものを返す。** concept の
  住所は文書そのもの(export と同じ形)を、ディレクトリの住所(`/` で終わる
  パスと根の `/api/v1/bundle/`)はその `index.md` を返す。だから
  `/api/v1/bundle/` がバンドルの根で、本文の絶対リンク `/tables/orders.md` は
  そこから解決される。構造化した JSON(concept の View、ディレクトリの一覧)は
  `Accept: application/json` で名指す。書き込みの応答は、何をしたかを本文で
  運ぶので JSON が既定である(決定 [0153](../decisions/0153-serve-the-bundle-as-okf.md))。
- **表現は `Accept` が決める。** 一つの住所の複数の表現であって、第二の面
  ではない。`Accept: application/gzip` はパスを部分木として読み、**その
  tar.gz** を返す。ルートなら全体 — これが export である(`files=false` で
  ファイルを除ける)。範囲の付いた呼び出し元が取れる
  アーカイブと、アーカイブが自分の範囲を名乗る形は [identity.md](identity.md)
  にある。
- **`?history` はそのオブジェクトの履歴**で、`Accept` にかかわらず JSON で
  答える(concept はリビジョン、既定 50・上限 200、ファイルは変更行、
  1000/1000)。markdown の履歴は `log.md` がディレクトリ単位で持つ。
- **書き込みで concept かファイルかを決めるのは住所と frontmatter の `type`**
  であって `Content-Type` ではない。
- **削除は `DELETE`(ソフト削除)、`?purge=true` で不可逆な破棄**である。
  `DELETE` に `note` を添えると、それは却下という裁定である
  ([faces.md](faces.md))。

### ディレクトリを読む

ディレクトリの `index.md`(SPEC §8)を JSON で読むと、その一階層の
サブディレクトリ(件数と、書かれていれば説明付き)・concept・ファイルが返る。
サブディレクトリの説明は、その親の `index.md` を PUT して書く([okf.md](okf.md))。**一ページ 1000 件で、
`cursor` で先へ歩ける。** markdown の `index.md` は歩かず、打ち切りを注記の
行として書く。ツリーを歩くことは需要の信号ではないので、利用として記録
しない。CLI は `ochakai browse`、Web UI はブラウズ画面である。

## move

**`POST /api/v1/move`** は二つの形を取る(鍵の組が形を言い、混ぜれば 400)。

### 一件を動かす(`from` / `to`)

一つのトランザクションで、concept 本体の id、**履歴**(move 自身も
`change: move` として足す)、利用実績、埋め込みのキーを書き換える。
埋め込むテキストは id で始まるので、**move が成り立った後、動いた concept の
ベクトルを新しい id で作り直す**(ディレクトリの move なら、その下の全部)。
作り直しに失敗しても move は立ったままで、`ochakai reembed` が残りを埋める。

- **内向き参照を書き換える。** 生きている concept のうち、本文のリンクか、
  frontmatter のパスの欄(OKF SPEC §6.2 の `resource`・`sources[].resource`・
  `computation`・`executor.resource`・`attester.resource`)が、動く concept か
  その名前空間のファイルを指すものを書き換え、それぞれを `update` の
  リビジョンとして記録する。書き換えた値は絶対パスになる。frontmatter は
  その値のトークンだけを差し替え、字下げ・コメント・他のキーは書かれた
  まま残す(一行に収まらない値だけ、そのキーのブロックを描き直す)。
  動く concept 自身の相対リンクと相対パスも、元のディレクトリで解決して
  絶対パスにする。移動の副作用も監査証跡に残る。
- **`<id>/` 名前空間のファイルも一緒に動く。** 名前空間の下の **concept は
  動かない** — それは自分の住所と履歴を持つ別の concept である。
- **移動先が埋まっていれば 409**。ソフト削除済みでも断る(その行はまだ
  住所と履歴を持っている)。
- move は立っている検証を失効させる(内容の作者が付け替わる)ので、動いた
  concept は `edited` のキューに入る。

### ディレクトリを丸ごと動かす(`from_prefix` / `to_prefix`)

**prefix の下の全オブジェクトが、一つのトランザクションで動く** — 生きて
いる concept、論理削除された concept(住所を握っているので置いていけない)、
prefix の下のすべてのファイル。一件の move が運ぶもの(リビジョン・台帳・
利用実績・埋め込み・内向き参照の書き換え)を全件について運ぶ。**丸ごと動くか、
動かない。**

クライアントのループでは足りない — 一覧に出ないもの(名前空間の外の
ファイル、論理削除された concept)はクライアントからは見えず、動かせない。
`move a b` が「`a` が concept ならそれを、ディレクトリならその下を」と
推測しないのは、同じ名前の concept とディレクトリが両立するからである。

### 範囲を持つ呼び出し元

書き換えが触れるもの — 動かす concept、移動先、それを指す全 concept —
がすべて書ける範囲にあるとき動き、**はみ出すなら丸ごと断る**
([identity.md](identity.md))。

**move は MCP に出さない。** 整理はキュレーションで、人の面の操作である。

## 住所で絞る: `prefix`

`prefix` は検索と一覧のフィルタで、そのサブツリー(prefix 自身とその下
すべて)に絞る。

- **セグメント境界で照合する**(`metrics` は `metrics-legacy/churn` に
  当たらない)。素の前方一致は、隣にディレクトリを一つ作っただけで他人の
  スコープを混ぜる。
- **繰り返せる(OR)。** 「自分のスコープと全社スコープ」を一回で問うため
  である。別々の順位を後でマージしても順位の意味は無い。
- フィルタであってモードではない — クエリとも `sort` とも組み合わせられる。
- **認可ではない。** 誰でも任意の値を渡せ、渡さなければ全体が返る。閲覧の
  境界はディレクトリ単位の付与が持つ([identity.md](identity.md))。
- 索引は張らない(照合順序に依存する範囲述語は環境で答えが変わる)。

## やらないこと

- 複数バンドル、パスから型を推測すること、アーカイブの自動アンラップ。
- 部分一致・glob・正規表現の prefix、スコープのレジストリや封筒フィールド、
  スコープによる順位の重み付け。
- `ls` / `rm` という綴り。
- ファイルの MCP ツール。
